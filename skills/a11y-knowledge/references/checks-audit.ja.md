# `@a11y-skills/audit` の結果の読み方

[`@a11y-skills/audit`](../../../packages/a11y-audit/README.ja.md) の各チェックが、何を確定し、何を要確認として残すか。チェックごとの結果 JSON（`violations` / `incomplete` / `passes` / `details`）を、達成基準の判定にどう写すかをまとめる。詳しい条件は各達成基準のファイルの「確かめるとき」。

## 原則

- **実測が無い達成基準は要確認にとどめる。** 止まった画面の情報（ツリー・HTML）から、操作や計測が要る達成基準を適合にしない。
- **`incomplete` は候補であって違反ではない。** 候補が 1 件以上あれば要確認、0 件なら対象外か適合（チェックごとに下の表）。
- **実測が途中で止まった（`interrupted` / `aborted`）なら、適合を付けない。** 試していない要素があるため。見つかった違反は残す。
- **「問題が見つからなかった」だけで適合にしない。** 適合にしてよい条件は達成基準ごとに決まっている。

## 複数ページの材料

`page-snapshot` を各ページで走らせ、`details.snapshot`（body の aria snapshot）・`title`・`lang`・`frames` を集める。見比べ方は [cross-page](./cross-page.ja.md)。

## 限界として書き添えるもの

- iframe の中・shadow DOM の中は、チェックによって見ている範囲が違う。結果の `details` を読んで、見ていない範囲を書き添える。
- 実測は開き直したページで行う。利用者が開いたメニューやダイアログの中（状態）は、既定では対象外。
