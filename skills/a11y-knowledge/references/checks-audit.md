# How to read `@a11y-skills/audit` results

What each check in [`@a11y-skills/audit`](../../../packages/a11y-audit/README.md) settles and what it leaves as needs review. This page summarizes how to map each check's result JSON (`violations` / `incomplete` / `passes` / `details`) onto verdicts for success criteria. The detailed conditions are in "When checking" in each success criterion's file.

## Principles

- **A success criterion without measurement stays as needs review.** Do not mark a criterion that needs operation or measurement as conformant from the information of a static screen (tree, HTML).
- **`incomplete` means a candidate, not a violation.** One or more candidates means needs review; zero means not applicable or conformant (per check, see the table below).
- **If the measurement stopped partway (`interrupted` / `aborted`), do not mark conformant.** There are elements that were not tried. Keep the violations that were found.
- **Do not mark conformant just because "no problem was found".** The conditions for marking conformant are decided per success criterion.

## Input for multiple pages

Run `page-snapshot` on each page and collect `details.snapshot` (the aria snapshot of body), `title`, `lang`, and `frames`. How to compare is in [cross-page](./cross-page.md).

## Limitations to note alongside the result

- Inside iframes and inside shadow DOM, the range each check looks at differs. Read the result's `details` and note the range that was not looked at.
- Measurement is done on a freshly opened page. The inside of a menu or dialog the user opened (state) is out of scope by default.
