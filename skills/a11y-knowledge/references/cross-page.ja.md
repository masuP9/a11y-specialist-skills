# 複数ページを見比べる達成基準の共通ルール

3.2.3（一貫したナビゲーション）、3.2.4（一貫した識別性）、3.2.6（一貫したヘルプ）と、2.4.2 の「同じタイトルのページ」の見比べに共通する判定のきまり。各達成基準のファイルより先に読む。

## 根拠

- WCAG の適合はページ単位で決まる（[Conformance Requirements](https://www.w3.org/TR/WCAG22/#conformance-reqs)）。「一貫している」かは他のページと比べないと分からないが、不適合を付けるのは個々のページ。
- 3.2.3 / 3.2.4 / 3.2.6 の「ウェブページ一式（set of web pages）」は、共通の目的を持ち、同じ作者・グループ・組織が作った、関連するウェブページの集まり（WCAG の用語定義）。

原文確認日: 2026-11-02。以下の多数派・候補抽出は著者の検査・報告方針であり、WCAGの適合条件ではない。各基準の根拠は [3.2.3](./criteria/3.2.3.ja.md)、[3.2.4](./criteria/3.2.4.ja.md)、[3.2.6](./criteria/3.2.6.ja.md) を参照する。

## 判定のきまり

- **先にページ一式の範囲を決め、その中のテストしたページを比較する。** 同一ドメインだけで一式にしない。目的・作者・機能上のまとまりを記録し、未検査ページへ結果を広げない。[独自: 検査範囲の方針。公式の範囲は各基準の根拠を参照]
- **ページ間の結果の割当は、多数派に合わせ、違う方を不適合にする。同数なら要確認。** 従来の割当方針を維持するが、同数でも確認済みの不一致は消さず、どのページへ割り当てるかが未決と書く。多数派のページに付ける適合は比較上の結果であり、一式全体のWCAG適合を保証しない。[独自: ページへの報告先を決める方針]
- **多数派はページ数で数える。** 要素数で数えると、1 ページに同じ部品が複数あるときに逆転する。[独自]
- **3.2.3 / 3.2.6で一ページにしか存在しないと確認した仕組みは比較しない。** 一ページしか取得していないだけなら要確認。3.2.4は一式内の同一ページの反復も確認する。ページ数の多数決を同一ページ内の部品へ適用せず、識別の食い違いを部品とともに記録する。[根拠: 各基準のE01。材料不足と報告は独自方針]
- **ページ間比較は同じ表示条件で行う。** 幅・ズーム・向き・メニュー状態を記録する。3.2.6では規範の注記2に従う。3.2.4は表示条件をそろえる初期比較だけで終えず、レスポンシブ表示の同じ機能も識別できるか確認する。[独自: 比較手順。根拠: 3.2.6-E02 / 3.2.4-E03]
- **最初の順序比較にはアクセシビリティツリーを使う。** ツリーの順を生のDOM順と同一視しない。3.2.3の視覚的な順序と3.2.4の可視の識別は別に確認し、未検査ならその範囲を残す。3.2.6は直列順が同じなら視覚的位置だけの差をFailにしない。[独自: 初期検査の方針。根拠: 3.2.3-E01 / 3.2.4-E03 / 3.2.6-E02]
- **判断できなかった組は要確認。** 推測で不適合にしない。[独自]

## 役割の分け方（判断と機械的な比較を分ける）

精度が出た分け方は、次の 3 段。

1. **材料を作る（機械的）**: 各ページの aria snapshot（`page-snapshot` の `details.snapshot`）から、ナビの仕組み・部品・ヘルプの候補を拾う。
2. **組にする（判断）**: 「ページをまたいで同じもの」を組にする。順序や多数決は判断しない。
3. **比較・報告する**: 組ごとの相対順序・識別を比較する。機械的な文字列差を不適合と同一視せず、各基準の例外・著者方針を照合してから、ページ間では多数派の割当を行う。

判断の段で候補を黙って省かない。渡された候補は、組か「対象外」のどちらかにちょうど 1 回ずつ入れる。省くと多数派が逆転し、誤った不適合が出る。

## よくある誤判定

- **別名の項目**: 名前もリンク先も違う項目（「印刷」と「プリント」）が、同じ項目の言い換えか別の項目かは、文面だけでは決まらない。別の項目として外すと 3.2.3 の見逃しになる。解説書も項目の増減を許しているので、曖昧さそのもの。迷ったら要確認。
- **同数で要確認になる**: 同じ反復機能に識別の不一致があり、二ページで一件ずつならページへの割当は同数で要確認。ただし不一致の証拠は報告する。第三のページがあっても常に多数派が成立するとは限らない。
- **仕組みごと外すと評価が残らない**: 3.2.3 で仕組み全体を「このページだけのもの」「セクションの補助ナビ」として外すと、その仕組みは評価なしになる。外すべきでないものまで外していないかを確かめる。
- **スキップリンクの候補は粗い**: 「先頭近くのページ内リンク」で拾うと、目次のリンクまで入る。ページ内へのリンク（`#` で始まる href）は、各ページの自分自身への URL になるので、リンク先で同一視しない。
- **ボタン・名前のない入力欄**: 初期の候補抽出でcheckbox等を外しても、3.2.4の対象外と報告しない。反復する機能かを画面・DOM・操作結果で補い、材料がなければ要確認にする。

## 材料の取り方

- `@a11y-skills/audit` の `page-snapshot` を各ページで走らせる（ページごとに `--output-dir` を分ける）。
- ランドマーク（banner / navigation / contentinfo / search / main）と、その中の link / button / 入力欄を、snapshot の階層から拾う。
- 2.4.2 の見比べには `details.title` を使う。
- `page-snapshot`は各結果バケットを空にし、判定しない。空配列をPass/NAにしない。`details.viewport`は幅・高さであり、ズーム・向き・メニュー状態は別途記録する。取得できないframeは `snapshot: null` とエラーが残るため未確認とする。[実装: runPageSnapshot.ts](../../../packages/a11y-audit/src/playwright/runPageSnapshot.ts)
