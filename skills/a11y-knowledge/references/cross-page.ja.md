# 複数ページを見比べる達成基準の共通ルール

3.2.3（一貫したナビゲーション）、3.2.4（一貫した識別性）、3.2.6（一貫したヘルプ）と、2.4.2 の「同じタイトルのページ」の見比べに共通する判定のきまり。各達成基準のファイルより先に読む。

## 根拠

- WCAG の適合はページ単位で決まる（[Conformance Requirements](https://www.w3.org/TR/WCAG22/#conformance-reqs)）。「一貫している」かは他のページと比べないと分からないが、不適合を付けるのは個々のページ。
- 3.2.3 / 3.2.4 / 3.2.6 の「ウェブページ一式（set of web pages）」は、共通の目的を持ち、同じ作者・グループ・組織が作った、関連するウェブページの集まり（WCAG の用語定義）。

## 判定のきまり

- **比べる範囲は、テストしたページだけ。** テストしていないページは考えない。[独自]
- **ページの間で食い違ったら、多数派に合わせ、違う方を不適合にする。同数に分かれたら要確認。** 適合も書く（食い違いが無ければ適合）。[独自]
- **多数派はページ数で数える。** 要素数で数えると、1 ページに同じ部品が複数あるときに逆転する。[独自]
- **1 ページにしか無いものは評価しない。** 比べる相手が無い。[解説書]（繰り返されるものだけが対象）
- **違うビューポート（画面幅）どうしは比べない。** [独自]
- **見た目の順序は使わず、ソースの順序（アクセシビリティツリーの順）だけで判定する。** CSS でナビの順序を入れ替えるのはまれ。[独自]
- **判断できなかった組は要確認。** 推測で不適合にしない。[独自]

## 役割の分け方（判断と機械的な比較を分ける）

精度が出た分け方は、次の 3 段。

1. **材料を作る（機械的）**: 各ページの aria snapshot（`page-snapshot` の `details.snapshot`）から、ナビの仕組み・部品・ヘルプの候補を拾う。
2. **組にする（判断）**: 「ページをまたいで同じもの」を組にする。順序や多数決は判断しない。
3. **判定する（機械的）**: 組ごとに相対的な順序・名前の一貫性を比べ、多数派のきまりを当てはめる。

判断の段で候補を黙って省かない。渡された候補は、組か「対象外」のどちらかにちょうど 1 回ずつ入れる。省くと多数派が逆転し、誤った不適合が出る。

## よくある誤判定

- **別名の項目**: 名前もリンク先も違う項目（「印刷」と「プリント」）が、同じ項目の言い換えか別の項目かは、文面だけでは決まらない。別の項目として外すと 3.2.3 の見逃しになる。解説書も項目の増減を許しているので、曖昧さそのもの。迷ったら要確認。
- **同数で要確認になる**: 同じ行き先に違う名前が付いたものが、別々のページに 1 つずつだけあると、必ず同数（要確認）になる。3 ページ以上にあれば多数派が決まる。
- **仕組みごと外すと評価が残らない**: 3.2.3 で仕組み全体を「このページだけのもの」「セクションの補助ナビ」として外すと、その仕組みは評価なしになる。外すべきでないものまで外していないかを確かめる。
- **スキップリンクの候補は粗い**: 「先頭近くのページ内リンク」で拾うと、目次のリンクまで入る。ページ内へのリンク（`#` で始まる href）は、各ページの自分自身への URL になるので、リンク先で同一視しない。
- **ボタン・名前の無い入力欄は「判断できない」になりやすい**: 名前が無いチェックボックスは見た目でしか同じ部品か分からないので、3.2.4 の対象から外す。

## 材料の取り方

- `@a11y-skills/audit` の `page-snapshot` を各ページで走らせる（ページごとに `--output-dir` を分ける）。
- ランドマーク（banner / navigation / contentinfo / search / main）と、その中の link / button / 入力欄を、snapshot の階層から拾う。
- 2.4.2 の見比べには `details.title` を使う。
