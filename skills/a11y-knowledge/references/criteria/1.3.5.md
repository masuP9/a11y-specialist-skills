# 1.3.5 Identify Input Purpose

- Components in scope: input (textbox and so on), combobox
- Inputs needed: measurement (autocomplete-audit from `@a11y-skills/audit`), the field's name and label
- Automated checks: autocomplete-audit, axe `autocomplete-valid`

## Rationale

- [Understanding 1.3.5](https://www.w3.org/WAI/WCAG22/Understanding/identify-input-purpose.html) ([Japanese translation](https://waic.jp/translations/WCAG22/Understanding/identify-input-purpose.html))
  - The scope is input fields that collect "information about the user" whose purpose is in WCAG's list of [Input Purposes for User Interface Components](https://www.w3.org/TR/WCAG22/#input-purposes). Information about other people (a shipping recipient) and search terms are out of scope.
  - The form in which the purpose is "programmatically determinable" is, in practice, the HTML `autocomplete` attribute.
- [H98: autocomplete attribute](https://www.w3.org/WAI/WCAG22/Techniques/html/H98)

## Judgment lines

- The scope is only input fields that collect the user's own information (name, email, phone, address, and so on; those that correspond to `autocomplete` values). Search fields and fields for other people's information are out of scope. [Understanding]
- If the field's purpose can be inferred from name / id / label / placeholder and the `autocomplete` value is written in a way not in the specification, non-conformant. If there is a valid value, conformant. [Understanding]
- A field without `autocomplete` (or with `off`) is non-conformant if it can be confirmed to be a field for the user's own information. If it can be read as not the user's information (a recipient's name and so on), out of scope. [Understanding]
- An invalid value on a field whose purpose could not be inferred is non-conformant if the label and so on confirm it is a field for the user's own information, out of scope if it can be read as not the user's information, and needs review if neither can be read. [Our interpretation]
- When the attribute value cannot be confirmed, do not mark non-conformant by guesswork (needs review). [Our interpretation]

## When building

- Give fields for the user's own information an `autocomplete` from the list (`name`, `email`, `tel`, `postal-code`, `street-address`, and so on).
- For fields for other people's information such as a shipping recipient, add a section like `autocomplete="shipping name"`, or do not add one.
- Do not put `autocomplete="off"` on fields for the user's own information (if you only want to stop browser completion, consider another means).
- Write values as in the specification (do not write `phone` for `tel`).

## When checking

- **Settled**: if autocomplete-audit reports "an invalid value on a field whose purpose could be inferred", non-conformant. If there is a valid value, conformant.
- **Remains**: `missing` (no autocomplete) and an invalid value on a field whose purpose could not be inferred are decided by checking whether the field is for the user's own information.
- **Do not assert**: do not mark a field without measurement non-conformant by guesswork.
