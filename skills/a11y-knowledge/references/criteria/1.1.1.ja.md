# 1.1.1 非テキストコンテンツ

- 対象の部品: 画像、画像による操作部品、SVG、canvas など。以下は画像を中心とする判断根拠であり、音声・映像・CAPTCHA 等の全分岐を網羅しない
- 要る材料: 画像の中身、周囲の文脈、DOM、計算された名前・役割、表示とアクセシビリティツリーへの露出
- 自動チェック: axe の `image-alt` / `input-image-alt` / `role-img-alt`
- 原文確認日: 2026-11-01。WCAG は 2024-12-12 勧告、Understanding / Techniques は WCAG 2.2 公開ページ（随時更新）。以下は引用ではなく要約。

## 根拠

### 1.1.1-E01 — 代替の十分さはその場での目的で決まる

- **種別・出典:** [Understanding —「Intent」「Examples」](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html#intent)。
- **要約:** 同じ画像でも用途により必要な代替が変わる。操作に使う画像では目的を、複雑な情報では短い名前だけでは伝わらない内容も扱う。
- **適用条件・限界:** 名前の有無だけでは十分さを判断できない。画像と周囲の説明を確認し、何が伝わらなくなるかを特定する。写真・ロゴ・大きい画像という分類だけでは決めない。

### 1.1.1-E02 — 装飾は内容と実装の両方を確認する

- **種別・出典:** [規範 — WCAG 2.2「pure decoration」の注記](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#dfn-pure-decoration)、[Technique — H67「Description」「Tests」](https://www.w3.org/WAI/WCAG22/Techniques/html/H67#tests)（Sufficient）。
- **要約:** 文字を含む画像でも、その語を入れ替えて目的が変わらない装飾はありうる。H67 は、無視してよい画像に空の `alt` と、未指定または空の `title` を用いる。
- **適用条件・限界:** H67 は「その画像を無視してよい」ことが前提。`alt=""` 自体は装飾である証拠ではない。情報を持つ画像を隠して要件を回避しない。

### 1.1.1-E03 — alt の欠落と代替の欠落は同じではない

- **種別・出典:** [Failure — F65「Description」「Tests」](https://www.w3.org/WAI/WCAG22/Techniques/failures/F65#tests)。
- **要約:** `img` / `area` / `input type="image"` の代替は、`alt` だけでなく、アクセシビリティサポーテッドなARIA等の経路も確認する。ファイル名の自動読み上げに頼らない。
- **適用条件・限界:** `alt` が無いという観察だけでF65を成立させない。別の名前の経路と、無視してよい画像の扱いを確認する。親に名前があるだけで子画像も適合と決めない。

### 1.1.1-E04 — 名前の存在と内容の検査は別

- **種別・出典:** ACT（Approved）[23a2a8「Applicability」「Expectation」「Accessibility Requirements Mapping」](https://www.w3.org/WAI/standards-guidelines/act/rules/23a2a8/#applicability)（版: 2023-08-31）、[qt1vmo の同節](https://www.w3.org/WAI/standards-guidelines/act/rules/qt1vmo/#applicability)（版: 2023-08-30）。
- **要約:** 23a2a8 は名前または装飾としての扱いを、qt1vmo は名前が同等の目的を果たすかを確認する。どちらも pass だけで達成基準全体の適合にはならない。
- **適用条件・限界:** 前者はプログラムで隠された要素を除く。後者は可視で名前のある `img` / `canvas` / `svg` が対象で、著者が名前を付けた祖先がある場合などを除く。ルールの対象外は、WCAGの対象外という意味ではない。axe と同一の実装だとは扱わない。

### 1.1.1-E05 — テストや感覚的体験では識別のための説明を使える

- **種別・出典:** [規範 — WCAG 2.2「Non-text Content」のTest / Sensory](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#non-text-content)。
- **要約:** テキストで同等にすると成立しなくなるテスト・演習や、主として特定の感覚的体験を提供する内容では、少なくとも内容を識別できる説明を用意する。
- **適用条件・限界:** 代替を空にしてよい例外ではない。通常の情報図や操作画像まで、短い識別だけで十分とはしない。

## 線引き

- テスト・感覚的体験ではE05の識別の要件を適用し、それ以外では画像の情報・操作目的が代替で伝わらないと確認できれば不適合。確認材料が足りなければ、欠けている材料を示して要確認にする。[根拠: 1.1.1-E01, 1.1.1-E05]
- 文字入り、大きいメイン画像、カルーセルという外観だけで装飾を否定しない。内容・機能・周囲との重複を確認する。[根拠: 1.1.1-E01, 1.1.1-E02]
- `alt=""`、`aria-hidden="true"`、ツリーに無いことだけを理由に適合・対象外にしない。画面上で情報を伝えるか、別の状態で表示されるかも確認する。[根拠: 1.1.1-E02, 1.1.1-E04]
- 画像だけのボタン・リンクでは操作目的を表す名前と子画像の露出を両方見る。親の名前だけで子画像の代替欠落を免除しない。`input type="image"` も操作目的を確認する。[根拠: 1.1.1-E01, 1.1.1-E03]
- 非テキストの操作部品は部品側からも確認する。同じ欠陥は報告でまとめ、関係する達成基準を記す。[独自: 重複報告の整理。根拠: 1.1.1-E01]

## 判断例

- 見た形を答える試験画像では、正解を代替テキストで教えることを要求せず、問題の画像だと識別できる説明を用いる。鑑賞体験を主目的とする作品画像も、作品を識別できる説明を用い、体験そのものを文章で完全再現することは要求しない。[根拠: 1.1.1-E05。独自の適用例]
- 可視の「検索」という文字と虫眼鏡画像を同じボタンに置き、画像に追加情報がなく、空のalt等で無視できるなら、画像の説明を重ねて要求しない。画像の目的がボタン名で伝わり、子画像も適切に扱われている例。[根拠: 1.1.1-E01–E03]
- 本文が図の情報を十分に説明している場合、短い識別と本文への参照で足りる。図の全情報をaltに再掲する必要はない。本文が触れていない傾向・関係を図だけで伝える場合は、その不足を確認する。[根拠: 1.1.1-E01]

## 作るとき

- 操作目的を親の名前で表し、追加情報のない子画像は無視できる実装にする。通常の `img` では `alt` を省略せず、装飾なら空にする。[1.1.1-E01–E03]
- 複雑な画像には必要な説明を用意する。名前の長短だけではなく、その場で必要な情報が伝わるかを見る。[1.1.1-E01]

## 確かめるとき

- **確定:** 代替の欠落・不十分さ、または無視できる必要がある画像の不適切な露出を、対象と文脈に照らして確認できた場合に不適合にする。[1.1.1-E01–E03]
- **残る:** 自動チェックの pass の後も、代替の十分さと装飾判断、ツール対象外の内容・状態を確認する。[1.1.1-E04]
- **言い切らない:** alt が無いだけ、名前があるだけ、画像を見ていない状態で適合・不適合を決めない。対象範囲外の音声・映像・CAPTCHA 等がある場合は、WCAG本体の該当分岐を追加確認する。[1.1.1-E01–E04]
