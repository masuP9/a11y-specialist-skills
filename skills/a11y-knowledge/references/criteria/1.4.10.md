# 1.4.10 Reflow

- Scope: Reading directions of content sections and preservation of information/functionality
- Needed: CSS viewport dimensions in the relevant direction, per-section scrolling, before/after content and access paths
- Automated checks: reflow-check (narrow-viewport candidates)

- Sources checked: 2026-11-01. WCAG: 2024-12-12 Recommendation; Understanding / Techniques: live WCAG 2.2 pages. Summaries, not quotations.

## Rationale

### 1.4.10-E01 — Zoom percentage alone does not determine test dimensions

- **Type / source:** [Normative — WCAG 2.2, Reflow, Note 1](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#reflow), [Technique — C32, Tests](https://www.w3.org/WAI/WCAG22/Techniques/css/C32#tests) (Sufficient).
- **Summary:** Vertically scrolling content uses 320 CSS px width; horizontally scrolling content uses 256 CSS px height. Equivalence to 400% assumes starting width 1280 / height 1024 CSS px.
- **Conditions / limits:** Record the relevant CSS dimension, not just zoom or physical pixels. The tool’s default 320×256 is a test setting, not a universal requirement to constrain both directions simultaneously.

### 1.4.10-E02 — Check exception scope and scrolling needed for reading

- **Type / source:** [Normative — Exception / Note 2](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#reflow), [Understanding — Understanding the scope of exceptions](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html#understanding-the-scope-of-exceptions).
- **Summary:** Necessary two-dimensional layouts exempt only the relevant section, not automatically individual table cells. Toolbars require a context where they must remain visible during manipulation.
- **Conditions / limits:** Excepted content may create page-level bidirectional scrolling while other content remains readable in one direction. Scrollbar presence alone is insufficient to fail.

### 1.4.10-E03 — Distinguish collapsed content from lost content

- **Type / source:** [Failure — F102, Description / Tests](https://www.w3.org/WAI/WCAG22/Techniques/failures/F102#tests).
- **Summary:** Hidden content at narrow widths can remain available through disclosures, dialogs, or links to the same/equivalent information and functionality.
- **Conditions / limits:** Moving content or collapsing navigation alone does not establish failure. Actually operate the alternative access path.

### 1.4.10-E04 — Distinguish switching panels from scrolling to read lines

- **Type / source:** [Technique — G225, Description / Tests](https://www.w3.org/WAI/WCAG22/Techniques/general/G225#tests) (Sufficient).
- **Summary:** Horizontally navigated panels can occur on vertically scrolling pages when each panel is readable within 320 CSS px width.
- **Conditions / limits:** A horizontally moving carousel alone does not fail. Check whether additional horizontal scrolling is needed to read text within each panel.

## Judgment lines

- Fail after verifying bidirectional scrolling needed to read non-excepted content or unavailable information/functionality. Horizontal-scroll detection alone is insufficient. [Evidence: 1.4.10-E01–E04]
- Retain the existing policy of reviewing all reflow-check candidates. Excluded selectors and `data-allow-scroll` are tool settings, not WCAG exception decisions. [Our interpretation: tool mapping; implementation: [runReflowCheck.ts](../../../../packages/a11y-audit/src/playwright/runReflowCheck.ts), [constants.ts](../../../../packages/a11y-audit/src/constants.ts)]

## When building

- Prefer adaptable widths, max-width, wrapping, and grid. Keep fixed-size images/iframes within their regions. [Our interpretation: author recommendation; supporting evidence: 1.4.10-E01]
- Recommend containing table scrolling in a dedicated box. Distinguish this from universally prohibiting page-level scrolling. [Our interpretation: author recommendation; supporting evidence: 1.4.10-E02]
- Test the relevant CSS dimension and access paths to collapsed content. [1.4.10-E01, 1.4.10-E03]

## When checking

- **Conclusive:** Bidirectional scrolling without an applicable exception, or lost information/functionality without alternative access. [1.4.10-E01–E04]
- **Remaining:** Table cells, toolbar necessity, readable panel areas, exclusions, and writing/scrolling directions. The current tool mainly detects horizontal overflow, not comprehensive vertical-writing height constraints or functionality. [Our interpretation: tool scope]
- **Do not overclaim:** Zero candidates or scrollbar presence/absence alone does not establish criterion-wide conformance/failure. [Our interpretation: scope management; supporting evidence: 1.4.10-E01–E04]
