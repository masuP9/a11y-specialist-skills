# 2.4.3 Focus Order

- Scope: Sequential focus navigation and state changes, including opening and closing menus and dialogs
- Needed: Observed order, logical relationships, and focus before and after opening/closing. Coordinates alone are insufficient
- Automated checks: focus-order-check, `tabOrder` from focus-indicator-check, axe `tabindex`

- Sources checked: 2026-11-01. WCAG: 2024-12-12 Recommendation; Understanding / Techniques: live WCAG 2.2 pages. The following are summaries, not quotations.

## Rationale

### 2.4.3-E01 — Judge meaning and operability, not visual alignment

- **Type / source:** [Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html#intent).
- **Summary:** More than one logical order can be valid. Focus order may differ from visual or programmatic reading order while preserving meaning and operability.
- **Conditions / limits:** Either of two independent columns may come first. Check sequences that disrupt visually conveyed hierarchy or relationships. Do not require top-to-bottom, left-to-right navigation for every layout.

### 2.4.3-E02 — A tabindex value alone does not establish failure

- **Type / source:** [Failure — F44, Description / Tests](https://www.w3.org/WAI/WCAG22/Techniques/failures/F44#tests), [Technique — G59, Tests](https://www.w3.org/WAI/WCAG22/Techniques/general/G59#tests) (Sufficient).
- **Summary:** F44 concerns tabindex creating an order inconsistent with content relationships and sequence. G59 compares interactive component order with logical order.
- **Conditions / limits:** Positive tabindex starts an investigation; it is not itself a failure. Matching DOM and visual order does not remove the need to check actual navigation.

### 2.4.3-E03 — Opening and closing can have alternative logical paths

- **Type / source:** [Failure — F85, Description / Tests](https://www.w3.org/WAI/WCAG22/Techniques/failures/F85#tests) (updated 2026-08-23).
- **Summary:** F85 distinguishes moving focus into an opened menu/dialog from allowing the next sequential navigation to enter a logical target. On closing, check return to the trigger; if it was removed, another logical destination is allowed.
- **Conditions / limits:** Neither lack of immediate focus movement nor return to a different element alone establishes failure. Check the path into the opened content, whether the trigger still exists, and the next task. This does not eliminate modal focus management.

### 2.4.3-E04 — Focusable static content is not automatically a violation

- **Type / source:** [Understanding — Notes in Intent](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html#intent).
- **Summary:** Static content may receive focus. Orders that impair meaning or operation, including confusing nested focusable elements, can be problematic.
- **Conditions / limits:** This criterion evaluates order. Distinguish reducing unnecessary Tab stops from requirements for components under 4.1.2 and other criteria.

## Judgment lines

- Compare observed order with content relationships and identify concrete harm to meaning or operation before failing. Reversed coordinates or long jumps alone are insufficient. [Evidence: 2.4.3-E01, 2.4.3-E02]
- If no logical-order mismatch remains, measurement of the target state completed, nothing was skipped, and at least one interactive component exists, treat the inspected scope as passing. Leave undecidable states and unmeasured scope for review. [Our interpretation: existing measurement policy; supporting evidence: 2.4.3-E01, 2.4.3-E02]
- Names or selectors suggesting fixed/sticky positioning are clues only. Check actual layout and context rather than failing on displacement alone. [Our interpretation: preventing coordinate-based misjudgments; supporting evidence: 2.4.3-E01]
- Judge opening/closing paths against F85. Our exclusion of dialog names from 4.1.2 does not affect focus-order checks. [Evidence: 2.4.3-E03; policy scope: [4.1.2](./4.1.2.md)]
- Do not fail solely for positive tabindex or focusable static elements. [Evidence: 2.4.3-E02, 2.4.3-E04]

## When building

- Align DOM order with logical reading order; avoid positive tabindex and visual-only reordering. [Our interpretation: maintainable implementation policy; supporting evidence: 2.4.3-E01, 2.4.3-E02]
- Move focus appropriately when opening a modal. Return it to the trigger when closing, or a destination matching the next task if the trigger was removed. [2.4.3-E03]

- Keep hidden content, such as closed menus, out of unintended focus navigation using `inert`, `display: none`, or an appropriate alternative. [Our interpretation: implementation policy; supporting evidence: 2.4.3-E01]

## When checking

- **Conclusive:** Fail when interaction establishes harm to meaning/operability or F85 failure conditions. [2.4.3-E01–E03]
- **Remaining:** Review focus-order-check candidates and `tabOrder` in context. Initial-state testing does not cover opening/closing states. [2.4.3-E01, 2.4.3-E03]
- **Do not overclaim:** Interrupted/capped traversal, skipped elements, or zero candidates do not establish a page-wide pass. [Our interpretation: inspection scope management]
