# 2.5.3 ラベルを含む名前（name）

- 対象の部品: 文字・文字画像の可視ラベルがある操作部品
- 要る材料: 同じ表示状態の画面、個々のラベル、計算された名前、名前と説明の参照先
- 自動チェック: axe `label-content-name-mismatch`。検出対象と文字列比較の限界を確認する
- 原文確認日: 2026-11-02。WCAGは2024-12-12勧告、Understanding / Techniquesは公開ページ（随時更新）。以下は引用ではなく要約。

## 根拠

### 2.5.3-E01 — 完全一致や先頭一致を一律に要求しない

- **種別・出典:** [規範 — Label in Name](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#label-in-name)、[Technique — G208「Description / Tests」](https://www.w3.org/WAI/WCAG22/Techniques/general/G208#description)（Sufficient）。
- **要約:** 可視ラベルの文字列が名前に含まれるか確認する。補足を加えてよい。可視ラベルを名前の先頭に置くことはベストプラクティスで、必須条件ではない。
- **適用条件・限界:** 表示が文字画像でも対象。単語が全部あっても、順序の変更や途中への別語の挿入でラベルの連続した文字列が失われていないか確かめる。

### 2.5.3-E02 — ラベルの範囲と説明を分ける

- **種別・出典:** [Technique — G211「Description / Examples / Tests」](https://www.w3.org/WAI/WCAG22/Techniques/general/G211#description)（Sufficient）、[Understanding — Identifying label text / Accessible Name and Description Computation specification](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html#identifying-label-text-for-components)。
- **要約:** 通常は部品の近くにある個別のラベルを照合し、見出し・グループ名・説明を全部名前に含めるとは要求しない。間に短いヒントがあっても、それだけでラベルを対象外にしない。
- **適用条件・限界:** 大文字小文字・句読点の差だけでFailにしない。丸括弧内の補足は説明として名前から外せるが、必須・入力形式などの重要な情報は別の方法でプログラムから分かるようにする。近くに他のラベルがなければplaceholderも照合候補。この扱いで[3.3.2](./3.3.2.ja.md)のplaceholderのみを不適合とする著者方針を変更しない。

### 2.5.3-E03 — 文字として読むものと記号を区別する

- **種別・出典:** [Understanding — Text labels “express something in human language”](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html#text-labels-express-something-in-human-language)。
- **要約:** 太字操作の「B」や矢印としての「>」など、機能を象徴する記号を文字ラベルとして機械的に照合しない。数式のラベルはこの扱いにせず、式を名前にも保つ。
- **適用条件・限界:** 可視文字ラベルのないアイコンだけの部品はこの基準の対象外。名前や代替の必要性は別基準で評価する。

### 2.5.3-E04 — 名前の欠落・上書き・分断を確認する

- **種別・出典:** [Failure — F96「Examples / Tests」](https://www.w3.org/WAI/WCAG22/Techniques/failures/F96#examples)、[Failure — F111「Description / Tests」](https://www.w3.org/WAI/WCAG22/Techniques/failures/F111#description)。
- **要約:** 可視文字ラベルがあるのに名前がない、別の文字列で上書きされる、途中の隠し文字でラベルが分断される場合を確認する。
- **適用条件・限界:** `aria-label`の存在自体でFailにせず、実際の名前を照合する。説明として読まれるだけの文字列では名前の不足を補えない。

## 線引き

- E02・E03の条件を踏まえたラベルが、名前に連続して同じ順で含まれればPass。名前の先頭でない、名前に補足がある、という理由だけではFailにしない。[根拠: 2.5.3-E01–E03]
- 可視文字ラベルがある部品で、実際の名前の欠落・置換・分断を確認したらFail。実際の音声操作の失敗を再現することは前提にしない。[根拠: 2.5.3-E04]
- 名前の有無は[4.1.2](./4.1.2.ja.md)、可視ラベルの説明性は[2.4.6](./2.4.6.ja.md)と分ける。「検索」という表示と「検索」という名前が一致しても、実際の機能が削除なら説明性は別に問題になる。[独自: 基準間の照合例。根拠: 2.5.3-E01, 2.4.6-E03]

## 判断例

- **Pass:** 表示が「検索」、名前が「サイト内を検索」。先頭一致ではないが文字列を含む。[根拠: 2.5.3-E01]
- **Pass:** 表示が「First Name:」、名前が「first name」。大文字小文字と句読点の差だけでは指摘しない。[根拠: 2.5.3-E02]
- **Pass:** 「Date (YYYY-MM-DD)」に対して名前は「Date」、形式は説明として関連付けられている。[根拠: 2.5.3-E02]
- **対象外:** 太字アイコンの「B」に名前「Bold」。記号のBを名前に追加する要求はしない。[根拠: 2.5.3-E03]
- **Fail:** 表示は「Download specification」、途中の隠し文字により名前は「Download gizmo specification」。ラベルの全単語を含むだけでは不十分。[根拠: 2.5.3-E04]
- **要確認:** 画像ボタンのaltだけ取得でき、画像内の文字は未確認。実際の画像と計算された名前を照合する。[独自: 検査例。根拠: 2.5.3-E01]

## 作るとき

- 個別の可視ラベルを名前に使い、追加の説明で上書き・分断しない。通常はラベルを先頭に置く。説明へ分ける補足の関連付けも保つ。[根拠: 2.5.3-E01–E02, E04]

## 確かめるとき

- **実装確認:** axe-core 4.14.0のルール定義・matches・evaluate、`runAxeAudit`、`DEFAULT_AXE_TAGS`。このルールはexperimentalではなく、既定のWCAGタグで実行対象。実行確認でも、不一致ボタンはviolations、一致ボタンはpassesになった。
- **検出範囲:** 内容から命名できるwidget roleで、ARIA由来の名前と可視の内部文字があるもの。隣接ラベルを持つ通常のテキスト入力や、画像の文字の読み取りを網羅しない。switch等は値表示とラベルの区別が必要で、不一致がincompleteになる場合がある。
- **確定:** violationsのラベル範囲・記号・補足と計算名を照合してFailを確定。incompleteは不足材料を特定する。別の名前チェックで欠落が出た場合も可視ラベルを確認する。[根拠: 2.5.3-E01–E04]
- **言い切らない:** passes・候補ゼロを基準全体のPassにしない。文字画像、外部ラベル、状態切替後の表示、名前と説明の区別は残る。
