# 1.4.1 Use of Color

- Scope: whole page (look for places that convey information by color). Not attached to components
- Inputs needed: image of the whole page (whether cues other than color are visible), element styles (weight, size, underline, border, lightness)
- Automated checks: axe `link-in-text-block` (links in running text)

- Sources checked: 2026-11-01. Understanding / Techniques are the continuously updated WCAG 2.2 published pages. The following are summaries, not quotations.

## Evidence

### 1.4.1-E01 — Check visible cues conveying the same information

- **Type / source:** [Understanding — “Intent”](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html#intent), [Technique — G14 “Examples” / “Tests”](https://www.w3.org/WAI/WCAG22/Techniques/general/G14.html#tests) (Sufficient).
- **Summary:** Check whether visible text, symbols, or other cues also convey the information encoded in color. States or text alternatives available only to assistive technology are not visible alternatives.
- **Conditions / limits:** Color without informational meaning, such as decoration, is outside scope. A link styled exactly like ordinary text also does not fail this criterion because no color distinction exists. Distinguish usability suggestions.

### 1.4.1-E02 — Separate lightness distinctions from identifying specific colors

- **Type / source:** [Understanding — “Intent”, lightness note](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html#intent), [Failure — F81 note under “Examples”](https://www.w3.org/WAI/WCAG22/Techniques/failures/F81#examples).
- **Summary:** A relative-luminance contrast of at least 3:1 can provide an additional visual distinction. If users must identify red versus green itself to understand the meaning, another cue is needed regardless of the ratio.
- **Conditions / limits:** Foreground/background inversion also needs sufficient contrast. Measure rather than deciding from an image's appearance whether 3:1 is met. Distinguish the compared colors from text/background and other comparisons under 1.4.3 / 1.4.11.

### 1.4.1-E03 — Compare inline links with surrounding text

- **Type / source:** [Technique — G183 “Description” / “Tests”](https://www.w3.org/WAI/WCAG22/Techniques/general/G183#tests) (Sufficient).
- **Summary:** Current G183 requires at least 3:1 against surrounding non-link text for inline links distinguished only by color and lightness. Additional indicators such as underlines are recommendations.
- **Conditions / limits:** This is not 3:1 against the background. Separately check both text colors against their backgrounds. Do not add underlines or extra hover indicators as mandatory conditions of this technique.

### 1.4.1-E04 — Check alternatives for each piece of chart or error information

- **Type / source:** [Technique — G111 “Examples” / “Tests”](https://www.w3.org/WAI/WCAG22/Techniques/general/G111.html#tests), [G14 “Examples”](https://www.w3.org/WAI/WCAG22/Techniques/general/G14.html#examples) (both Sufficient), [Failure — F81 “Tests”](https://www.w3.org/WAI/WCAG22/Techniques/failures/F81#tests).
- **Summary:** Check that series/legend patterns, line styles, text, etc. convey the same information, and that required/error fields are identifiable without color alone.
- **Conditions / limits:** A note referring to color is not itself a failure when the same information is also supplied through text or symbols. Reporting the note and affected items separately is a counting policy.

### 1.4.1-E05 — Distinguish visited-link colors from general status indicators

- **Type / source:** [Understanding — “Intent”, visited links note](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html#intent).
- **Summary:** Color differences alone between visited/unvisited links under UA history and :visited constraints do not fail this criterion.
- **Conditions / limits:** Do not extend this to author-managed read status or selection. Continue checking link text against the background separately.

## Judgment lines

- What to look for: places that convey information by a difference in color: chart series and legends, required fields or input errors shown with red text or a red border, navigation or tabs showing the selected item or current location by color, status shown by a colored dot or badge, and notes that explain by color such as "items in red are ...". [Evidence: 1.4.1-E01]
- If the same information can be understood from a cue other than color (text, symbol, shape, pattern, line style, underline, bold, border, icon shape, position), conformant. Cues are limited to what is visible on screen. Text that exists only in the accessibility tree (visually hidden text, `aria-current`) does not count as a visual cue. [Evidence: 1.4.1-E01]
- Even if each item has a different color, do not list it if the visible name or text on that item conveys the same information (buttons with a different color per type and the name written too, like Info / Success / Warning / Error. The color supplements the name). [Our interpretation: author's inspection/reporting policy. Supporting evidence: 1.4.1-E01–E04] (from the pattern of misjudgments)
- List something as selected or current location only when, among items of the same appearance, only one (or some) differs in color. Do not infer the selected item from a row where every color differs. `aria-pressed` / `aria-selected` / `aria-current` do not count as cues, but are used to tell whether the component has a selection state. [Our interpretation: author's inspection/reporting policy. Supporting evidence: 1.4.1-E01–E04]
- Lightness difference: for things where it is enough to tell which one differs from the others (selected / current location, a single differing item), verify sufficient contrast even when foreground/background colors are inverted. A ratio of at least 3:1 can provide a distinction. If measurement is unavailable and the boundary is uncertain, use needs review. Fail when the ratio is below 3:1 and there are no other cues. [Evidence: 1.4.1-E02]
- Things whose meaning cannot be understood without knowing which color it is, like "red is required, blue is optional" or "a green dot is online, a red dot is offline", are non-conformant even with a lightness difference. [Evidence: 1.4.1-E02]
- Even if the meaning of a cue is explained at a distant place on the page, count it as a cue if that explanation is visible (the note "* is required" and "Address *" far away). [Our interpretation: author's inspection/reporting policy. Supporting evidence: 1.4.1-E01–E04]
- When fields or items of the same appearance (red border, red text) are lined up, check the cue for each one. An error message or symbol serves only as a cue for the field it is attached to (if only the neighboring field has an error message, the field without one is non-conformant). [Our interpretation: author's inspection/reporting policy. Supporting evidence: 1.4.1-E01–E04] (from the pattern of misses)
- A note that explains by color alone, like "items in red are required", requires checking for other cues. If text or symbols convey the same information, the note alone is not a failure. Once color-only dependence is confirmed, report both the note and affected items. [Evidence: 1.4.1-E04. Reporting both is our reporting policy]
- A chart is non-conformant if series and legend correspond by color alone. Conformant if there are line styles, marker shapes, names attached directly to the series, or a table of the same values right beside it. [Evidence: 1.4.1-E04. Accepting an adjacent table of the same values is our judgment policy]
- Do not list: links in running text distinguished by color alone (leave to axe `link-in-text-block`), colors with no meaning (heading backgrounds, brand colors, decoration), color swatches that convey the color itself, colors inside photos or illustrations, text/background and similar contrast ratios (1.4.3 / 1.4.11), colors that change only on hover or focus. [Our interpretation: author's inspection/reporting policy. Supporting evidence: 1.4.1-E01–E04] (division)
- Differences that count as cues when checking by style: a `font-weight` difference of 200 or more (400 to 600. A difference of 100 is hard to tell apart), a difference in `font-style`, a font size ratio of 1.125 or more, a difference in `text-decoration-line`, a difference in the thickness of the visible sides of a border, a lightness ratio of 3:1 or more in background or text color. A difference in border color alone does not count. [Our interpretation: author's inspection/reporting policy. Supporting evidence: 1.4.1-E01–E04]

- Do not fail color differences alone between visited and unvisited links; distinguish author-managed states. [Evidence: 1.4.1-E05]
- Retain the existing weight difference of 200, size ratio of 1.125, and the visual-reporting exclusions for photos, illustrations, hover, etc. as our policy. These are not WCAG thresholds or general exemptions. [Our interpretation: author's inspection policy. Supporting evidence: 1.4.1-E01–E04]

## When building

- Where color indicates status or category, always add one more cue: "*" or the word "required" for required fields, a message and icon for errors, bold / underline / border for the selected item, line style / marker / direct labels for chart series.
- Do not write notes like "red text is required". Indicate with a symbol or text instead of color, and explain that meaning in the note.
- Recommend retaining underlines on inline links. This implementation policy is separate from conformance through G183; lack of an underline alone is not a failure. [Our interpretation: author's recommendation. Supporting evidence: 1.4.1-E03]
- If distinguishing by lightness difference, make it 3:1 or more and use it only for "which one differs". Do not substitute lightness for the meaning of a color (red = danger).

## When checking

- **Settled**: retain the policy of treating axe `link-in-text-block` violations as failures within the detected scope. Do not count incomplete results as violations or generalize passes to the whole page. The inspected axe-core 4.14.0 distinguishes 3:1 against surrounding text, style differences, and identical colors. [Our interpretation: tool mapping. Supporting evidence: 1.4.1-E01, 1.4.1-E03. Implementation inspected: `linkInTextBlockEvaluate` / `linkInTextBlockStyleEvaluate` in `node_modules/axe-core/axe.js`]
- **Remains**: look for places matching the judgment lines above by viewing the image of the whole page. For places that look like color alone, re-check for cues by style (weight, underline, border, lightness).
- **Do not assert**: do not mark color coding non-conformant when the name or text conveys the same information. Do not relabel text/background or similar contrast failures as 1.4.1. The 3:1 distinction between colors is also checked under this criterion. Do not judge colors that change on hover from the image.
