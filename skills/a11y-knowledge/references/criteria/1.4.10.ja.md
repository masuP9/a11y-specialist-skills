# 1.4.10 リフロー

- 対象: 各内容領域の読める方向、情報・機能の保持
- 要る材料: 対象方向のCSSビューポート寸法、領域ごとのスクロール、変更前後の内容と到達経路
- 自動チェック: reflow-check（狭いビューポートでの候補抽出）

- 原文確認日: 2026-11-01。WCAGは2024-12-12勧告、Understanding / Techniquesは随時更新のWCAG 2.2公開ページ。以下は引用ではなく要約。

## 根拠

### 1.4.10-E01 — ズーム倍率だけでは検査寸法が決まらない

- **種別・出典:** [規範 — WCAG 2.2「Reflow」のNote 1](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#reflow)、[Technique — C32「Tests」](https://www.w3.org/WAI/WCAG22/Techniques/css/C32#tests)（Sufficient）。
- **要約:** 縦スクロールの内容では幅320 CSS px、横スクロールの内容では高さ256 CSS pxに対応する。400%との対応は、開始幅1280／高さ1024 CSS pxという条件付き。
- **適用条件・限界:** 倍率表示や端末の物理ピクセルだけで判定しない。内容の方向に応じた寸法を記録する。ツールの既定320×256は検査設定であり、両方向を同時に制限する一律の必須条件ではない。

### 1.4.10-E02 — 例外の範囲と、実際に読むためのスクロールを確認する

- **種別・出典:** [規範 — 同基準の例外・Note 2](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#reflow)、[Understanding —「Understanding the scope of exceptions」](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html#understanding-the-scope-of-exceptions)。
- **要約:** 必要な二次元レイアウトの例外は該当領域に限る。表の個々のセルには自動で広がらず、ツールバーも操作中に表示を保つ必要がある文脈で判断する。
- **適用条件・限界:** 例外領域がページの二方向スクロールを生んでも、例外でない内容が一方向だけで読める場合は区別する。スクロールバーの存在だけで不適合にしない。

### 1.4.10-E03 — 折り畳みと消失を区別する

- **種別・出典:** [Failure — F102「Description」「Tests」](https://www.w3.org/WAI/WCAG22/Techniques/failures/F102#tests)。
- **要約:** 狭い表示で内容が見えなくなっても、開閉部品・ダイアログ・別表示へのリンク等で同じか同等の情報・機能へ到達できる場合を区別する。
- **適用条件・限界:** メニューへの収納や配置変更だけで不適合にしない。見えなくなった内容の代替経路を実際に操作して確認する。

### 1.4.10-E04 — 横に送るパネルと、行を読むための横スクロールを区別する

- **種別・出典:** [Technique — G225「Description」「Tests」](https://www.w3.org/WAI/WCAG22/Techniques/general/G225#tests)（Sufficient）。
- **要約:** 縦スクロールのページに横送りのパネル群があっても、各パネルが幅320 CSS px内で読める構成を認める。
- **適用条件・限界:** カルーセル全体が横に動くことだけで不適合にしない。各パネル内の文章を読むために、さらに横スクロールが必要かを確かめる。

## 線引き

- 例外でない内容を読むために二方向スクロールが必要、または情報・機能に到達できないことを確認して不適合にする。横スクロールの検出だけでは決めない。[根拠: 1.4.10-E01–E04]
- reflow-checkの候補はすべて要確認とする既存方針を維持する。除外selectorや`data-allow-scroll`はツール設定であり、WCAGの例外認定ではない。[独自: ツールとの対応。実装: [runReflowCheck.ts](../../../../packages/a11y-audit/src/playwright/runReflowCheck.ts)、[constants.ts](../../../../packages/a11y-audit/src/constants.ts)]

## 作るとき

- 固定幅を避け、max-width・折り返し・grid等で内容を収める。固定幅の画像・iframeも領域に収まるようにする。[独自: 著者の実装推奨。参考根拠: 1.4.10-E01]
- 表等のスクロールは専用の箱に閉じ込めることを推奨する。ページ全体のスクロールを一律に禁じる要件とは区別する。[独自: 著者の推奨。参考根拠: 1.4.10-E02]
- 対象方向のCSS寸法で検査し、折り畳まれた内容の操作経路も確かめる。[1.4.10-E01, 1.4.10-E03]

## 確かめるとき

- **確定:** 例外不成立の二方向スクロール、または代替経路のない内容・機能の消失。[1.4.10-E01–E04]
- **残る:** 表のセル、ツールバーの必要性、パネル内の読める範囲、除外対象、書字・スクロール方向。現行ツールは主に横はみ出しを検出し、縦書きの高さ方向や機能を網羅しない。[独自: ツールの検査範囲]
- **言い切らない:** 候補0件やスクロールバーの有無だけで、基準全体を適合・不適合にしない。[独自: 検査範囲の管理。参考根拠: 1.4.10-E01–E04]
