# 3.2.3 Consistent Navigation

- Scope: navigation repeated within the same set of web pages
- Inputs needed: each page's aria snapshot and screen, set boundaries, presentation conditions, and user preferences. Read [cross-page](../cross-page.md) first
- Automated checks: no dedicated check. `page-snapshot` only supplies material
- Sources checked: 2026-11-02. WCAG is the 2024-12-12 Recommendation; Understanding / Techniques are living WCAG 2.2 public pages. The following are summaries, not quotations.

## Rationale

### 3.2.3-E01 — Check repeated mechanisms and user-initiated changes

- **Type / source:** [Normative — Consistent Navigation](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#consistent-navigation), [Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/consistent-navigation.html#intent).
- **Summary:** Compare repeated navigation within the same set, distinguishing order changes initiated by users, such as presentation preferences or adaptive user agents.
- **Conditions / limits:** Merely following a link to another page does not request reordering. The intent covers consistency of both visual layout and source order.

### 3.2.3-E02 — Separate additions and removals from order reversals

- **Type / source:** [Technique — G61, Description and Tests](https://www.w3.org/WAI/WCAG22/Techniques/general/G61.html#tests) (Sufficient), [Failure — F66, Tests](https://www.w3.org/WAI/WCAG22/Techniques/failures/F66#tests).
- **Summary:** Check relative order between mechanisms and between links within them. Inserting submenus or removing items is not itself a failure. Check for reversals of shared items.
- **Conditions / limits:** Do not require identical item counts or coordinates on every page. Calling something secondary navigation does not exempt its repeated parts.

## Judgment lines

- Group repeated mechanisms from navigation, skip links, search, and header/footer link lists. Compare order after establishing correspondence. [Our interpretation: separating judgment from mechanical comparison. Evidence: 3.2.3-E01–E02]
- Do not flag additions/removals, inserted secondary navigation, or current-location presentation alone. Confirm that the relative order of remaining shared items is preserved. [Evidence: 3.2.3-E02]
- Assign page results using the author policy for majorities and ties in [cross-page](../cross-page.md). On a page assigned a failure, report both mechanisms in the reversed pair without guessing which was moved. [Our interpretation: reporting policy. Evidence: 3.2.3-E02]
- Keep snapshot order comparison as the initial inspection, but do not treat it as conformance of visual order. Also compare screens, for example when CSS reorders items. [Our interpretation: separating inspection scopes. Evidence: 3.2.3-E01]

## Judgment examples

- **Conformant:** Section-specific submenu items are inserted between A, B, and C while their order remains A, B, C. [Evidence: 3.2.3-E02]
- **Non-conforming inconsistency:** Shared A, B becomes B, A in another page's default presentation, without user reordering. Assign page results using the majority policy; record the confirmed reversal even in a tie. [Evidence: 3.2.3-E01–E02. Assignment is author policy]
- **Do not flag under the exception:** A user reorders navigation through presentation preferences. This does not exempt reversals in the author's default presentation. [Evidence: 3.2.3-E01]
- **Needs review:** Both names and destinations differ, leaving functional equivalence unclear. Check destinations and action results to establish the group. [Our interpretation: inspection policy avoiding incorrect exclusions. Evidence: 3.2.3-E02]

## When building

- Use shared navigation components; add page-specific items without changing shared item order. Preserve order between mechanisms such as search as well. [Evidence: 3.2.3-E02]
- Indicate the current location with `aria-current` or similar, without changing order for that presentation. [Our interpretation: author implementation policy. Supporting evidence: 3.2.3-E02]

## When checking

- **Settled:** Results of comparing corresponding mechanisms, relative order, and user-initiated changes. Automated output alone does not settle this. [3.2.3-E01–E02]
- **Remains:** Screens under matching presentation conditions, uncollected menus and iframes, and set boundaries.
- **Do not assert:** Failure merely from additions/removals or coordinate differences, or visual consistency from snapshots alone. [Evidence: 3.2.3-E01–E02]
