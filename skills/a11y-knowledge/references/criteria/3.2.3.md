# 3.2.3 Consistent Navigation

- Scope: multiple pages (navigation elements. The whole page if there is no corresponding element)
- Inputs needed: the aria snapshot of each page (`page-snapshot`). Read [cross-page](../cross-page.md) first
- Automated checks: none

## Rationale

- [Understanding 3.2.3](https://www.w3.org/WAI/WCAG22/Understanding/consistent-navigation.html) ([Japanese translation](https://waic.jp/translations/WCAG22/Understanding/consistent-navigation.html))
  - Navigation mechanisms repeated across multiple pages must appear in "the same relative order" across pages, so users can remember positions and use them.
  - "The same relative order" is satisfied if the order of the remaining items is preserved even when items are added or removed.
  - When the user changed the order themselves, it is an exception.
- [G61: presenting in the same relative order](https://www.w3.org/WAI/WCAG22/Techniques/general/G61), [F66: order differs per page](https://www.w3.org/WAI/WCAG22/Techniques/failures/F66)

## Judgment lines

- The scope is navigation mechanisms repeated across multiple pages: navigation, skip links, search, and rows of links in the header or footer. [Understanding]
- Not violations: items being added or removed (a submenu inserted, an item that exists only on that page), section-specific sub-navigation, and only the current page's item changing its presentation. [Understanding]
- Separate judgment from mechanical comparison. Do not do the judgment of grouping "the same thing across pages" and the comparison of whether the order matches in the same place. After grouping, compare the relative order per group. [Our interpretation]
- When a group's order is reversed, mark both mechanisms in the group non-conformant (on a page where search comes before navigation, both search and navigation are non-conformant). Do not decide which one was moved. [Our interpretation]
- Excluding an entire mechanism as "only on this page" or "a section's sub-navigation" leaves that mechanism unevaluated. Check that nothing was excluded that should not have been. [Our interpretation]
- Handling of majority, even splits, and viewports is in [cross-page](../cross-page.md).

## When building

- Make the header, footer, and global navigation shared components and show them in the same order on every page.
- When adding page-specific items, add them without changing the order of the shared items.
- The current page's item may change its presentation (`aria-current="page"`).
- Do not move the search form between the header and the footer depending on the page.

## When checking

- **Settled**: none.
- **Remains**: pick up navigation mechanisms from each page's snapshot, group the same ones, and compare the relative order per group.
- **Do not assert**: do not mark the addition or removal of items non-conformant. Do not evaluate a mechanism that exists on only one page. Whether items with different names and different link targets are a rewording of the same item or different items cannot be decided from the wording alone, so when in doubt, needs review.
