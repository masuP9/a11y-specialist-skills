# 2.5.7 Dragging Movements

- Scope: whole page
- Inputs needed: measurement (pointer-gesture-check from `@a11y-skills/audit`. Candidates for elements that seem to be operated by dragging)
- Automated checks: pointer-gesture-check (the same single measurement as 2.5.1)

## Rationale

- [Understanding 2.5.7](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html) ([Japanese translation](https://waic.jp/translations/WCAG22/Understanding/dragging-movements.html))
  - Functionality operated by dragging needs a means to do the same thing with a single pointer without dragging (click to pick and click to place, move with buttons).
  - The exception is when dragging is essential (drawing).
  - Distinct from the gestures (paths) of 2.5.1. Dragging is a single-pointer operation of "press, move, release", but the need to move is the problem.
- [G219: an alternative to dragging](https://www.w3.org/WAI/WCAG22/Techniques/general/G219), [F108: dragging only](https://www.w3.org/WAI/WCAG22/Techniques/failures/F108)

## Judgment lines

- As with 2.5.1, measurement only goes as far as listing candidates. One or more candidates is needs review; zero is not applicable. Neither conformant nor non-conformant is marked. [Our interpretation]
- Whether it actually moves when dragged is not confirmed. [Our interpretation]

## When building

- Give reordering (sortable lists) up and down buttons or keyboard operation.
- Make sliders movable with arrow keys (a standard `<input type="range">` works by default).
- Where files are dropped by drag and drop, also place a file selection button.

## When checking

- **Settled**: none.
- **Remains**: for each candidate, actually try whether the same thing can be done without dragging.
- **Do not assert**: do not mark conformant or not applicable while there are candidates. Do not mark non-conformant from candidates alone.
