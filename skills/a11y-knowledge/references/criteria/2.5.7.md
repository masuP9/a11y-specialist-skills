# 2.5.7 Dragging Movements

- Scope: dragging functionality provided by the author
- Inputs needed: pointer-gesture-check candidates and results of single-pointer operation without dragging
- Automated checks: pointer-gesture-check (the same run as 2.5.1)

- Sources checked: 2026-11-01. WCAG refers to the 2024-12-12 Recommendation; Understanding / Techniques are the continuously updated WCAG 2.2 published pages. The following are summaries, not quotations.

## Evidence

### 2.5.7-E01 — Check that the alternative also works with a single pointer

- **Type / source:** [Understanding — “Intent”](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html#intent), [Failure — F108 “Tests”](https://www.w3.org/WAI/WCAG22/Techniques/failures/F108#tests).
- **Summary:** Keyboard arrow support alone is insufficient. A single pointer must operate the same function without dragging.
- **Conditions / limits:** Entering a value in a text input can be an alternative. Do not exclude text entry through a touchscreen's on-screen keyboard. If the only alternative requires a path gesture, also check 2.5.1.

### 2.5.7-E02 — Separate controls on the same page and multiple actions are allowed

- **Type / source:** [Understanding — “Intent”](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html#intent), [Technique — G219 “Examples” / “Tests”](https://www.w3.org/WAI/WCAG22/Techniques/general/G219#tests) (Sufficient).
- **Summary:** The alternative must be on the same page and perform the same function. It need not use the same component or a single click. A menu choosing a destination after selection or up/down buttons can work.
- **Conditions / limits:** The existence of another control is insufficient; verify that it actually selects the required destinations, values, etc.

### 2.5.7-E03 — Check UA behavior and essential exceptions

- **Type / source:** [Normative — WCAG 2.2 “Dragging Movements”](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#dragging-movements), [Understanding — “Intent” / “Examples”](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html#intent).
- **Summary:** UA-determined functionality that the author has not modified is excepted. Ordinary scrolling and scrolling through CSS overflow do not require the same author-provided alternatives as custom dragging.
- **Conditions / limits:** Check separately when the author suppresses or reimplements standard behavior. A line-drawing interface such as a matching quiz can have a selection alternative; drawing alone does not establish essentiality.

## Judgment boundaries

- Fail a nonessential drag-only function that does not qualify for the UA exception. Evaluate keyboard operability separately under 2.1.1. [Evidence: 2.5.7-E01–E03]
- Follow [2.5.1's judgment boundaries](./2.5.1.md#judgment-boundaries) for candidates and page-level manual-review nodes. Zero candidates alone must not change needs review to not applicable. The tool exercises neither dragging nor alternatives. [Our interpretation: tool mapping]

## When building

- Provide clickable/tappable up/down buttons or destination menus for reordering. Keyboard support alone is not the alternative. [Evidence: 2.5.7-E01, 2.5.7-E02]
- Provide slider track clicks/taps, increment/decrement buttons, or value inputs, and verify that required values can be selected. [Evidence: 2.5.7-E01]
- Include a file chooser button with a file drop zone. [Our interpretation: author's implementation policy. Supporting evidence: 2.5.7-E01]

## When checking

- **Established:** Whether a single pointer performs the same function without dragging and whether an exception applies. [2.5.7-E01–E03]
- **Remaining:** Actual candidate behavior, the range of functionality available through alternatives, and modifications to standard behavior.
- **Do not conclude:** Candidates alone do not establish failure. Arrow-key operation alone does not establish conformance. [2.5.7-E01]
