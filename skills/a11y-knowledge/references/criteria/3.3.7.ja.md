# 3.3.7 冗長な入力

- 対象: 同じプロセスの中で、既に入力した情報や利用者に提供した情報をもう一度入力させる箇所
- 要る材料: プロセス全体の入力項目と提示した情報、前の値、再入力欄の初期値と選択手段、再入力を求める理由
- 自動チェック: `redundant-entry-check`は1ページ内の重なりの候補だけを出す。複数ページの手順は手動で確認する
- 原文確認日: 2026-11-05。WCAGは2024-12-12勧告。Understandingは2025-09-17更新、G221は2026-03-09更新の公開ページ（随時更新）。以下は引用ではなく要約。

## 根拠

### 3.3.7-E01 — 対象のプロセスと情報を決める

- **種別・出典:** [規範 — Redundant Entry](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#redundant-entry)、[用語 — process](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#dfn-processes)、[Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/redundant-entry.html#intent)、[G221「Examples」](https://www.w3.org/WAI/WCAG22/Techniques/general/G221#examples)（Sufficient）。
- **要約:** 同じプロセスで入力した情報と、利用者に提供した情報が対象。G221の例2のように、前のステップで発行された識別番号も含む。第三者の決済を挟むなど、プロセスは別ドメインにまたがることがある。
- **適用条件・限界:** セッション間の保存は要求しない。セッションを閉じた後や離脱後に戻った場合は適用しない。履歴書のアップロードのように別の方法で渡された情報は対象外。

### 3.3.7-E02 — 自動入力と選択の手段を確認する

- **種別・出典:** [規範 — Redundant Entry](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#redundant-entry)、[Understanding — Intent / Examples](https://www.w3.org/WAI/WCAG22/Understanding/redundant-entry.html#intent)、[G221「Tests」](https://www.w3.org/WAI/WCAG22/Techniques/general/G221#tests)（Sufficient）。
- **要約:** 変更できる初期値としての表示は自動入力の例。選択には、ドロップダウン等から選んで入れる、ページ上の文字を選択して入力欄へコピーする、「請求先と同じ」のチェックボックスが含まれる。選択できる情報は同じページに必要で、開閉部品の中でもよい。
- **適用条件・限界:** 「available to select」は手段を限定しない。ブラウザの自動補完だけでは足りず、コンテンツ側が情報を提供する。既定で見え、入力欄の近くにあることは理想であり必須条件ではない。Understandingは、同じ情報を求めないことも将来の手法候補に挙げる。

### 3.3.7-E03 — 3つの例外を確認する

- **種別・出典:** [規範 — Redundant Entry](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#redundant-entry)、[Understanding — Exceptions](https://www.w3.org/WAI/WCAG22/Understanding/redundant-entry.html#exceptions)。
- **要約:** 例外は、再入力が必要不可欠（記憶ゲーム等）、内容のセキュリティ確保に必要（パスワードの表示・コピーの防止等）、前の情報が有効でなくなった場合。表示しないパスワードを手入力で作るときの再確認は例外に当たる。
- **適用条件・限界:** プライバシーや個人情報に特有の例外はない。ただし、自動入力の実装では一時保存時も含めてデータを保護する（[Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/redundant-entry.html#intent)）。

### 3.3.7-E04 — エラー後の値の保持と3.3.8を分ける

- **種別・出典:** [Understanding — Examples / Intent](https://www.w3.org/WAI/WCAG22/Understanding/redundant-entry.html#examples)。
- **要約:** 誤ったカード番号で送信してエラーになっても、送信した情報を消さないことが例に挙がる。検索結果ページで検索語を初期値にすることも例の一つ。
- **適用条件・限界:** これらは例であり、すべての再表示に同じ実装を求める記述ではない。ブラウザの自動入力は[3.3.8](./3.3.8.ja.md)では十分な手法だが、この基準ではコンテンツ側の提供を求める。

## 線引き

- 同じプロセスで同じ情報を再び求める欄について、自動入力、同じページでの選択、例外のいずれかが成立すればPass。どれも成立せず入力し直すしかなければFail。[根拠: 3.3.7-E01–E03]
- 前のステップの情報を次のステップで入れ直させ、そのページに値も選択手段もなければFail。ブラウザの自動補完が働くことはPassの理由にしない。[根拠: 3.3.7-E02]
- 同じページの確認用メール欄や請求先・配送先のように、前の欄の値が見えていて、選択してコピーし貼り付けられるなら、この基準のFailにしない。値を伏せている、又は貼り付けを禁止しているなら、例外がない限りFail。[独自: Understandingの「ページ上の文字を選択してコピーする」を入力欄の値にも適用する方針。根拠: 3.3.7-E02]
- 末尾4桁だけの表示のように、値の一部しか選べないものは選択手段として扱わない。[独自: 必要な情報全体を選べないため。根拠: 3.3.7-E02]
- 送信エラーの後、エラーでない項目まで消して入れ直させるならFail。却下された項目だけを空にすることは「有効でなくなった」として扱い、パスワード欄を空にすることはセキュリティの例外として扱う。[独自: 却下された項目の扱い。根拠: 3.3.7-E03–E04]
- パスワードの再確認や操作前の再認証は例外として扱う。セキュリティ以外の理由しかない欄へ広げない。[根拠: 3.3.7-E03]
- 手順内の「戻る」部品で前のステップへ戻ると値が消える場合は、同じプロセスとして判定する。ブラウザの戻る・再読み込みで消えるだけなら、離脱と区別できないのでFailにせず改善候補とする。[独自: 手順の中で提供された移動と離脱を分ける方針。根拠: 3.3.7-E01]
- 検索語を残さないことだけではFailにしない。同じ語の再入力が手順の完了に必要な場合に判定する。[独自: 検索語の初期値は例であり必須条件ではないため。根拠: 3.3.7-E04]

## 判断例

- **Pass:** 第1ステップで入力した社員番号が第3ステップに変更可能な初期値で入っている。[根拠: 3.3.7-E02]
- **Pass:** 次のステップに「請求先と同じ」のチェックボックスがあり、選ぶと配送先の値が入る。[根拠: 3.3.7-E02]
- **Pass:** 前のステップで発行された番号がそのページに表示され、選択してコピーし入力欄へ貼り付けられる。[根拠: 3.3.7-E01–E02]
- **対象外:** 翌日に再訪して、新しいセッションで住所を入力する。[根拠: 3.3.7-E01]
- **対象外:** 履歴書をアップロードした後に、職歴を入力欄へ入れる。別の方法で渡した情報のため。[根拠: 3.3.7-E01]
- **例外:** 新規パスワードを非表示で作成し、確認欄に再入力する。[根拠: 3.3.7-E03]
- **Fail:** 配送先住所を入力した次のページで請求先住所を求めるが、初期値もコピーの手段もなく、同じページに前の住所もない。[根拠: 3.3.7-E01–E02]
- **Fail:** 同じページのメール確認欄が貼り付けを禁止している。例外の理由もない。[独自: 同じページの扱い。根拠: 3.3.7-E02]
- **Fail:** 第三者の決済ページで、購入手続きで入力済みの請求先住所をもう一度入力させ、選択手段もない。[根拠: 3.3.7-E01–E02]
- **要確認:** 同じプロセスでカードのセキュリティコードを再び求める。原文に例がないので、再要求の理由がセキュリティ要件かを確認する。プライバシーへの配慮だけなら例外にしない。[独自: 検査例。根拠: 3.3.7-E03]

## 作るとき

- まず同じ情報を求めない。必要なら変更できる初期値で入れるか、同じページで選べるようにする。[根拠: 3.3.7-E02]
- 送信エラーでは受理できる入力を保持する。再利用する値は一時保存時も含めて保護する。[根拠: 3.3.7-E03–E04]

## 確かめるとき

- **実装確認:** axe-core 4.14.0にwcag337タグのルールはない。`redundant-entry-check`（`a11y-skills/redundant-entry`）は、同じformの中、又はformの外の欄全体で目的が重なる2つ目以降の編集できる欄を`incomplete`にする。
- **確定:** プロセス全体を通した入力・提示の記録と、実際の自動入力・選択の操作、例外の理由を照合した結果。
- **候補の扱い:** `copyControls`は文言の一致であり、値が写ることを確かめていない。パスワード・ワンタイムコード欄を集計しないのはツールの範囲であり、例外の成立を意味しない。読み込み時に隠れている欄も数える。
- **残る:** 候補0件はPassにしない。複数ページの手順、提供された情報の再入力、別のform、チェックボックス・ラジオボタン、iframe・shadow DOMの中は検出しない。手順を通した確認ができなければ、未確認のステップを明記して要確認にする。
