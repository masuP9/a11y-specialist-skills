# 3.2.4 Consistent Identification

- Scope: repeated components with the same functionality within a set of pages
- Inputs needed: names, roles, locations, action results, visible labels, icons, and context. Read [cross-page](../cross-page.md) first
- Automated checks: no dedicated check. Names from `page-snapshot` alone do not settle this
- Sources checked: 2026-11-02. WCAG is the 2024-12-12 Recommendation; Understanding / Techniques are living WCAG 2.2 public pages. The following are summaries, not quotations.

## Rationale

### 3.2.4-E01 — A shared destination does not establish a shared component

- **Type / source:** [Normative — Consistent Identification](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#consistent-identification), [Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/consistent-identification.html#intent).
- **Summary:** Evaluate repeated components with the same function. Footer and body contact links illustrate components not perceived as instances of the same repeated component. Repetition within one page in the set can also be included.
- **Conditions / limits:** URLs and landmarks are grouping clues, not definitive identity tests. This criterion does not require consistent identification of non-functional content or different functions.

### 3.2.4-E02 — Do not substitute exact string matching for consistency

- **Type / source:** [Technique — G197, Tests](https://www.w3.org/WAI/WCAG22/Techniques/general/G197#tests) (Understanding pairs it with sufficient techniques for labels, names, and alternatives under 1.1.1 / 4.1.2), [Failure — F31, Description and Examples](https://www.w3.org/WAI/WCAG22/Techniques/failures/F31#examples).
- **Summary:** G197's identical text is one sufficient method. F31 gives “Search / Find” and “Save page / Save” as failures, while allowing contextual number differences such as “Go to page 4 / Go to page 5.”
- **Conditions / limits:** Do not make the technique's exact-match test the only normative condition. Explicitly identify author policies that differ from F31 examples.

### 3.2.4-E03 — Check both names and visual identification

- **Type / source:** [Understanding — Examples 3–9](https://www.w3.org/WAI/WCAG22/Understanding/consistent-identification.html#examples).
- **Summary:** Contextual “Page 4 / Previous page” and responsive changes from search text to a magnifying glass are conforming examples. Changing the save icon between a floppy disk and a checkmark fails even with the same name.
- **Conditions / limits:** Also check differing names when appearance matches. Do not exclude the same search component in the header and footer merely because its location differs.

## Judgment lines

- In step 1, group repeated components by location and role, checking destinations and action results. Distinguish separate contact links in the body and footer, but do not exclude repeated components solely for different locations. [Our interpretation: candidate grouping policy. Evidence: 3.2.4-E01, E03]
- In step 2, assess recognition of the same function. Allow contextual differences in numbering and current-location presentation. Treat unexplained wording changes such as “お問い合わせ / Contact” as different; inspect context when evidence is insufficient, such as abbreviations. [Evidence: 3.2.4-E02–E03. Japanese examples and abbreviation handling are author policy]
- Retain the policy that an unchanged main term with added explanation or decoration counts as the same wording. This author policy is broader than F31's “Save page / Save” failure example; do not present it as an official conforming example. Do not extend this allowance to modifiers distinguishing functions or changes to identifying icons. [Our interpretation: avoiding misjudgments from superficial wording differences. Comparison evidence: 3.2.4-E02–E03]
- Retain initial snapshot filtering of running-text links and checkboxes, but do not treat them as outside WCAG's scope. Supplement with screens and DOM inspection when the same function repeats. Do not identify links as equivalent solely from `#`. [Our interpretation: disclosing candidate extraction limits. Evidence: 3.2.4-E01]
- Use the majority policy in [cross-page](../cross-page.md) for assignment across pages. Separately inspect same-page repetition and visual identification; do not extend passes for extracted candidates to the entire criterion. [Our interpretation: inspection policy. Evidence: 3.2.4-E01, E03]

## Judgment examples

- **Conformant:** “Go to page 4 / Go to page 5,” or contextual “Page 4 / Previous page.” Do not demand identical strings. [Evidence: 3.2.4-E02–E03]
- **Non-conforming inconsistency:** “Search / Find” for the same search, or floppy-disk/checkmark icons for the same save. Matching names must not hide the latter. [Evidence: 3.2.4-E02–E03]
- **Do not flag under author policy:** “保存 / ページを保存” for the same save function when the difference only adds explanation. Record the difference from F31. [Our interpretation: wording policy above. Comparison evidence: 3.2.4-E02]
- **Out of scope:** Separate footer and body contact links, or different results such as printing receipts versus invoices. Clear names remain recommended. [Evidence: 3.2.4-E01, E03]
- **Needs review:** It is unclear whether unnamed checkboxes perform the same action across pages. Obtain appearance, surrounding instructions, and action results. [Our interpretation: inspection policy. Evidence: 3.2.4-E01]

## When building

- Give the same repeated function shared names and visual identification, reflecting only necessary context differences. [Evidence: 3.2.4-E02–E03]
- Prefer specific names for different functions, but do not fail 3.2.4 solely because they share an icon. [Our interpretation: implementation recommendation. Supporting evidence: 3.2.4-E01]

## When checking

- **Settled:** Results of comparing identification after confirming the same repeated function. [3.2.4-E01–E03]
- **Remains:** Visible labels/icons, same-page repetition, inputs excluded by extraction, and actual action results.
- **Do not assert:** Conformance or failure from matching URLs or names alone. Majority is not an official conformance condition. [Evidence: 3.2.4-E01–E03. Assignment is author policy]
