# 3.2.4 Consistent Identification

- Scope: multiple pages (components such as links, buttons, and input fields)
- Inputs needed: the aria snapshot of each page (`page-snapshot`). The component's name, role, the landmark it is placed in, and link target. Read [cross-page](../cross-page.md) first
- Automated checks: none

## Rationale

- [Understanding 3.2.4](https://www.w3.org/WAI/WCAG22/Understanding/consistent-identification.html) ([Japanese translation](https://waic.jp/translations/WCAG22/Understanding/consistent-identification.html))
  - Components with "the same functionality" across multiple pages must be identified consistently (the same name, the same alternative text).
  - "Consistent" is not "identical". It is enough that users can tell it is the same functionality ("Search" and a magnifying glass icon named "Search").
  - If the functionality differs even with the same name, the name should be changed.
- [G197: the same label for the same functionality](https://www.w3.org/WAI/WCAG22/Techniques/general/G197), [F31: different names for the same functionality](https://www.w3.org/WAI/WCAG22/Techniques/failures/F31)

## Judgment lines

- The scope is components that appear repeatedly (components that appear with the same role on multiple pages, such as global navigation, search, account actions, and footer links). Even if the function or link target is the same, the same identification is not required unless it is a repetition of the same component. "Contact" in the footer and "Contact the support team" in the body text, or a card on the top page and an item on a list page, are each different components. [Understanding]
- "Consistent" is not "identical". The axis of judgment is whether a user who learned one can recognize the other as having the same function. Things that differ only in a number, like "Go to page 4" and "Go to page 5", or the text "Search" and a magnifying glass icon named "Search", are consistent. [Understanding]
- The same function may have different link targets (language switching). If the function differs even with the same icon, the name should be changed. [Understanding]
- Step 1 (is it the same component): decide by the place it is in (landmark) and its role. Components within banner / navigation / contentinfo / search are compared as the same component if they have the same function. Components in the body (main) are treated as the same component only when they appear with the same role on every page (each page's "Save" button, pagination). Even if the name differs on only one page, put it in the same component if it corresponds to a component with the same role on other pages. Things with different places or roles (a body component and a footer component, a card on the top page and an item on a list page) are not the same component even with the same link target. [Our interpretation] (from the pattern of misjudgments)
- Step 2 (is it called the same): things with the same function but different wording ("Contact" and "お問い合わせ") are different. Things that differ only in a number, where only the current page's presentation changes, or where one name contains the other's main word as is with only an explanation or decoration (emoji) added, are the same. Cases where judgment is split, like an abbreviation and its full name, are needs review. [Our interpretation]
- Narrowing candidates: exclude links in running text (text directly under the parent) from candidates. However, do not exclude those inside navigation / banner / contentinfo / search. Exclude checkboxes (unnamed ones can only be identified as the same component by appearance). Keep buttons, but those whose function cannot be told from the name alone are needs review. [Our interpretation]
- A link to within the page (href starting with `#`) becomes each page's URL to itself, so do not treat them as the same by link target. [Our interpretation]
- Handling of majority, even splits, and viewports is in [cross-page](../cross-page.md).

## When building

- Make components with the same functionality shared components and decide the name in one place ("Search", "Contact", "Log in").
- Keep the names (aria-label) of icon-only buttons the same across pages.
- Do not change the language or wording by page, like "Contact" and "お問い合わせ".
- Do not use the same icon for different functionality.

## When checking

- **Settled**: none.
- **Remains**: pick up components from each page's snapshot, group them into the same component in step 1, divide them into groups by wording in step 2, and judge disagreements by majority.
- **Do not assert**: do not mark different components (different place or role) non-conformant for lacking the same identification. Do not mark differences that only add decoration non-conformant.
