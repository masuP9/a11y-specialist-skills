# 2.4.7 フォーカスの可視化

- 対象: ページ全体（操作できる要素すべて）
- 要る材料: 実測（`@a11y-skills/audit` の focus-indicator-check。フォーカス前後の計算済みスタイルの差分）
- 自動チェック: focus-indicator-check

## 根拠

- [Understanding 2.4.7](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)（[日本語](https://waic.jp/translations/WCAG22/Understanding/focus-visible.html)）
  - キーボードでフォーカスした要素が、どれか分かる表示になっていること。ブラウザ既定のフォーカスリングで満たせる。
  - 表示の形（outline、背景、下線、枠）は問わない。どれだけ見やすいかは 2.4.11〜2.4.13 と 1.4.11 の範囲。
- [G149: 既定のフォーカス表示を消さない](https://www.w3.org/WAI/WCAG22/Techniques/general/G149)、[C15: フォーカス時にスタイルを変える](https://www.w3.org/WAI/WCAG22/Techniques/css/C15)、[F55: フォーカスを外す](https://www.w3.org/WAI/WCAG22/Techniques/failures/F55)、[F78: outline を消す](https://www.w3.org/WAI/WCAG22/Techniques/failures/F78)

## 線引き

- 判定は Tab でフォーカスを送った実測を根拠にする。実測が無いときは判定しない。[独自]
- 実測は outline・box-shadow・背景色・border・text-decoration の計算済みスタイルの変化だけを見る。疑似要素（`::after`）、文字色、親要素の変化は見えない。変化が無くてもフォーカスが見えないとは確定できないので、**不適合は付けない**。変化の無い要素があれば要確認とし、目で確かめる要素を挙げる。[独自]
- 変化の無い要素が無く、実測が最後まで終わり、飛ばした要素が無ければ適合。ただし色の差の大きさは見ていないと書き添える。[独自]
- 実測が途中で止まった、要素を飛ばした（URL の変化でやり直した）、操作できる要素が 0 件、のときは適合を付けない。[独自]

## 作るとき

- `outline: none` / `outline: 0` を書かない。消すなら代わりの表示（`box-shadow`、背景、下線）を `:focus-visible` で付ける。
- フォーカスの表示は、要素の全周か、少なくとも 2 辺に出す。色だけの変化にしない（1.4.11 で 3:1 が要る）。
- フレームワークの CSS リセットが outline を消していないか確かめる。
- 自作の部品（div + tabindex）にも `:focus-visible` のスタイルを付ける。

## 確かめるとき

- **確定**: 無し（不適合は付けない）。
- **残る**: 実測で変化の無かった要素を目で確かめる。
- **言い切らない**: スタイルの差分が無いことだけで不適合にしない。途中で止まった実測で適合にしない。
