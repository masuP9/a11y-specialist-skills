# 3.3.1 エラーの特定

- 対象の部品: form、input（クライアント側・サーバー側の入力検証）
- 要る材料: 誤入力、検証結果、エラー時の画面・テキスト代替・属性
- 自動チェック: 専用チェックなし。入力前の画面だけでは判断しない
- 原文確認日: 2026-11-02。WCAGは2024-12-12勧告、Understanding / Techniquesは随時更新のWCAG 2.2公開ページ。以下は引用ではなく要約。

## 根拠

### 3.3.1-E01 — 自動検出された入力エラーを対象にする

- **種別・出典:** [規範 — Error Identification](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#error-identification)、[Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html#intent)。
- **要約:** 検出したエラーについて、項目と誤りの内容が分かるテキストを確認する。範囲外の値を自動補正した場合も、変更を説明する。
- **適用条件・限界:** 検証しないことと、検証して拒否するのに説明がないことを区別する。後者を対象外にしない。修正方法は[3.3.3](./3.3.3.ja.md)で確認する。

### 3.3.1-E02 — エラーの配置を一つに限定しない

- **種別・出典:** [Technique — G83「Description」](https://www.w3.org/WAI/WCAG22/Techniques/general/G83#description)、[G85「Description」](https://www.w3.org/WAI/WCAG22/Techniques/general/G85#description)（ともに3.3.1のSufficient）。
- **要約:** 未入力や形式の誤りを、欄のそば、一覧、ダイアログ等で説明できる。どの欄のどの問題かを利用者が特定できることを確認する。
- **適用条件・限界:** 一覧や各欄へのリンクは唯一の方法ではない。赤枠だけ・説明のないアイコンだけでは不足する。

### 3.3.1-E03 — 属性の有無と説明の十分さを分ける

- **種別・出典:** [Technique — ARIA21「Description」「Tests」](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA21#tests)（Sufficient）、[Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html#intent)。
- **要約:** ARIA21では検証結果に応じて状態を付け、ラベル・説明とともにエラーを伝える。検証前から `aria-invalid="true"` にしない。この属性の使用自体は規範の必須条件ではない。
- **適用条件・限界:** 属性だけで説明が十分とは言わず、属性がないだけで3.3.1不適合とも言わない。テキスト代替も評価する。ネイティブHTML検証は利用環境で項目とエラーを伝えられれば適合し得るが、3.3.3まで自動的に満たすとはしない。

## 線引き

- 検出されたエラーの項目・内容がテキストまたはテキスト代替で分かれば、この条件を満たす。エラー状態を未取得なら、再現に必要な入力と操作を記して要確認にする。[根拠: 3.3.1-E01–E03]
- 表示位置・特定のARIA属性・エラー一覧の欠落だけでFailにしない。関連付け・状態・通知に問題があれば、1.3.1 / 4.1.2 / 4.1.3の適用条件を別途照合する。[根拠: 3.3.1-E02–E03]

## 判断例

- **適合:** サーバーが「メールアドレスの形式が正しくありません」と該当欄を特定して返す。修正方法の十分さは3.3.3で別に判断する。[根拠: 3.3.1-E01–E02]
- **不適合:** 送信を拒否し赤枠だけを表示する。テキスト代替もない。範囲外の数量を黙って上限に直す場合も、説明の欠落を指摘する。[根拠: 3.3.1-E01–E03]
- **指摘しない:** ネイティブ検証が項目とエラーを伝えているのに、独自の `aria-invalid` がないことだけを指摘する。[根拠: 3.3.1-E03]
- **要確認:** 初期画面しかなく、空送信後やサーバー検証後の応答を見ていない。その状態を取得して決める。[独自: 検査方針。根拠: 3.3.1-E01]

## 作るとき

- 欄のそばの説明と関連付けを基本とし、複数エラーでは一覧と欄へのリンクを用意する。これは推奨する実装であり唯一の適合方法ではない。[独自: 修正箇所へ移りやすくする方針。根拠: 3.3.1-E02–E03]
- 検証後に状態と説明を更新し、修正後は古いエラーを残さない。[根拠: 3.3.1-E03]

## 確かめるとき

- **確定:** 検出されたエラーと、その項目・内容を伝える説明を照合した結果。[3.3.1-E01–E03]
- **残る:** サーバー応答、自動補正、ネイティブ検証の利用環境での提示。副作用を許せる環境で誤入力を試す。
- **言い切らない:** 入力前の静的検査やARIA属性だけで適否を決めない。[独自: 検査方針]
