# 3.2.1 On Focus

- Scope: components receiving focus and resulting context changes
- Inputs needed: before/after interaction logs, URL, display, focus position, distinction from activation
- Automated checks: focus-indicator-check `details.onFocusViolations` and related fields; checks URL changes during Tab navigation
- Sources checked: 2026-11-02. WCAG is the 2024-12-12 Recommendation; Understanding / Techniques are living public pages. The following are summaries, not quotations.

## Rationale

### 3.2.1-E01 — Separate focus from activation, and content changes from context changes

- **Type / source:** [Normative — On Focus](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#on-focus), [Understanding — Intent / Changes of context](https://www.w3.org/WAI/WCAG22/Understanding/on-focus.html#intent).
- **Summary:** Check submissions, new windows, focus moves to other components, and similar results of focus alone. Scope includes pointer-induced focus, not only Tab.
- **Conditions / limits:** Clicking a button also activates it; do not attribute every subsequent navigation to focus. Highlighting or supplemental content alone need not change context. URL change and context change are not equivalent.

### 3.2.1-E02 — Use activation and do not unexpectedly remove received focus

- **Type / source:** [Technique — G107, Tests](https://www.w3.org/WAI/WCAG22/Techniques/general/G107#tests) (Sufficient), [Failure — F55, Tests](https://www.w3.org/WAI/WCAG22/Techniques/failures/F55.html#tests).
- **Summary:** Change context through user activation rather than focus. Check failure conditions when focus is removed immediately upon receipt.
- **Conditions / limits:** Moving focus into help whenever a field receives focus fails. Do not extend that judgment to merely showing instructions while retaining focus.

## Judgment lines

- Judge actual focus operations and outcomes. A focus-triggered new window or focus-stealing dialog can fail without any URL change. Tab-based URL testing does not define the SC's full scope. [Evidence: 3.2.1-E01–E02]
- Retain the default failure for elements with measured origin/pathname changes accompanying focus. If evidence establishes a display-neutral history update or an independent timer instead, do not fail from this evidence. Do not attribute unidentified navigation to another element. [Our interpretation: URL-based inspection policy. Evidence: 3.2.1-E01]
- Query/hash-only changes require review of content, focus, and cause rather than automatic failure. Resolve to Fail for confirmed context changes or no finding for mere URL updates. [Our interpretation: URL-candidate review policy. Evidence: 3.2.1-E01]
- Retain scoped conformance for “page navigation on Tab focus” when there are no violations/unresolved URL candidates, at least one operable target, and a completed measurement. State that new windows, dialogs, and elements not reached by Tab remain untested. Do not use this limited result to erase known violations outside that scope. [Our interpretation: reporting policy with explicit scope. Supporting evidence: 3.2.1-E01–E02]
- Do not pass with incomplete/unidentified results such as interrupted, aborted, or unidentifiedNavigation. The current tool puts URL differences into onFocusViolations; even normalized violations require separate interpretation of query/hash changes. Unidentified navigation remains incomplete. [Our interpretation: tool mapping. Implementation checked: `packages/a11y-audit/src/playwright/runFocusIndicatorCheck.ts`, `src/utils/axe-format.ts`]

## Judgment examples

- **Conformant:** Focus shows supplemental information while remaining in place; submission/navigation waits for activation. [Evidence: 3.2.1-E01–E02]
- **Non-conformant:** Focusing a field alone moves focus into a help dialog. Flag even without a URL change. [Evidence: 3.2.1-E01–E02]
- **Do not flag:** Enter activates a button and navigates. Focus alone changes nothing. [Evidence: 3.2.1-E02]
- **Needs review:** Hash changed after Tab, but the display was not captured. Inspect major content changes, focus movement, and cause. [Our interpretation: inspection example. Evidence: 3.2.1-E01]

## When building

- Trigger submissions/navigation through explicit activation, not focus handlers. Evaluate change events separately under 3.2.2. [Evidence: 3.2.1-E01–E02]
- Keep the original interaction available when displaying supplemental information. [Evidence: 3.2.1-E01]

## When checking

- **Settled:** Context changes caused by focus. The URL-based default follows the author policy above. [3.2.1-E01–E02]
- **Remains:** Mere URL updates, activation/timer attribution, and context changes the tool does not test.
- **Do not assert:** Conformance from unchanged URLs or failure for every focus-related content update. [Evidence: 3.2.1-E01]
