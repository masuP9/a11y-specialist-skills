# 3.2.1 On Focus

- Scope: whole page, and the element that caused the violation
- Inputs needed: measurement (`onFocus` from focus-indicator-check in `@a11y-skills/audit`. Elements whose URL changed on focus alone)
- Automated checks: focus-indicator-check

## Rationale

- [Understanding 3.2.1](https://www.w3.org/WAI/WCAG22/Understanding/on-focus.html) ([Japanese translation](https://waic.jp/translations/WCAG22/Understanding/on-focus.html))
  - Receiving focus alone must not cause a "change of context" (moving to another page, moving focus, a new window, a major rearrangement of content).
  - A visual change on focus (highlighting, a tooltip) is not a change of context.
- [G107: changing on action rather than on focus](https://www.w3.org/WAI/WCAG22/Techniques/general/G107), [F55: removing focus as soon as it is received](https://www.w3.org/WAI/WCAG22/Techniques/failures/F55)

## Judgment lines

- The verdict is based on measurement that sent focus with Tab. Without measurement, do not judge. [Our interpretation]
- If there is an element whose origin or pathname changed on focus alone, non-conformant (the navigation is observed directly, so no exception applies). Attach it to the element if the violating element can be identified, otherwise to the whole page. [Understanding]
- A URL change within the same document (query / hash only) is not automatically marked non-conformant. It also occurs with `pushState` / `replaceState`, so whether it is a navigation that changes the screen content cannot be known from the URL alone. Needs review. [Our interpretation]
- Conformant if there are no violations, the measurement finished to the end, and there is at least one operable element. Add "only page navigation on Tab focus was examined (new windows, dialogs, and elements not reachable by Tab are out of scope)". [Our interpretation]
- When the measurement ended without knowing which element caused the navigation (`unidentifiedNavigation`), do not mark conformant. [Our interpretation]
- An SPA implementation that rewrites only the pathname with `replaceState` remains as a false positive. [Our interpretation]

## When building

- Do not navigate, submit, or move focus on the `focus` event. Change things on `click` / `change` / Enter.
- Do not auto-navigate on a select box's `change` (3.2.2).
- Showing a tooltip on focus is fine.

## When checking

- **Settled**: if `onFocus` has an element whose origin or pathname changed, non-conformant.
- **Remains**: for elements where only the query / hash changed, check whether the screen content changes.
- **Do not assert**: do not mark conformant without measurement. Do not mark conformant from a measurement that stopped partway.
