# 3.3.3 エラー修正の提案

- 対象の部品: form、input（自動検出された入力エラー）
- 要る材料: エラー状態、受け付ける形式・値、提示される修正方法、例外の理由
- 自動チェック: 専用チェックなし
- 原文確認日: 2026-11-02。WCAGは2024-12-12勧告、Understanding / Techniquesは随時更新のWCAG 2.2公開ページ。以下は引用ではなく要約。

## 根拠

### 3.3.3-E01 — 既知の修正方法と例外を照合する

- **種別・出典:** [規範 — Error Suggestion](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#error-suggestion)、[Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/error-suggestion.html#intent)。
- **要約:** 自動検出された入力エラーについて、修正の提案が分かっていれば提示する。提示するとセキュリティ又はコンテンツの目的を損なう場合は例外となる。
- **適用条件・限界:** 正しい個人情報を推測することまで求めない。既知の形式・許容値の説明と、正解そのものの開示を区別する。3.3.1のエラー特定は別に確認する。

### 3.3.3-E02 — 形式と許容値に合った提案をする

- **種別・出典:** [Technique — G85「Description」](https://www.w3.org/WAI/WCAG22/Techniques/general/G85#description)、[G84「Description」](https://www.w3.org/WAI/WCAG22/Techniques/general/G84#description)（ともにSufficient）。
- **要約:** 形式の誤りには正しい形式の説明・例、限定された値の誤りには許容値の一覧や近い候補を示せる。
- **適用条件・限界:** 誤りの通知だけで直せるとは限らない。一方、別メッセージを機械的に要求せず、既存の説明も含めて何を直せるか確認する。

### 3.3.3-E03 — 提案の配置・提示手段を限定しない

- **種別・出典:** [Technique — G177「Description」「Tests」](https://www.w3.org/WAI/WCAG22/Techniques/general/G177#tests)（Sufficient）、[Understanding — Examples](https://www.w3.org/WAI/WCAG22/Understanding/error-suggestion.html#examples)。
- **要約:** 修正候補を欄のそばに出すほか、近くのリンクから候補一覧へ案内できる。月名に数字が入力されたとき、月名の一覧や該当する月名を示す例がある。
- **適用条件・限界:** 常に一つの正解を自動決定する必要はない。利用者が提案を見つけ、選べるかを確認する。

## 線引き

- 既知の修正方法があり、例外に当たらないのに「無効な値です」だけなら不適合。検証仕様や応答が未取得なら、既知の形式・候補と実際の提示を確認する。[根拠: 3.3.3-E01–E03]
- 認証に使う正しい秘密の値を教えないことは例外として扱う。ただし「パスワード欄だから」すべての提案を免除しない。新規登録時の公開された長さ条件など、安全に伝えられる修正方法は示す。[独自: 規範の例外を機能ごとに適用する方針。根拠: 3.3.3-E01]
- ネイティブ検証のメッセージも内容で評価する。ブラウザが出したという理由だけで適合・不適合にしない。[根拠: 3.3.3-E01–E02]

## 判断例

- **適合:** 7桁以外の郵便番号に「郵便番号は7桁の数字で入力してください」と示す。独立した候補一覧は不要。[根拠: 3.3.3-E02]
- **適合:** 意味の明らかな氏名欄の未入力に「氏名を入力してください」と示す。入力すべき本人の氏名を提案する必要はない。[独自: 既知の修正方法の適用例。根拠: 3.3.3-E01–E02]
- **不適合:** 許容する都道府県名が分かっているのに、表記誤りへ「エラー」とだけ返し、候補や修正説明へも案内しない。[根拠: 3.3.3-E02–E03]
- **例外で指摘しない:** ログイン時、正しい秘密のパスワードを開示しない。新規登録で短すぎる値に必要な文字数を示さないケースには、この例外を広げない。[独自: 例外の適用例。根拠: 3.3.3-E01]
- **要確認:** 「入力を確認してください」という応答しかなく、許容値も周辺の説明も未取得。その資料を取得して修正可能性を判断する。[独自: 検査方針。根拠: 3.3.3-E01–E02]

## 作るとき

- 誤りの内容と修正方法を一緒に示す。候補が複数なら選択や一覧へのリンクを用意する。[根拠: 3.3.3-E02–E03]
- 秘密を開示せずに説明できる制約を伝える。例外は対象の機能と損なわれるセキュリティ・目的を記録する。[独自: 実装・報告方針。根拠: 3.3.3-E01]

## 確かめるとき

- **確定:** 実際のエラー、既知の修正方法、提示内容、例外を照合した結果。[3.3.3-E01–E03]
- **残る:** 未入力・形式違い・許容値外など検証の分岐、サーバー応答、候補へのリンク先。
- **言い切らない:** 初期画面だけで適否を決めず、エラー説明があるだけで修正提案まで適合にしない。[独自: 検査方針]
