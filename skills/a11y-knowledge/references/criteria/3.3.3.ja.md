# 3.3.3 エラー修正の提案

- 対象の部品: form
- 要る材料: エラーが起きた状態の画面
- 自動チェック: 無し

## 根拠

- [Understanding 3.3.3](https://www.w3.org/WAI/WCAG22/Understanding/error-suggestion.html)（[日本語](https://waic.jp/translations/WCAG22/Understanding/error-suggestion.html)）
  - 入力エラーが自動で検出され、修正の方法が分かるなら、それを利用者に示すこと。
  - 例外は、セキュリティや目的を損なう場合（パスワードの正しい値を示す）。
  - 「必須です」だけでは修正の提案にならない場合がある（何を入れるかが分からない）。形式の誤りなら、正しい形式の例を示す。
- [G84: 誤りの内容を示す](https://www.w3.org/WAI/WCAG22/Techniques/general/G84)、[G85: 正しい形式を示す](https://www.w3.org/WAI/WCAG22/Techniques/general/G85)、[G177: 修正の候補を示す](https://www.w3.org/WAI/WCAG22/Techniques/general/G177)

## 線引き

- 3.3.1 と同じく、エラーの状態が情報に出ていなければ要確認。修正の提案の仕組みが確認できないことを理由に不適合にしない。[解説書]
- エラーが出ている画面で、誤りの内容だけで修正の方法が無い（「無効な値です」）なら、修正の方法が分かる場合に限り不適合。[解説書]

## 作るとき

- エラーメッセージに、何が誤りで、どう直せばよいかを書く（「郵便番号は 7 桁の数字で入力してください（例: 1000001）」）。
- 候補が決まる誤り（都道府県名の表記ゆれ）は候補を示す。
- パスワードの誤りは、正しい値を示さない（例外）。

## 確かめるとき

- **確定**: 無し。
- **残る**: 実際に誤った入力で送信し、修正の方法が示されるかを見る。
- **言い切らない**: 入力前の画面だけで適合・不適合を付けない。
