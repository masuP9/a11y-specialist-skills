# 3.3.8 Accessible Authentication (Minimum)

- Scope: Each authentication step for existing users (including multi-factor authentication, account recovery, and conditionally shown CAPTCHAs)
- Materials: All authentication paths and steps, the action each step requires, measured paste and autofill behavior, and the actual CAPTCHA challenge
- Automated check: `accessible-authentication-check` reports candidates. It does not judge whether alternatives exist or what a challenge asks
- Sources checked: 2026-11-05. WCAG: Recommendation of 2024-12-12. Living published pages updated: Understanding 2026-09-06, G218 2025-07-15, H100 2026-01-12, F109 2026-04-27. The following are summaries, not quotations.

## Evidence

### 3.3.8-E01 — Separate what counts as a cognitive function test

- **Type / source:** [Normative — Accessible Authentication (Minimum)](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#accessible-authentication-minimum), [Term — cognitive function test](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#dfn-cognitive-function-test), [Understanding — Cognitive Function Tests](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html#cog-fun-tests).
- **Summary:** Memorization, character transcription, correct spelling, calculation, and puzzles qualify. This includes remembering a site-specific password or a pattern gesture.
- **Conditions / limits:** Name, email address, and phone number are identifiers personal to the user and consistent across sites, so they are not memorization tests. Do not apply this to site-specific usernames.

### 3.3.8-E02 — Determine the steps in scope

- **Type / source:** [Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html#intent), [Cognitive Function Tests](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html#cog-fun-tests), [Object Recognition](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html#object-recognition).
- **Summary:** Authentication of existing users is in scope. Multi-factor authentication needs a path where every step meets the conditions. Identity checks for account recovery need a method that is not a cognitive function test. Tests triggered by ad blockers or repeated incorrect entry are also in scope.
- **Conditions / limits:** Creating a username or initiating an account is out of scope. Not blocking paste and similar measures also reduce the burden of registration, but are not requirements of this criterion there.

### 3.3.8-E03 — Check for another method without a cognitive function test

- **Type / source:** [Normative — Accessible Authentication (Minimum)](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#accessible-authentication-minimum), [Understanding — Examples](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html#examples), [Two-factor authentication systems](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html#two-factor-authentication), [G218 “Tests”](https://www.w3.org/WAI/WCAG22/Techniques/general/G218#tests) (Sufficient).
- **Summary:** Examples include email links, WebAuthn, third-party login with OAuth, hardware keys, operating-system authentication, scanning a QR code, and confirming a notification on a device.
- **Conditions / limits:** An audio CAPTCHA requiring transcription is not an alternative ([Cognitive Function Tests](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html#cog-fun-tests)). WebAuthn and OAuth are potential future techniques but appear among Understanding's examples. G218's object-recognition step 5 is an AAA-only condition.

### 3.3.8-E04 — Check that paste and autofill are not stopped

- **Type / source:** [Normative — Note 2](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#accessible-authentication-minimum), [Understanding — Login forms](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html#login-forms), [Copy and paste](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html#copy-paste), [H100 “Description / Tests”](https://www.w3.org/WAI/WCAG22/Techniques/html/H100#description) (Sufficient).
- **Summary:** Normative Note 2 gives password manager support and paste as examples of mechanisms. Understanding says that either blocking autofill or blocking paste fails unless an alternative is provided. H100's procedure checks for an appropriate accessible name and that pasting is allowed.
- **Conditions / limits:** H100 covers login with only an email and password. Its example has `autocomplete`, but the procedure does not check it. The statement that inputs meeting 1.3.5 and 4.1.2 are generally recognized does not guarantee actual filling.

### 3.3.8-E05 — Check split entry and other formats

- **Type / source:** [Failure — F109 “Description / Tests”](https://www.w3.org/WAI/WCAG22/Techniques/failures/F109#description), [Understanding — Copy and paste](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html#copy-paste).
- **Summary:** Requiring entry in a different format from the one originally created is a failure. Examples include digit-by-digit inputs that cannot take the whole value in one paste, entering “the 2nd, 6th, and last characters”, and selecting each character with a `select`.
- **Conditions / limits:** If the whole value can be pasted into the first input and the rest populate automatically, it does not match the F109 example. It applies to entering all characters or a subset. F109 does not hold when an alternative method exists.

### 3.3.8-E06 — Judge verification codes by paste

- **Type / source:** [Understanding — Two-factor authentication systems](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html#two-factor-authentication).
- **Summary:** Requiring manual transcription of a verification code is not compliant. It must at least be possible to paste the code and to allow user agents to fill the fields automatically.
- **Conditions / limits:** When a code reaches a secondary device, evaluation assumes it can reach the clipboard. Evaluate whether the content accepts pasting; whether the devices can transfer the code is out of scope.

### 3.3.8-E07 — Check the scope of object recognition and personal content

- **Type / source:** [Normative — Accessible Authentication (Minimum)](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#accessible-authentication-minimum), [Understanding — Object Recognition](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html#object-recognition), [Personal Content](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html#personal-content).
- **Summary:** Recognizing material things that can be seen and touched (including vehicles and animals) and identifying non-text content the user provided are exceptions. They may be images, video, or audio.
- **Conditions / limits:** Remembering or transcribing a site-set word, recognizing a picture the site provided, tasks beyond recognition (such as multiplying cats by dogs), and text-based personal content are not excepted. Cultural differences in objects are not treated as accessibility-specific. AAA 3.3.9 has no such exceptions.

### 3.3.8-E08 — Separate other tests and hidden characters

- **Type / source:** [Understanding — Other types of cognitive tests](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html#other-cognitive-tests), [Hiding characters](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html#hiding-content).
- **Summary:** Calculations and visual puzzles are not excepted and need another method. An option to show the password is given as an optional feature that reduces burden.
- **Conditions / limits:** Do not make a show-password option a requirement of this criterion. The source also acknowledges cases needing typing, such as creating a password to save in a password manager.

## Judgment lines

- Pass when each authentication step has no cognitive function test, or an alternative, mechanism, object recognition, or personal content holds. Fail when none holds. [Evidence: 3.3.8-E01–E04, E07]
- Fail when password or code inputs block pasting and no alternative exists. Working autofill alone does not change this. [Author policy: Normative Note 2 lists examples; this adopts Understanding's reading that blocking autofill or paste fails. Keeps the existing judgment policy. Evidence: 3.3.8-E04]
- Accept an alternative after confirming every step on that path avoids cognitive function tests. When a passkey, OAuth, or other option from Understanding's examples actually works, do not send it back to needs review on abstract uncertainty alone. [Evidence: 3.3.8-E02–E03]
- Do not Fail on `autocomplete="off"` alone. Actually try autofill: if a script or similar stops it, Fail when no alternative exists, even if paste works. If it fills, do not report it. [Author policy: The attribute alone cannot establish “active blocking”. Evidence: 3.3.8-E04]
- Do not Fail only because an `autocomplete` attribute or a show-password option is missing. Judge 1.3.5 and 4.1.2 targets under those criteria. [Evidence: 3.3.8-E04, E08]
- Judge a CAPTCHA by the action actually required, not the presence of a widget. Do not treat one that shows no challenge as a test. A CAPTCHA outside authentication (contact form, registration) is out of scope here. [Author policy: Judgment order. Evidence: 3.3.8-E02, E07]
- Conformance through object recognition or user-provided images is an AA Pass. Report 3.3.9 separately when evaluating it, and do not mix it into AA failures. [Evidence: 3.3.8-E07]

## Judgment examples

- **Pass:** An email and password login does not stop pasting or autofill. [Evidence: 3.3.8-E04]
- **Pass:** Pasting a password is blocked, but all steps can be completed with an email link or passkey. [Evidence: 3.3.8-E03]
- **Pass:** The whole SMS verification code can be pasted into the input. Transfer between devices is not evaluated. [Evidence: 3.3.8-E06]
- **Pass:** Digit-by-digit inputs populate when the whole code is pasted into the first one. [Evidence: 3.3.8-E05]
- **Pass:** A login CAPTCHA only asks users to select photos of cars. [Evidence: 3.3.8-E07]
- **Out of scope:** Entering a new password during registration. [Evidence: 3.3.8-E02]
- **Fail:** A password input rejects pasting and tells users to type it. No alternative exists. [Evidence: 3.3.8-E04]
- **Fail:** Users must enter only characters 1, 3, and 5 of a password in separate inputs. No alternative exists. [Evidence: 3.3.8-E05]
- **Fail:** After repeated incorrect entries, a distorted-text or calculation CAPTCHA appears. Its audio version also requires transcription, and no alternative exists. [Evidence: 3.3.8-E01–E03, E08]
- **Fail:** Password recovery only asks for a text answer to a secret question. [Evidence: 3.3.8-E02, E07]
- **Needs review:** Paste was not measured for a form that appears after pressing the login button or for inputs in an iframe. Open that form and measure. [Author policy: Inspection example. Evidence: 3.3.8-E04]
- **Needs review:** A CAPTCHA widget is on the page, but the challenge after repeated incorrect entries was not checked. Reproduce the trigger and record the challenge type. [Author policy: Inspection example. Evidence: 3.3.8-E02, E07]

## When building

- Give inputs appropriate names and autofill values, and do not stop paste or autofill. Allow verification codes to be entered all at once. [Evidence: 3.3.8-E04–E06]
- Offering alternatives such as passkeys, email links, or third-party login lets users choose. Object recognition and personal content remain barriers despite the exception, so avoid them if possible. [Evidence: 3.3.8-E03, E07]

## When checking

- **Implementation confirmed:** axe-core 4.14.0 has no rule tagged wcag338. `auth-paste-blocked`, `auth-autocomplete`, and `auth-captcha` from `accessible-authentication-check` are all `incomplete` and do not judge whether alternatives exist or what a challenge asks.
- **Settled:** The result of comparing each step on all paths, actual paste and autofill, alternatives, and the challenge. For blocked paste, also record `valueAfterPaste` and `pasteEventPrevented`.
- **Reading candidates:** Paste is measured with a short two-character string, and a single inserted character also yields `inserted`. Check split inputs and whole-value paste at the actual code length. `inserted` alone is not conformance. [Evidence: 3.3.8-E05]
- **Remaining:** Places not found (iframes and shadow roots, forms after a button press, custom implementations without `captcha` in the name, later authentication steps, and recovery paths) and unmeasured states (`unavailable`, `focus-moved`, invisible inputs). Zero candidates or no in-scope inputs is not Pass. State the unchecked paths and mark needs review.
