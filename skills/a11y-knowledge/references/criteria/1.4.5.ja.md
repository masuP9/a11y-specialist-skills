# 1.4.5 文字画像

- 対象の部品: image
- 要る材料: 画像の中身（スクリーンショット）、名前・キャプション・周りの文章
- 自動チェック: 無し

## 根拠

- [Understanding 1.4.5](https://www.w3.org/WAI/WCAG22/Understanding/images-of-text.html)（[日本語](https://waic.jp/translations/WCAG22/Understanding/images-of-text.html)）
  - 「文字画像」の定義の注: 文字以外の部分が重要な視覚的コンテンツである画像は、文字画像に当たらない。解説書はグラフ・スクリーンショット・ダイアグラムを例に挙げる。
  - 例外は「カスタマイズ可能」（利用者が文字の見た目を変えられる）と「必要不可欠」（ロゴタイプなど、特定の表現が情報に欠かせない）。
  - 意図は、利用者が文字の見た目（フォント・サイズ・色・行間）を自分に合わせて変えられること。
- [C22: CSS で見た目を付ける](https://www.w3.org/WAI/WCAG22/Techniques/css/C22)、[C30: 文字画像を切り替えられる](https://www.w3.org/WAI/WCAG22/Techniques/css/C30)

## 線引き

- 画像の中に文字があり、その文字を HTML の文字で表せるのに画像にしているときに不適合。[解説書]
- 判断の軸は「画像が伝えたいのが文字の中身（文章）か、文字以外の見た目か」。[解説書]（定義の注）
  - 文字以外の部分が大事な見た目の内容である画像（グラフ・ダイアグラム・アプリやサイトの画面を写した画像）は、文字が多くても文字画像に当たらず適合。[解説書]
  - 文字だけが写っていても、文字の形や配置を見せる意図の画像（フォントの見本、組版の例、手書き、見た目の比較）は、画像であることが欠かせないので適合。[解説書]（必要不可欠）
  - 文字の中身を伝えるだけの画像は不適合。文章を引用するために載せた画面の写し（記事・SNS の投稿・メールの文面を読ませるもの）、文章や説明を画像にしただけのもの（無地の背景に文字が並ぶ画像）。画面の写しでも、見せたいのが文字の中身だけなら例外にしない。[独自]（定義の注の読み方）
- ロゴや商標の文字は例外で適合。[解説書]（必要不可欠）
- 写真やイラストと文字が一体になった表現（写真の上にキャッチコピーを載せたメイン画像やバナー。文字だけを HTML にすると同じ見た目を再現できないもの）、写真にたまたま写った看板の文字、図の一部の小さな文字（グラフの目盛り）は例外で適合。例外に当たるのは文字が見た目の表現と切り離せない場合で、文章や説明を画像にしただけのものは当たらない。[独自]（運用上の線引き。書く前は写真とキャッチコピーの画像をすべて不適合にしていた）
- 文字の無い画像は対象外。[解説書]
- どれに当たるかは、周りの文脈（figure のキャプション・周りの文章・名前）と画像の中身（画面・ウィンドウの枠・UI 部品・図の軸や線・文字の並べ方）から判断する。キャプションや名前で示されていなくても、画像の中身で判断してよい。[独自]
- 画像を見られないときは、名前や周りの情報から文字画像とはっきり分かる場合（名前が長い文章）だけ不適合とし、分からなければ要確認。「〜の画面」「スクリーンショット」「〜のグラフ」「フォントの見本」と分かれば不適合にしない。[独自]

## 作るとき

- 見出し・ボタン・お知らせの文字を画像にしない。Web フォントと CSS で表現する。
- ロゴは画像でよいが、alt に組織名を入れる。
- グラフ・画面の写しは画像でよい。中の文字の要点は alt か本文に書く（1.1.1）。
- 写真とキャッチコピーを重ねたメイン画像は、可能なら文字を HTML にして CSS で重ねる。できないときは alt にコピーの文字を入れる。

## 確かめるとき

- **確定**: 無し。
- **残る**: 文字の入った画像を 1 つずつ、上の軸（文字の中身か、見た目か）で決める。
- **言い切らない**: 画像を見ずに文字画像と決めない。グラフ・画面の写し・ロゴを不適合にしない。
