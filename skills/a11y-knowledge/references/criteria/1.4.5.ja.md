# 1.4.5 文字画像

- 対象の部品: image
- 要る材料: 画像の中身（スクリーンショット）、名前・キャプション・周りの文章
- 自動チェック: 無し
- 原文確認日: 2026-11-02。WCAGは2024-12-12勧告、Understanding / Techniquesは随時更新の公開ページ。以下は引用ではなく要約。

## 根拠

### 1.4.5-E01 — 実現可能性と二つの例外を照合する

- **種別・出典:** [規範 — Images of Text](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#images-of-text)、[Understanding — Intent / Examples](https://www.w3.org/WAI/WCAG22/Understanding/images-of-text.html#intent)。
- **要約:** 使用する技術で表示を実現できるか、利用者によるカスタマイズ又は特定の表現の必要不可欠性があるか確認する。ロゴタイプは必要不可欠とされる。
- **適用条件・限界:** 書体・組版の見本など表現自体が情報である場合を含む。制作上の都合だけを必要不可欠としない。社名だけの画像・表紙・サムネイルへの広い扱いは以下の著者方針であり、公式の包括的免除ではない。

### 1.4.5-E02 — 重要な視覚情報のある画像と文字だけの伝達を分ける

- **種別・出典:** [規範 — images of text](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#dfn-images-of-text)。
- **要約:** 文字以外にも重要な視覚情報がある画像は、文字画像の定義から除かれる。
- **適用条件・限界:** 画像の形式やファイル名だけで決めない。画面の写しでも文章だけを読ませる用途をどう扱うかは、以下で著者方針として明示する。

### 1.4.5-E03 — 同じ情報を可視テキストでも提供する経路を確認する

- **種別・出典:** [Understanding — Intentの注記](https://www.w3.org/WAI/WCAG22/Understanding/images-of-text.html#intent)。
- **要約:** 画像と同じ情報を、利用者が見た目を調整できるテキストでも提示していれば、この基準を満たす。
- **適用条件・限界:** altや読み上げ専用の隠しテキストの存在だけで、この可視テキストの経路を認めない。AAAの[1.4.9](./1.4.9.ja.md)には同じ扱いを広げない。

### 1.4.5-E04 — 表示切替の実動作を確認する

- **種別・出典:** [Technique — C22「Description」](https://www.w3.org/WAI/WCAG22/Techniques/css/C22#description)、[C30「Description」](https://www.w3.org/WAI/WCAG22/Techniques/css/C30#description)（いずれもSufficient）。
- **要約:** テキストをCSSで表現する方法や、画像表示からテキスト表示に切り替える操作を提供する方法がある。
- **適用条件・限界:** 切替先の情報と操作の利用可能性を確認する。画像を単に拡大できるだけでは、文字の見た目を利用者の要求に合わせられるとは限らない。これらの実装方法を唯一の方法にしない。

## 線引き

- 画像の文字を使用する技術のテキストで表せるのに画像だけで伝え、以下の例外・対象外にも当たらないときは不適合。同じ情報を調整可能な可視テキストでも提示している場合は適合とする。[根拠: 1.4.5-E01・E03]
- 文字の無い画像は対象外。[根拠: 1.4.5-E02]
- 文字画像に当たらない画像と、下の例外に当たる画像も、適合ではなく対象外にする。[独自: 根拠: 1.4.5-E01–E02。同じ体裁の資料の表紙が適合と不適合に割れたため、例外の扱いを 1 つにそろえた]
- 判断の軸は「画像が伝えたいのが文字の中身（文章）か、文字以外の見た目か」。[根拠: 1.4.5-E02]
  - 文字以外の部分が大事な見た目の内容である画像（グラフ・ダイアグラム・アプリやサイトの画面を写した画像）は、文字が多くても文字画像に当たらず対象外。[根拠: 1.4.5-E02]
  - 製品やサービスの紹介で見出しの横に置く画面のイメージ図（ウィンドウの枠・ボタン・入力欄・メニューを描いたもの）も、画面を写した画像と同じに扱う。[独自: 画像の意図と見た目から判断する既存の運用方針。根拠: 1.4.5-E01–E02]
  - 文字だけが写っていても、文字の形や配置を見せる意図の画像（フォントの見本、組版の例、手書き、見た目の比較）は、画像であることが欠かせないので対象外。[根拠: 1.4.5-E01]
  - 文字の中身を伝えるだけの画像で、同じ情報の可視テキストや他の達成経路がなければ不適合。文章を引用するために載せた画面の写し（記事・SNS の投稿・メールの文面を読ませるもの）、文章や説明を画像にしただけのもの（無地の背景に文字が並ぶ画像）。画面の写しでも、見せたいのが文字の中身だけなら例外にしない。[独自: 根拠: 1.4.5-E01–E02。定義の注の読み方]
- ロゴや商標の文字は例外で対象外。[根拠: 1.4.5-E01]
  - 社名・団体名・ブランド名・製品やサービスの名前だけが写っている画像は、書体が普通に見えてもロゴとして扱う（導入企業や取引先の一覧に並ぶ社名の画像）。名前だけかどうかは、名前（alt）ではなく画像に写っている文字で決める。名前にキャッチコピーや説明文が添えてあれば、名前だけとは見なさない。[独自: 文字だけのロゴを見た目で区別できないための既定方針。根拠: 1.4.5-E01。規範がすべての社名画像をロゴと認定するという意味ではない]
- 資料・書籍・ホワイトペーパーの表紙と、セミナー・イベント・記事のサムネイル（アイキャッチ画像）は例外で対象外。その資料や催しの見た目そのものを見せる画像なので、文字がタイトルだけでも、文字が主な内容でも当たる。[独自: 根拠: 1.4.5-E01–E02。必要不可欠の読み方]
- 写真やイラストと文字が一体になった表現（写真の上にキャッチコピーを載せたメイン画像やバナー。文字だけを HTML にすると同じ見た目を再現できないもの）、写真にたまたま写った看板の文字、図の一部の小さな文字（グラフの目盛り）は例外で対象外。例外に当たるのは文字が見た目の表現と切り離せない場合で、文章や説明を画像にしただけのものは当たらない。[独自: 根拠: 1.4.5-E01–E02。運用上の線引き。書く前は写真とキャッチコピーの画像をすべて不適合にしていた]
- どれに当たるかは、周りの文脈（figure のキャプション・周りの文章・名前）と画像の中身（画面・ウィンドウの枠・UI 部品・図の軸や線・文字の並べ方）から判断する。キャプションや名前で示されていなくても、画像の中身で判断してよい。[独自: 画像の意図と見た目から判断する既存の運用方針。根拠: 1.4.5-E01–E02]
- 名前（alt）の中身は、画像の中に文字があるか、文章を画像にしたものかの手がかりにしない。alt が長い文章でも、隣の見出しや本文と同じ文でも、HTML のタグを含んでいても、それは代替テキストの書き方で、画像に何が写っているかは分からない。[独自: 根拠: 1.4.5-E01–E02。製品の画面のイメージ図の alt が隣の見出しと同じで、「見出しを画像にした」と不適合にした誤りから]
- 画像を見られないときは不適合にしない。名前や周りの文（「〜の画面」「スクリーンショット」「〜のグラフ」「〜の図」「フォントの見本」「資料の表紙」）から上の対象外に当たる画像と分かれば対象外、分からなければ要確認。ただし文章を引用するための画面の写しと分かれば、対象外にしない。[独自: 画像の意図と見た目から判断する既存の運用方針。根拠: 1.4.5-E01–E02]
- 利用者が見た目を調整できる画像や、利用可能な操作で同じ内容のテキスト表示へ切り替えられるものは指摘しない。カスタマイズ例外は既存の報告方針に合わせ対象外、テキスト表示への切替経路は適合として記録する。[根拠: 1.4.5-E01・E04。報告区分は独自]

## 判断例

- **適合:** 画像化した告知と同じ情報を、隣の可視テキストでも読めて見た目を調整できる。altだけの提供とは分ける。[根拠: 1.4.5-E03]
- **適合:** 見出し画像を、利用可能な表示切替で同じ内容のHTMLテキストにできる。[根拠: 1.4.5-E04]
- **対象外:** 書体の違いを比較する標本画像。文字の形そのものが伝える情報である。[根拠: 1.4.5-E01。報告区分は独自]
- **対象外（著者方針）:** 紹介する資料の表紙や、導入企業の社名だけを写した画像。上記の既定方針を採り、抽象的な不確実性だけで要確認に戻さない。[独自: 既存方針の適用例。根拠: 1.4.5-E01–E02]
- **不適合:** 通常の説明文を無地背景の画像だけで提示し、altはあるが、可視テキスト・切替・例外のいずれもない。[根拠: 1.4.5-E01・E03–E04]
- **要確認:** 取得できない画像のaltが長い文章だが、画像の用途は不明。画像本体と周辺の表示、同じ情報の可視テキストを取得する。[独自: 検査例。根拠: 1.4.5-E01–E03]

## 作るとき

- 見出し・ボタン・お知らせの文字を画像にしない。Web フォントと CSS で表現する。
- ロゴは画像でよいが、alt に組織名を入れる。
- グラフ・画面の写しは画像でよい。中の文字の要点は alt か本文に書く（1.1.1）。
- 写真とキャッチコピーを重ねたメイン画像は、可能なら文字を HTML にして CSS で重ねる。できないときは alt にコピーの文字を入れる。

## 確かめるとき

- **自動で確定する範囲**: 無し。手動で画像・用途・達成経路を照合した結果は確定できる。[根拠: 1.4.5-E01–E04]
- **残る**: 文字の入った画像を 1 つずつ、上の軸（文字の中身か、見た目か）と、同じ情報の可視テキスト・表示切替で決める。altが適切でも1.4.5の達成を代用しない。[根拠: 1.4.5-E01–E04]
- **言い切らない**: 画像を見ずに文字画像と決めない。上の線引きに当たるグラフ・画面の写し・ロゴ（社名だけの画像を含む）・資料の表紙を不適合にしない。alt の文面から文字画像と決めない。
