# 3.2.4 一貫した識別性

- 対象: 同じページ一式の中で繰り返す、同じ機能を持つ部品
- 要る材料: 名前・役割・場所・操作結果、可視ラベル・アイコン、文脈。先に [cross-page](../cross-page.ja.md) を読む
- 自動チェック: 専用チェックなし。`page-snapshot`の名前だけでは決まらない
- 原文確認日: 2026-11-02。WCAGは2024-12-12勧告、Understanding / Techniquesは随時更新のWCAG 2.2公開ページ。以下は引用ではなく要約。

## 根拠

### 3.2.4-E01 — 同じ行き先だけで同じ部品にしない

- **種別・出典:** [規範 — Consistent Identification](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#consistent-identification)、[Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/consistent-identification.html#intent)。
- **要約:** 同じ機能を持つ反復部品を対象とする。フッターの連絡リンクと本文中の連絡リンクは、同じ反復部品として認識されない例。ページ一式内の同一ページでの反復も含み得る。
- **適用条件・限界:** URL・ランドマークは候補整理の手掛かりであり、同一性を確定する条件ではない。機能のない内容や異なる機能を同じ識別にそろえることは、この基準の要求ではない。

### 3.2.4-E02 — 一貫性を文字列の完全一致に置き換えない

- **種別・出典:** [Technique — G197「Tests」](https://www.w3.org/WAI/WCAG22/Techniques/general/G197#tests)（Understandingでは1.1.1 / 4.1.2のラベル・名前・代替の十分な達成方法との併用）、[Failure — F31「Description」「Examples」](https://www.w3.org/WAI/WCAG22/Techniques/failures/F31#examples)。
- **要約:** G197の同じテキストは十分な方法の一つ。F31は「Search / Find」「Save page / Save」を失敗例に挙げる一方、「4ページへ / 5ページへ」の文脈に沿う番号差を認める。
- **適用条件・限界:** Techniqueの完全一致テストを規範の唯一の条件にしない。著者方針でF31の例と異なる扱いを採る場合は明記する。

### 3.2.4-E03 — 名前と見た目の両方で識別を確認する

- **種別・出典:** [Understanding — Examples 3–9](https://www.w3.org/WAI/WCAG22/Understanding/consistent-identification.html#examples)。
- **要約:** 文脈に合う「4ページ / 前のページ」、検索文字から虫眼鏡へのレスポンシブな変更は適合例。同じ名前でも保存アイコンがフロッピーとチェック印に変わる例は不適合。
- **適用条件・限界:** 見た目が同じでも名前が不一致なら別に確認する。ヘッダーとフッターの同じ検索部品も、場所だけで比較から除外しない。

## 線引き

- 段1では場所と役目から反復部品を組にし、リンク先・操作結果を照合する。本文とフッターの別の連絡リンク等は区別するが、場所が違うだけで反復部品を外さない。[独自: 候補を組にする方針。根拠: 3.2.4-E01・E03]
- 段2では同じ機能を再認識できるかを判断する。文脈に合う番号・現在位置の違いは認める。「お問い合わせ / Contact」のような理由のない呼び方の変更は別として扱い、略語など判断に足りない場合は文脈を確認する。[根拠: 3.2.4-E02–E03。日本語例と略語の扱いは独自方針]
- 主な語をそのまま含み説明や飾りが加わっただけなら、従来どおり同じ呼び方として扱う。F31の「Save page / Save」を失敗とする例より広く認める著者方針であり、公式の適合例とはしない。機能を区別する修飾や、識別に使うアイコンの変更まで単なる飾りとして免除しない。[独自: 表層的な文言差による誤判定を避ける方針。比較根拠: 3.2.4-E02–E03]
- 本文中のリンク・checkboxを初期のsnapshot比較から外す候補絞りは維持するが、WCAGの対象外とはしない。反復する同じ機能があれば画面・DOMで補う。`#`だけでリンクを同一視しない。[独自: 候補抽出の限界を明示する方針。根拠: 3.2.4-E01]
- ページ間の割当は [cross-page](../cross-page.ja.md) の多数派方針。同一ページ内の反復や視覚的な識別は別途確認し、抽出対象だけのPassを基準全体へ広げない。[独自: 検査方針。根拠: 3.2.4-E01・E03]

## 判断例

- **適合:** 「4ページへ / 5ページへ」や、文脈に沿った「4ページ / 前のページ」。同じ文字列に統一させない。[根拠: 3.2.4-E02–E03]
- **不適合となる食い違い:** 同じ検索に「Search / Find」を使う、同じ保存にフロッピーとチェック印を使う。名前一致だけで後者を見逃さない。[根拠: 3.2.4-E02–E03]
- **独自方針で指摘しない:** 同じ保存機能の「保存 / ページを保存」が、説明の追加だけに当たる場合。F31との相違を記録する。[独自: 上記の文言差の扱い。比較根拠: 3.2.4-E02]
- **対象外:** フッターの連絡リンクと本文中の別の連絡リンク、領収書印刷と請求書印刷のように異なる結果の機能。分かりやすい名前は別途推奨する。[根拠: 3.2.4-E01・E03]
- **要確認:** 名前のないcheckboxが各ページで同じ操作か不明。見た目・周辺説明・操作結果を取得する。[独自: 検査方針。根拠: 3.2.4-E01]

## 作るとき

- 同じ反復機能には共通の名前と視覚的な識別を使い、必要な文脈の違いだけ反映する。[根拠: 3.2.4-E02–E03]
- 異なる機能は名前を具体化することを推奨するが、同じアイコンを使うことだけで3.2.4不適合とはしない。[独自: 実装推奨。参考根拠: 3.2.4-E01]

## 確かめるとき

- **確定:** 同じ反復機能と確認できた部品の識別を比較した結果。[3.2.4-E01–E03]
- **残る:** 可視ラベル・アイコン、同一ページ内の反復、候補抽出から外れた入力欄、実際の操作結果。
- **言い切らない:** 同じURLや同じ名前だけで適否を決めない。多数派は公式の適合条件ではない。[根拠: 3.2.4-E01–E03。割当は独自方針]
