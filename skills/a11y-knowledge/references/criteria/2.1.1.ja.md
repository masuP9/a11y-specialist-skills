# 2.1.1 キーボード

- 対象: 操作部品と、その部品が提供する機能（複合部品・ダイアログ内部を含む）
- 要る材料: 要素・役割・状態、キーボードでの到達と実行、同じ機能の代替経路
- 自動チェック: keyboard-reachability-check、axeの `scrollable-region-focusable` 等。到達の検査と機能の実行を分ける
- 原文確認日: 2026-11-02。WCAGは2024-12-12勧告、Understanding / Techniques / APGは随時更新の公開ページ。以下は引用ではなく要約。

## 根拠

### 2.1.1-E01 — 個々の部品ではなく機能と入力の本質を確認する

- **種別・出典:** [規範 — Keyboard](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#keyboard)、[Understanding — Intent / Examples](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html#intent)。
- **要約:** 同じ又は同等の機能をキーボードで実行できれば、すべての可視部品をTabで到達可能にする必要はない。短時間の連打や長押し等、個々のキーの特定タイミングを必須にしない。
- **適用条件・限界:** 経路依存の例外は入力手法ではなく機能の本質で判断する。自由描画と、手書きで文字を入力する機能を区別する。ドラッグによる並べ替え・移動は経路依存とは限らず、キーボード代替が必要。

### 2.1.1-E02 — 到達と実行を機能ごとに検査する

- **種別・出典:** [Technique — G202「Tests」](https://www.w3.org/WAI/WCAG22/Techniques/general/G202#tests)（Sufficient）、[H91「Description / Tests」](https://www.w3.org/WAI/WCAG22/Techniques/html/H91#tests)（キーボード操作を提供するSufficient）。
- **要約:** 機能を列挙し、キーボードのみで実行できる経路を確認する。標準HTMLの部品・リンクはUAのキーボード操作を利用できる。
- **適用条件・限界:** 標準要素でもスクリプトが動作を妨げる場合は別。機能が同じ別部品やショートカットを代替にできるが、単にフォーカスが届くだけでは実行の証拠にならない。

### 2.1.1-E03 — ポインタ専用処理とフォーカス除去の実害を確認する

- **種別・出典:** [Failure — F54「Tests」](https://www.w3.org/WAI/WCAG22/Techniques/failures/F54.html#tests)、[F55「Tests」](https://www.w3.org/WAI/WCAG22/Techniques/failures/F55.html#tests)。
- **要約:** ポインタ用ハンドラしかなく機能をキーボードで使えない、又はフォーカス直後のblurで操作できない条件を確認する。
- **適用条件・限界:** click等のイベント名だけで失敗にしない。標準要素のキーボード起動や同等機能の別経路を確認する。キーボードトラップの2.1.2とは別に評価する。

### 2.1.1-E04 — APGの推奨とWCAGの必須条件を分ける

- **種別・出典:** [補助資料 — APG「Keyboard Navigation Inside Components」](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/#kbd_general_within)、[Understanding — Intent（キー操作の慣習）](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html#intent)。
- **要約:** roving tabindexやaria-activedescendantは部品内の移動方法。APGの慣習は実装・検査の手掛かりで、WCAGの唯一のキー割当ではない。
- **適用条件・限界:** Enterのみで実行できる自作ボタンをSpace非対応だけで2.1.1のFailにしない。独自キーの発見しやすさは改善点として分ける。

## 線引き

- focusableやtabindexだけで不適合にしない。負のtabindexでも矢印キーや同等機能の別経路があれば評価する。実際に機能がキーボードで使えず、例外でもなければ不適合。[根拠: 2.1.1-E01–E04]
- 標準要素（button / a[href] / input / select / textarea / summary）で既定の役割・フォーカス可能・tabindex無し又は0以上なら、標準操作を使えるものとして適合とする従来の判断を維持する。ただしキーのキャンセル、pointer専用処理、フォーカス除去等の具体的な兆候があれば実行を確認する。抽象的なスクリプトの可能性だけでは要確認へ戻さない。[独自: 標準要素の既定評価。参考根拠: 2.1.1-E02–E03]
- 自作部品・役割を変更した部品は、用意されたキー操作で機能を実行できるか確認する。非フォーカスの複合部品の入れ物は重複して未確認とせず内部を評価し、activedescendant方式や方式不明なら入れ物も確認する。dialogの入れ物が非フォーカスだけではFailにしない。[独自: 検査単位の方針。根拠: 2.1.1-E01・E04]
- disabledが効き、ブラウザが操作を止める要素は対象外。aria-disabledやa / div上のdisabledだけでは除外しない。利用可能な状態に変わる機能はその状態で評価する。[独自: 誰も操作できない状態の除外。参考根拠: 2.1.1-E01]
- keyboard-reachability-checkのreachedは到達の証拠。unreachableは同等機能の別経路を調べる候補で、not-evaluatedやabortedも残す。grid / treegrid、iframe・Shadow DOM、未展開の状態等は検査範囲外になり得る。[独自: ツールとの対応。実装確認: `packages/a11y-audit/src/playwright/runKeyboardReachabilityCheck.ts`、`src/utils/axe-format.ts`]

## 判断例

- **適合:** 検索ボタン自体はTabで届かないが、検索欄でEnterを押すと同じ検索を実行できる。[根拠: 2.1.1-E01–E02]
- **不適合:** 並べ替えがドラッグだけで、移動ボタン・キー操作等の代替もない。終点を変える機能を経路依存として免除しない。[根拠: 2.1.1-E01–E03]
- **例外で指摘しない:** 筆跡の経路そのものを描く自由描画。色選択・保存等の他の機能は引き続き評価する。[根拠: 2.1.1-E01。周辺機能の適用は著者の検査例]
- **指摘しない:** 自作ボタンがEnterで実行できるがSpaceでは動かない。APGとの差だけではFailにしない。[根拠: 2.1.1-E04]
- **要確認:** ツールで未到達だが、操作説明にショートカットがある。実行結果を確認する。[独自: 検査例。根拠: 2.1.1-E01–E02]

## 作るとき

- 標準要素と一般的なキー操作を優先し、同じ機能をキーボードで実行できるようにする。[根拠: 2.1.1-E02・E04]
- tabindexは0 / -1を基本とし、自作の複合部品はAPGのパターンを参考にする。正数のtabindexや慣習との差だけを2.1.1違反とする規則ではない。[独自: 実装推奨。参考根拠: 2.1.1-E04]

## 確かめるとき

- **確定:** 機能の実行結果と例外・代替経路の照合。到達だけの検査結果は到達まで。[2.1.1-E01–E04]
- **残る:** 実行・値変更・開閉、独自キー、未検査の状態と部品。
- **言い切らない:** 各部品のTab到達、EnterとSpaceの両方、APGとの完全一致を一律必須にしない。[根拠: 2.1.1-E01・E04]
