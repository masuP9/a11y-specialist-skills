# 2.1.1 キーボード

- 対象の部品: 操作できるもの全部（button、link、input、checkbox、radio、switch、combobox、slider、tab、menuitem、option、treeitem、gridcell、listbox、tablist、menu、tree、grid、modal）
- 要る材料: アクセシビリティツリー（tagName、role、focusable、tabindex、disabled）、実測（`@a11y-skills/audit` の keyboard-reachability-check）
- 自動チェック: keyboard-reachability-check、axe の `scrollable-region-focusable` など

## 根拠

- [Understanding 2.1.1](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html)（[日本語](https://waic.jp/translations/WCAG22/Understanding/keyboard.html)）
  - すべての機能がキーボードで操作できること。特定のキーの打ち方（タイミング）に依存しないこと。
  - 例外は、経路に依存する入力（手書き）だけ。
  - 「キーボードで届く」ことと「キーボードで動かせる」ことは別。Tab で届かなくても、矢印キー（ロービング tabindex、`aria-activedescendant`）で操作できる設計がある。
- [G202: すべての機能にキーボード操作](https://www.w3.org/WAI/WCAG22/Techniques/general/G202)、[F54: ポインタ専用のイベント](https://www.w3.org/WAI/WCAG22/Techniques/failures/F54)、[F55: フォーカスを受けた瞬間に外す](https://www.w3.org/WAI/WCAG22/Techniques/failures/F55)、[APG のキーボード操作の設計パターン](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/)

## 線引き

- 止まった画面の情報（ツリー・HTML）から、キーボードで届かない・操作できないとは言い切れない。`focusable` や `tabindex` だけを理由に不適合にしない。[解説書]（ロービング tabindex、activedescendant）
- HTML 標準の要素（button / a[href] / input / select / textarea / summary）で、role がその要素の既定のまま、フォーカスでき、tabindex が無いか 0 以上なら、ブラウザ標準のキーボード操作が効くので適合。[解説書]
- tabindex が負の数の要素は、Tab では届かないが矢印キーで操作できることがある。要確認（実際のキー操作で確かめる）。[解説書]
- div や span に role を付けた自作の部品や、標準の要素の role を変えたもの（tab / menuitem / option / treeitem / gridcell）は、フォーカスできても Enter・スペース・矢印キーで動くかが情報から分からない。要確認。[独自]
- 複合部品の入れ物（listbox / tablist / menu / tree / grid）がフォーカスを受けないと確認できた場合は、入れ物だけの未確認の判定を重ねず、中の項目でキーボード操作を確かめる。入れ物自体がフォーカスを受ける方式（aria-activedescendant など）やフォーカスできるか不明な場合は、入れ物も確認対象に残す。実際のキー操作の記録があれば、入れ物についての判定の根拠として残す。[独自]
- ダイアログは、入れ物自体がフォーカスできないことを理由に不適合にせず、中の項目の操作を確かめる。[解説書]（APG）
- ブラウザが操作を止めている無効な要素（disabled が効く要素に disabled 属性があり、ブラウザもフォーカスできないと判定したもの）には 2.1.1 を問わない。誰も操作できないので、キーボードだけの問題にならない。`aria-disabled="true"` は対象外にしない（ブラウザは操作を止めず、マウスでだけ押せる不適合が隠れうる）。a や div の disabled は効かないので対象外にしない。[独自]
- 実測（keyboard-reachability-check）で届いた要素は「届く」まで。動かせるかは別。届かない要素は、別の経路（矢印キー）がありうるので要確認。[独自]

## 作るとき

- 操作部品は標準の要素（button、a[href]、input、select）で作る。div に click を付けない。
- 自作の部品（tab、menu、listbox、tree、grid）は APG のキーボード操作のパターンに従う。Tab で入れ物に入り、矢印キーで中を移動、Enter / スペースで実行。
- `tabindex` は 0 か -1 だけ使う。正の数で順番を作らない。
- マウスでだけ動く操作（hover で出るメニュー、ドラッグ）には、キーボードで同じことができる経路を用意する。
- `aria-disabled="true"` の部品は、押せないように見せるだけでなく、押したときに何も起きないようにする。

## 確かめるとき

- **確定**: keyboard-trap-check の違反（2.1.2）。keyboard-reachability-check で届いた要素は「届く」ことが確定（動かせるかは別）。
- **残る**: 自作の部品が Enter・スペース・矢印キーで動くか。届かなかった要素に別の経路があるか。実際にキーを押して確かめる。
- **言い切らない**: tabindex や focusable だけで不適合にしない。disabled の要素を不適合にしない。標準の要素でない部品を、情報だけで適合にしない。
