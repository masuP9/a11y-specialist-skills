# 1.3.1 情報及び関係性

- 対象の部品: 入力欄（input、checkbox、radio、switch、combobox、listbox、slider）、ランドマーク、navigation、form、table、heading、list、modal など多数
- 要る材料: アクセシビリティツリー・DOM（名前の出どころ、親子関係）、画面や音で伝える構造・関係
- 自動チェック: axeの `list` / `listitem`、`th-has-data-cells` 等は部分検査。`label` と `landmark-*` の分類は下記参照
- 原文確認日: 2026-11-02。WCAGは2024-12-12勧告、WAI-ARIA 1.2は2023-06-06勧告、Understanding / Techniquesは随時更新の公開ページ。HTML中心の確認であり、全メディア・文書形式の網羅ではない。以下は引用ではなく要約。

## 根拠

### 1.3.1-E01 — 提示で伝える関係を具体的に照合する

- **種別・出典:** [規範 — Info and Relationships](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#info-and-relationships)、[Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html#intent)。
- **要約:** 見た目又は音で伝える構造・関係が、プログラムで取得できるか、テキストとして提供されるかを確認する。存在しない関係を追加する要求ではない。
- **適用条件・限界:** 「必須は＊」の説明等、関係を文字で提供する方法もある。単なる装飾をすべて構造とみなさず、何の情報が失われるかを示す。

### 1.3.1-E02 — 可視ラベルとの関係と名前の有無を分ける

- **種別・出典:** [Technique — H44「Tests」](https://www.w3.org/WAI/WCAG22/Techniques/html/H44#tests)、[ARIA16「Tests」](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA16#tests)（関係を特定するSufficient）。[Failure — F68](https://www.w3.org/WAI/WCAG22/Techniques/failures/F68.html#tests)は現在4.1.2に対応。
- **要約:** 可視ラベルと入力欄の関係を、labelやARIA等の実装・名前の出どころから確認する。H44・ARIA16を唯一の方法にはしない。
- **適用条件・限界:** F68や名前の検査を1.3.1へ直接転記しない。名前があるだけで、画面に提示されたすべての関係の一致が保証されるわけではない。

### 1.3.1-E03 — 見出し・リスト・入力グループの意味を確かめる

- **種別・出典:** [Technique — H42「Description / Tests」](https://www.w3.org/WAI/WCAG22/Techniques/html/H42#tests)、[H48「Description / Tests」](https://www.w3.org/WAI/WCAG22/Techniques/html/H48#tests)、[H71「Description / Tests」](https://www.w3.org/WAI/WCAG22/Techniques/html/H71#tests)（構造・関係を特定するSufficient）。
- **要約:** 見出し、リスト、共通説明を持つ入力グループとして伝える意味を実装と照合する。fieldset / legendはグループの説明を渡す方法の一つ。個別ラベルと明確な説明だけで選択肢が十分に分かる場合は、H71もfieldset / legendを必須にしていない。
- **適用条件・限界:** 文中のコンマ区切りの列挙にlistを一律必須にしない。特定の見出し番号やfieldsetの欠落だけでFailにせず、失われた階層・関係を示す。

### 1.3.1-E04 — 表の関連付けとレイアウト目的を区別する

- **種別・出典:** [Technique — H63「Description / Tests」](https://www.w3.org/WAI/WCAG22/Techniques/html/H63#tests)（Sufficient）、[Failure — F46「Description / Tests」](https://www.w3.org/WAI/WCAG22/Techniques/failures/F46#tests)。
- **要約:** データセルから必要な見出しが分かるかを確かめる。最初の行・列が見出しの単純な表ではthだけで足りる。レイアウト表にデータ表の意味を誤って付ける場合は区別する。
- **適用条件・限界:** scopeをすべての表で必須にしない。レイアウト表の使用だけをWCAG違反にせず、誤った構造や読み順等の実際の問題を確認する。

### 1.3.1-E05 — 領域の意味とARIAの名前要件を区別する

- **種別・出典:** [Technique — ARIA11「Description / Tests」](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA11#tests)（Sufficient）、[技術仕様 — WAI-ARIA 1.2「region」](https://www.w3.org/TR/2023/REC-wai-aria-1.2-20230606/#region)。
- **要約:** ランドマークは領域を識別する手段。明示したregionには内容の目的を表す名前が必要。名前のある領域は、その名前と提示内容の対応も見る。
- **適用条件・限界:** ARIAの実装要件とWCAGの違反条件を同一視しない。main等の名前欠落、同種ランドマークの重複だけで一律に1.3.1をFailにしない。

## 線引き

### 入力欄とラベル

- 画面に見えるラベルの文字があるのに、プログラムで結び付いていなければ不適合。[根拠: 1.3.1-E01–E02]
- `label for` / ラベルで包む / `aria-labelledby` で関係が正しく結び付いていれば、その関係は適合。[根拠: 1.3.1-E02]
- 名前の無い入力欄の近くにラベルになる文字が見えるなら、結び付いていないと判断して不適合にする。結び付いていればその文字が名前になるので、対象欄の計算済みの名前が無いと確認できたことが関係の欠落の根拠になる（「結び付きが分からない」として保留にしない）。[独自: 著者の検査・報告方針。参考根拠: 1.3.1-E01–E02]
- ラベルになる文字が画面に無い（placeholder だけ）なら、結び付けるべき外部ラベルとの関係が無いので、ラベル関係の欠落としては1.3.1で指摘しない。他のグループ化等の関係は別に評価する。ラベルが無いこと・placeholder だけであることは 3.3.2 で扱う。[独自: 著者の検査・報告方針。参考根拠: 1.3.1-E01–E02]
- placeholder から来た名前でも名前は名前。1.3.1 / 4.1.2 の不適合の理由にしない。[独自: 著者の検査・報告方針。参考根拠: 1.3.1-E01–E02]

### ランドマーク

- main / navigation / complementary / banner / contentinfo / search は名前が無くても原則として適合。名前が無いことだけを理由に不適合にしない。[根拠: 1.3.1-E05]
- `<section>` に名前が無ければ region ランドマークにならない単なる section なので、名前が無いことは不適合の理由にならない。`role="region"` を明示したら名前が要る。[根拠: 1.3.1-E05。名前必須はARIAの要件であり、1.3.1のFailには失われた関係を示す]
- 名前があるときは、領域内の見出しや領域の意味と合っているかを見る（見出しが「請求情報」なのに `aria-labelledby` が「アカウント設定」を指す）。確かめられなければ推測で不適合にしない。[独自: 著者の検査・報告方針。参考根拠: 1.3.1-E01・E05]
- 同じ種類のランドマークが複数あるときに区別する名前があるかは、ページ全体を見ないと分からない。1 つの要素の情報だけから不適合にしない。[独自: 著者の検査・報告方針。参考根拠: 1.3.1-E01・E05]

### フォーム（入れ物）

- フォームの 1.3.1 は、フォームという入れ物の構造（グループ化、見出しとの関係）で見る。中の入力欄の問題（名前が無い、ラベルが結び付いていない）は、その入力欄の 1.3.1 / 4.1.2 と、フォームの 3.3.2 で扱い、フォームの 1.3.1 を重ねて不適合にしない（二重に数えない）。[独自: 著者の検査・報告方針。参考根拠: 1.3.1-E01–E02]

### ダイアログ

- dialog / alertdialog 自身の名前の欠落は、[4.1.2の独自方針](./4.1.2.ja.md) に従いベストプラクティスの改善候補とする。1.3.1の不適合へ振り替えない。別の構造・関係の問題を1.3.1で報告するときは、その根拠を具体的に示す。[独自: 著者の検査・報告方針。参考根拠: 1.3.1-E01–E02]

## 判断例

- **適合:** 単純なデータ表の先頭行にthがあり、各データと見出しが対応する。scopeがないだけでは指摘しない。[根拠: 1.3.1-E04]
- **不適合:** 見た目では項目の見出しだが、実装は太字の段落のみで、見出しとしての意味が他の方法でも提供されない。[根拠: 1.3.1-E01・E03]
- **指摘しない:** 本文中で「赤、青、緑」と列挙しているだけ。ulへ変更することを必須にしない。[根拠: 1.3.1-E03]
- **独自方針を維持:** placeholderのみの欄をラベル関係の欠落でFailにせず3.3.2で評価する。dialog自体の名前欠落も1.3.1へ振り替えない。[独自: 既存の基準間分担。参考根拠: 1.3.1-E01–E02]
- **要確認:** ツリーには見出しがあるが画面を取得できず、見た目の階層との一致が不明。画面とDOMを照合する。[独自: 検査方針。根拠: 1.3.1-E01・E03]

## 作るとき

- 見えるラベルは `<label for>` で結び付ける。見た目の都合で `<label>` を置けないときは `aria-labelledby` で見えている文字を指す。
- 見た目でグループに見える入力欄（住所の 3 つの欄、ラジオの並び）は `<fieldset>` と `<legend>` でまとめる。
- 見出しは見た目の階層どおりに `h1`〜`h6` を付ける。見出しに見える太字の段落を作らない。
- 同じ種類のランドマークを 2 つ以上置くなら、`aria-label` か `aria-labelledby` で区別する名前を付ける。
- `<section>` をランドマークにしたいときだけ名前を付ける。名前の無い section はランドマークにならない。
- 表の見出しは `<th>`（と必要なら `scope` 等）で表す。レイアウトにはCSSを推奨するが、表の使用だけでFailにしない。[根拠: 1.3.1-E04]

## 確かめるとき

- **確定:** 提示された関係と実装の欠落・誤りを照合した結果。axeのlist / listitem・th-has-data-cells等も対象ノードと関係を確認する。[1.3.1-E01–E04]
- **残る:** 見出し階層、表の見出し対応、入力グループ、領域名と内容。ツリーだけでは可視・聴覚的な提示との一致は確定しない。
- **言い切らない:** axe-core 4.14.0の `label` は4.1.2の名前検査でplaceholderでも通る。`landmark-*` はbest-practice分類。これらを1.3.1の確定違反へ直接転記しない。[独自: ツールとの対応。実装確認: `node_modules/axe-core/axe.js`。根拠: 1.3.1-E01–E02・E05]
