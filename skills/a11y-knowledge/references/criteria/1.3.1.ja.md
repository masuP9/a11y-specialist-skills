# 1.3.1 情報及び関係性

- 対象の部品: 入力欄（input、checkbox、radio、switch、combobox、listbox、slider）、ランドマーク、navigation、form、table、heading、list、modal など多数
- 要る材料: アクセシビリティツリー（名前の出どころ、親子関係）、画面に見えるラベル・見出し
- 自動チェック: axe の `label`、`list`、`th-has-data-cells`、`landmark-*` など

## 根拠

- [Understanding 1.3.1](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html)（[日本語](https://waic.jp/translations/WCAG22/Understanding/info-and-relationships.html)）
  - 判断の軸は「見た目で伝えている構造・関係が、プログラムでも判断できるか（または文字で書かれているか）」。見た目に無い関係まで作ることは求めない。
  - 「プログラムによる解釈が可能」は、支援技術が読み取れる形。名前の結び付け、見出しの階層、表の見出しセル、リストのマークアップ。
- [H44: label 要素](https://www.w3.org/WAI/WCAG22/Techniques/html/H44)、[ARIA16: aria-labelledby](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA16)、[ARIA11: ランドマーク](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA11)、[F68: ラベルが結び付いていない](https://www.w3.org/WAI/WCAG22/Techniques/failures/F68)

## 線引き

### 入力欄とラベル

- 画面に見えるラベルの文字があるのに、プログラムで結び付いていなければ不適合。[解説書]（F68）
- `label for` / ラベルで包む / `aria-labelledby` で結び付いていれば適合。[解説書]
- 名前の無い入力欄の近くにラベルになる文字が見えるなら、結び付いていないと判断して不適合にする。結び付いていればその文字が名前になるので、名前が無いこと自体が結び付いていない根拠になる（「結び付きが分からない」として保留にしない）。[独自]
- ラベルになる文字が画面に無い（placeholder だけ）なら、結び付けるべき関係が無いので 1.3.1 の対象外。ラベルが無いこと・placeholder だけであることは 3.3.2 で扱う。[独自]
- placeholder から来た名前でも名前は名前。1.3.1 / 4.1.2 の不適合の理由にしない。[独自]

### ランドマーク

- main / navigation / complementary / banner / contentinfo / search は名前が無くても原則として適合。名前が無いことだけを理由に不適合にしない。[解説書]
- `<section>` に名前が無ければ region ランドマークにならない単なる section なので、名前が無いことは不適合の理由にならない。`role="region"` を明示したら名前が要る。[解説書]（region は名前があって初めてランドマーク）
- 名前があるときは、領域内の見出しや領域の意味と合っているかを見る（見出しが「請求情報」なのに `aria-labelledby` が「アカウント設定」を指す）。確かめられなければ推測で不適合にしない。[独自]
- 同じ種類のランドマークが複数あるときに区別する名前があるかは、ページ全体を見ないと分からない。1 つの要素の情報だけから不適合にしない。[独自]

### フォーム（入れ物）

- フォームの 1.3.1 は、フォームという入れ物の構造（グループ化、見出しとの関係）で見る。中の入力欄の問題（名前が無い、ラベルが結び付いていない）は、その入力欄の 1.3.1 / 4.1.2 と、フォームの 3.3.2 で扱い、フォームの 1.3.1 を重ねて不適合にしない（二重に数えない）。[独自]

### ダイアログ

- dialog / alertdialog の名前は 1.3.1（と 2.4.6）の話として付ける。4.1.2 では問わない（[4.1.2](./4.1.2.ja.md)）。[独自]

## 作るとき

- 見えるラベルは `<label for>` で結び付ける。見た目の都合で `<label>` を置けないときは `aria-labelledby` で見えている文字を指す。
- 見た目でグループに見える入力欄（住所の 3 つの欄、ラジオの並び）は `<fieldset>` と `<legend>` でまとめる。
- 見出しは見た目の階層どおりに `h1`〜`h6` を付ける。見出しに見える太字の段落を作らない。
- 同じ種類のランドマークを 2 つ以上置くなら、`aria-label` か `aria-labelledby` で区別する名前を付ける。
- `<section>` をランドマークにしたいときだけ名前を付ける。名前の無い section はランドマークにならない。
- 表の見出しは `<th>`（と必要なら `scope`）で表す。レイアウトのための表を作らない。

## 確かめるとき

- **確定**: axe の `label`（見えるラベルと結び付いていない入力欄）、`list` / `listitem`、`th-has-data-cells` などの違反は不適合。
- **残る**: 見出しの階層が見た目と合っているか、グループ化が見た目と合っているか、ランドマークの名前が中身と合っているか。ページ全体を見て決める。
- **言い切らない**: ランドマークに名前が無いことだけで不適合にしない。placeholder だけの欄を 1.3.1 で不適合にしない（3.3.2 で見る）。
