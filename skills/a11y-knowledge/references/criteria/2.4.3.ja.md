# 2.4.3 フォーカス順序

- 対象: ページ全体（部品ごとには付けない）
- 要る材料: 実測（`@a11y-skills/audit` の focus-indicator-check の `tabOrder`、focus-order-check）。各要素の Tab の順と位置
- 自動チェック: focus-order-check、axe の `tabindex`（正の数）

## 根拠

- [Understanding 2.4.3](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html)（[日本語](https://waic.jp/translations/WCAG22/Understanding/focus-order.html)）
  - 要件は「意味と操作性を保つ順序」であって、「見た目の順と一致する順序」ではない。見た目と違っても意味が通れば適合。
  - 順序が 1 つに決まらない内容もある（複数の妥当な順序）。
  - ダイアログを開いたらフォーカスをダイアログに移し、閉じたら元に戻すことも 2.4.3 の範囲。
- [G59: ソース順と見た目の順を合わせる](https://www.w3.org/WAI/WCAG22/Techniques/general/G59)、[F44: tabindex で意味を損なう順にする](https://www.w3.org/WAI/WCAG22/Techniques/failures/F44)、[F85: ダイアログにフォーカスを移さない](https://www.w3.org/WAI/WCAG22/Techniques/failures/F85)

## 線引き

- Tab で移った順を、読む順（上から下、左から右）と見比べる。読む順と大きく食い違う移動（本文の途中からページ下部へ飛び、また戻る）が意味や操作を損なうと読み取れれば不適合。[解説書]
- 食い違いが無く、実測が最後まで終わり、飛ばした要素が無く、操作できる要素が 1 つ以上あれば適合。判断できなければ要確認。[独自]
- 固定表示（fixed / sticky）の要素（ヘッダー、下に貼り付くバナー）は、位置がスクロールに左右される。名前や selector から固定表示らしいと読める要素への移動・からの移動は、位置の食い違いだけを理由に不適合にしない。[独自]
- 正の `tabindex` は順序を壊しやすいが、それだけで不適合にしない（結果の順序で決める）。[解説書]
- 実測が途中で止まった・要素を飛ばした・順を切り詰めた（上限で切れた）ときは適合を付けない。[独自]

## 作るとき

- DOM の順を見た目の順に合わせる。CSS の `order` や `flex-direction: row-reverse` で見た目だけ入れ替えない。
- `tabindex` に正の数を使わない。
- ダイアログを開いたらフォーカスを中に移し、閉じたら開いたボタンに戻す。
- 画面に出ていない要素（閉じたメニューの中）はフォーカスできないようにする（`inert`、`display: none`）。

## 確かめるとき

- **確定**: 無し。
- **残る**: `tabOrder` の順と位置を読み、食い違いが意味や操作を損なうかを決める。
- **言い切らない**: 見た目と順が違うだけで不適合にしない。途中で止まった実測で適合にしない。
