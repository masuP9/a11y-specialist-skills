# 3.3.2 Labels or Instructions

- Components in scope: form (the input fields inside, taken together), input, checkbox, radio, switch, combobox, listbox, slider
- Inputs needed: the input field's name and the source of the name (label / aria-label / placeholder)
- Automated checks: axe `label` (presence of a name. Passes even with only a placeholder)

## Rationale

- [Understanding 3.3.2](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html) ([Japanese translation](https://waic.jp/translations/WCAG22/Understanding/labels-or-instructions.html))
  - When input is requested, there must be a label or instructions. What to enter, the format, and whether it is required must be understandable.
  - That the label is "programmatically associated" is the range of 1.3.1 / 4.1.2. 3.3.2 requires that a visible label or instructions exist.
  - A placeholder disappears when typing, so it does not serve as a permanent label.
- [G131: descriptive labels](https://www.w3.org/WAI/WCAG22/Techniques/general/G131), [G162: label position](https://www.w3.org/WAI/WCAG22/Techniques/general/G162), [H90: indicating required](https://www.w3.org/WAI/WCAG22/Techniques/html/H90), [F82: not indicating the required format](https://www.w3.org/WAI/WCAG22/Techniques/failures/F82)

## Judgment lines

- If there is an input field with no name, or whose name comes only from the placeholder (it disappears when typing, so it does not serve as a permanent label), non-conformant. [Understanding]
- A placeholder-only label is handled here. Do not use it as a reason for non-conformance under 1.3.1 / 4.1.2 (a name that comes from the placeholder is still a name). [Our interpretation] (division)
- 3.3.2 for a form looks at the labels of the input fields inside, taken together. If the information of the inner input fields is not visible, needs review. [Our interpretation]
- If a field that needs a format specification (how to write a date, whether to use hyphens) has no instructions, non-conformant. [Understanding] (F82)

## When building

- Give every input field a visible `<label>`. Use the placeholder as a hint, not as a substitute for the label.
- For fields with a fixed format (date, phone number), write an example in the label or instructions.
- Indicate required fields with the word "required" or a symbol, and explain the symbol's meaning at the top of the form.
- If hiding a label visually, use a visually hidden `<label>` rather than `aria-label` (so the name can be spoken with voice input).

## When checking

- **Settled**: violations of axe `label` (no name) are non-conformant. A pass is not counted as conformant (it passes even with only a placeholder).
- **Remains**: whether there are fields whose name comes only from the placeholder. Whether fields that need format instructions have them.
- **Do not assert**: do not mark conformant solely because a name exists.
