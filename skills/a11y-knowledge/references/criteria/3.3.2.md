# 3.3.2 Labels or Instructions

- Components in scope: form, input, checkbox, radio, switch, combobox, listbox, and slider accepting data entry
- Inputs needed: visible labels and instructions, presentation during input, accepted formats, and name sources
- Automated checks: axe `label` supplies evidence about name implementation; it does not settle 3.3.2
- Sources checked: 2026-11-02. WCAG is the 2024-12-12 Recommendation; Understanding / Techniques are living WCAG 2.2 public pages. The following are summaries, not quotations.

## Rationale

### 3.3.2-E01 — Separate computed names from presentation to users

- **Type / source:** [Normative — Labels or Instructions](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#labels-or-instructions), [Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html#intent).
- **Summary:** Optional inputs are included. Assess labels or instructions presented to all users separately from programmatic associations (1.3.1) and accessible names (4.1.2). Links and expand/collapse actions unrelated to data entry are outside scope.
- **Conditions / limits:** A missing name alone does not fail this criterion. Conversely, `aria-label` or a visually hidden label alone cannot replace visible instructions.

### 3.3.2-E02 — Inspect actual labels, including images and context

- **Type / source:** [Understanding — Examples](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html#examples), [Technique — G131, Description](https://www.w3.org/WAI/WCAG22/Techniques/general/G131#description) (Sufficient for 3.3.2 using a more specific technique).
- **Summary:** Images understood by the intended audience, such as a magnifying glass for search, can label inputs. Check each field's meaning without mechanically demanding separate visible text for every field.
- **Conditions / limits:** For segmented inputs, check group instructions together with identification of each field. Evaluate label clarity and descriptiveness separately under 2.4.6 as well.

### 3.3.2-E03 — Provide required-field and format cues as needed

- **Type / source:** [Technique — H90, Description](https://www.w3.org/WAI/WCAG22/Techniques/html/H90#description) (Sufficient with G131), [Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html#intent).
- **Summary:** Required status can be included in labels or legends as text or symbols, explaining symbols before their first use. Provide necessary instructions for unusual formats and similar constraints. Long instructions may be presented on focus.
- **Conditions / limits:** Do not require a format example for every field. Compare instructions with the values actually accepted.

### 3.3.2-E04 — Do not generalize F82 to all missing format instructions

- **Type / source:** [Failure — F82, Description and Tests](https://www.w3.org/WAI/WCAG22/Techniques/failures/F82#tests).
- **Summary:** This addresses segmented phone fields indicated only by parentheses or hyphens, without visible labels or input instructions.
- **Conditions / limits:** Check the condition where both F82 tests are false. Do not cite it as the source for general missing date-format or hyphen instructions.

## Judgment lines

- Visible labels or instructions with missing name associations can satisfy the presentation requirement of 3.3.2. Evaluate 1.3.1 / 4.1.2 separately. [Evidence: 3.3.2-E01]
- This knowledge base treats a placeholder-only field that loses its label or instructions during input as a 3.3.2 failure. Do not apply this judgment when other visible labels or instructions exist, or when the label remains after input. [Our interpretation: author policy prioritizing identification during input. Supporting evidence: 3.3.2-E01–E02]
- Do not fail 1.3.1 / 4.1.2 solely because a name comes from a placeholder. This does not exempt other relationship or name defects. [Our interpretation: division between criteria. Supporting evidence: 3.3.2-E01]
- axe-core 4.14.0 maps `label` to `wcag412` and includes a non-empty placeholder among its passing routes. Do not transfer its violations directly to 3.3.2 failures or treat its passes as 3.3.2 conformance. [Our interpretation: tool mapping. Implementation checked: the `label` rule in `node_modules/axe-core/axe.js`. Supporting evidence: 3.3.2-E01]

## Judgment examples

- **Conformant:** A magnifying-glass image label communicates a search field's purpose, and the field accepts free input. Do not flag solely for missing separate visible text or format examples. [Evidence: 3.3.2-E02–E03]
- **Non-conformant:** A field accepts only a custom membership-number format without necessary instructions. Segmented phone fields with only parentheses and hyphens, without labels or instructions, meet F82's conditions. [Evidence: 3.3.2-E03–E04]
- **Conforming example:** The segmented phone-number example in Understanding combines a visible “Phone number” group label with titles identifying each of the three fields. Distinguish this from F82 without a group label or instructions; do not flag solely because each field lacks its own visible label. [Evidence: 3.3.2-E02–E04]
- **Needs review:** The accessibility tree contains a name but does not establish whether a visible label exists. Obtain the screen and presentation after input. [Our interpretation: inspection policy. Evidence: 3.3.2-E01]

## When building

- Use visible labels for ordinary inputs and placeholders for supplemental hints. Switching to a visually hidden label alone does not fix missing visible instructions. [Our interpretation: author implementation policy. Supporting evidence: 3.3.2-E01–E02]
- Provide required-field indicators and necessary format instructions, explaining symbols before first use. [Evidence: 3.3.2-E03]

## When checking

- **Settled:** Results of manually comparing presentation with input requirements. axe name checks alone do not settle this criterion. [3.3.2-E01–E04]
- **Remains:** Optional fields, options, groups, labels during input, and necessary format and required-field instructions.
- **Do not assert:** That name presence or absence establishes visible label presence or absence. [Evidence: 3.3.2-E01]
