# 3.3.3 Error Suggestion

- Components in scope: form, input (automatically detected input errors)
- Inputs needed: error state, accepted formats and values, correction guidance, and reasons for exceptions
- Automated checks: no dedicated check
- Sources checked: 2026-11-02. WCAG is the 2024-12-12 Recommendation; Understanding / Techniques are living WCAG 2.2 public pages. The following are summaries, not quotations.

## Rationale

### 3.3.3-E01 — Check known corrections and exceptions

- **Type / source:** [Normative — Error Suggestion](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#error-suggestion), [Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/error-suggestion.html#intent).
- **Summary:** Provide known correction suggestions for automatically detected input errors, unless doing so would jeopardize security or the purpose of the content.
- **Conditions / limits:** Guessing correct personal information is not required. Distinguish explaining known formats or allowed values from disclosing the answer itself. Check 3.3.1 error identification separately.

### 3.3.3-E02 — Match suggestions to formats and allowed values

- **Type / source:** [Technique — G85, Description](https://www.w3.org/WAI/WCAG22/Techniques/general/G85#description), [G84, Description](https://www.w3.org/WAI/WCAG22/Techniques/general/G84#description) (both Sufficient).
- **Summary:** For format errors, provide descriptions or examples of the correct format. For restricted values, provide allowed values or similar candidates.
- **Conditions / limits:** Notification alone may not enable correction. Conversely, do not mechanically demand a separate message: consider existing instructions when determining what users can correct.

### 3.3.3-E03 — Do not restrict placement or delivery methods

- **Type / source:** [Technique — G177, Description and Tests](https://www.w3.org/WAI/WCAG22/Techniques/general/G177#tests) (Sufficient), [Understanding — Examples](https://www.w3.org/WAI/WCAG22/Understanding/error-suggestion.html#examples).
- **Summary:** Suggestions may appear beside a field or be reached through a nearby link to a candidate list. Examples include a list of month names or the corresponding month name when a number was entered.
- **Conditions / limits:** Automatically choosing one correct answer is not always necessary. Check whether users can find and choose suggestions.

## Judgment lines

- “Invalid value” alone fails when a correction is known and no exception applies. If validation rules or responses are unavailable, check known formats and candidates against actual presentation. [Evidence: 3.3.3-E01–E03]
- Treat withholding the correct secret used for authentication as an exception. Do not exempt all suggestions merely because the field is a password field: provide safe correction guidance such as public length requirements during registration. [Our interpretation: applying the normative exception per function. Evidence: 3.3.3-E01]
- Evaluate native validation messages by their content. Browser-generated messages are neither automatically conformant nor automatically failures. [Evidence: 3.3.3-E01–E02]

## Judgment examples

- **Conformant:** A postal code with the wrong length produces “Enter the postal code as 7 digits.” No separate candidate list is needed. [Evidence: 3.3.3-E02]
- **Conformant:** An empty, clearly identified name field produces “Enter your name.” Suggesting the user's actual name is unnecessary. [Our interpretation: application of known correction guidance. Evidence: 3.3.3-E01–E02]
- **Non-conformant:** Accepted prefecture names are known, but a spelling error produces only “Error,” with no candidates or route to correction guidance. [Evidence: 3.3.3-E02–E03]
- **Do not flag under the exception:** Withholding the correct secret password during login. Do not extend this exception to withholding required length when a new registration password is too short. [Our interpretation: application of the exception. Evidence: 3.3.3-E01]
- **Needs review:** Only a “Check your input” response is available; accepted values and surrounding instructions have not been obtained. Obtain them to assess correction guidance. [Our interpretation: inspection policy. Evidence: 3.3.3-E01–E02]

## When building

- Present the problem and correction together. For multiple candidates, offer a selection or a link to a list. [Evidence: 3.3.3-E02–E03]
- Explain constraints that can be disclosed without revealing secrets. Record the function and security or purpose affected by an exception. [Our interpretation: implementation and reporting policy. Evidence: 3.3.3-E01]

## When checking

- **Settled:** Results of comparing actual errors, known corrections, presentation, and exceptions. [3.3.3-E01–E03]
- **Remains:** Validation branches such as missing input, format errors, and disallowed values; server responses; destinations of suggestion links.
- **Do not assert:** Conformance or failure from the initial screen alone, or conformance of correction suggestions merely because an error description exists. [Our interpretation: inspection policy]
