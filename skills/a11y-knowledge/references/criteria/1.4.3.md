# 1.4.3 Contrast (Minimum)

- Scope: The visual presentation of text and images of text, including placeholder text and text shown on hover or focus
- Materials: Text and background colors (values obtained from the user agent or styles), font size and weight, background images, gradients and overlaps, the presentation in each state, the available themes, and whether an exception applies (inactive, decorative, part of a picture, logo)
- Automated check: axe-core 4.14.0 `color-contrast` (`wcag2aa` / `wcag143`; runs under audit's default WCAG tags). It only looks at text in the initial presentation. `@a11y-skills/audit` has no check dedicated to 1.4.3
- Sources checked: 2026-11-10. WCAG: Recommendation of 2024-12-12. Understanding updated 2026-10-04; G18, G145, and G148 updated 2026-09-06; G174 updated 2026-06-28; F24 updated 2026-10-04; F83 updated 2026-03-09 (living public pages). ACT rule afw4f7 is approved, updated 2023-08-30 (a newer proposed version exists separately). The following are summaries, not quotations.

## Evidence

### 1.4.3-E01 — Decide the scope and exceptions

- **Type / source:** [Normative — Contrast (Minimum)](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#contrast-minimum), [Term — pure decoration](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#dfn-pure-decoration), [Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html#intent), [Understanding — Logos](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html#logos), [Understanding — Inactive User Interface Components](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html#inactive-controls).
- **Summary:** Text and images of text need 4.5:1, large text 3:1. Text that is part of an inactive component, purely decorative, not visible to anyone, part of a picture containing significant other visual content, or part of a logo or brand name has no requirement. An inactive component is visible but not currently operable. Decorative text can be rearranged or substituted without changing its purpose. Beyond logos, text made low contrast because of brand guidelines is not exempt. A logo that normally has sufficient contrast but is shown faint as an author choice (a row of logos that darken only on hover) is not exempt either.
- **Conditions / limits:** Heavily stylized text that acts as a graphic, and characters used as symbols (`X` for close, `>` for an arrow), are non-text content and are assessed under [1.4.11](./1.4.11.md). Choosing a sufficient-contrast variant for a logo that acts as a component is encouraged by Understanding, not required.

### 1.4.3-E02 — The large-text line

- **Type / source:** [Term — large scale](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#dfn-large-scale), [Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html#intent).
- **Summary:** At least 18 point, or 14 point bold, or the equivalent size for CJK fonts. Since 1pt = 1.333px, these are about 24px and 18.5px. The size is obtained from the user agent, or calculated from font metrics the way user agents do. Resizing by the user is not included.
- **Conditions / limits:** The "equivalent size" for CJK is not defined. A note says fonts with extraordinarily thin strokes or unfamiliar letter forms are harder to read at low contrast, but the thresholds do not change.

### 1.4.3-E03 — Which colors to compare and how to treat the ratio

- **Type / source:** [Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html#intent), [Term — contrast ratio](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#dfn-contrast-ratio), [Technique — G18 "Tests"](https://www.w3.org/WAI/WCAG22/Techniques/general/G18#tests) (Sufficient).
- **Summary:** Do not round the ratio (4.499:1 does not meet 4.5:1). Use the foreground and background colors obtained from the user agent or styles, not the anti-aliased edge color. For images of text, measure the color two pixels in from the edge of the letter and the background immediately next to it. A narrow border around a letter counts as part of the letter; a wide border that fills in the letter's inner details is a halo and counts as background.
- **Conditions / limits:** The border and halo explanation is a definition note, which is informative under WCAG 2.2 section 5.1 ([5.1](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#interpreting-normative-requirements)). axe's internal numbers (such as the upper width of shadows or outlines) are tool implementation, not W3C lines.

### 1.4.3-E04 — Text over background images and gradients

- **Type / source:** [Failure — F83 "Description"](https://www.w3.org/WAI/WCAG22/Techniques/failures/F83#description), [F83 "Tests"](https://www.w3.org/WAI/WCAG22/Techniques/failures/F83#tests), [G18 "Description"](https://www.w3.org/WAI/WCAG22/Techniques/general/G18#description), [ACT afw4f7 "Background"](https://www.w3.org/WAI/standards-guidelines/act/rules/afw4f7/#background).
- **Summary:** Compare the text with the parts of the image behind it that are most like the text. F83 first runs a quick check against the most similar part (the darkest part for dark text); if that meets the ratio, there is no failure. Otherwise check the background behind each letter; if that also falls short, it fails. G18 shows ways to keep the ratio, such as darkening the background behind the text or adding a thin outline to the letters. ACT says there is no clear method for determining legibility when only some pixels have sufficient contrast.
- **Conditions / limits:** The details of the per-letter check (which letters to pick, which area of background to compare) are not settled by the sources.

### 1.4.3-E05 — Specifying only the text color or only the background color

- **Type / source:** [Failure — F24 "Description"](https://www.w3.org/WAI/WCAG22/Techniques/failures/F24#description), [F24 "Tests"](https://www.w3.org/WAI/WCAG22/Techniques/failures/F24#tests), [Term — contrast ratio](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#dfn-contrast-ratio), [ACT afw4f7 "Background"](https://www.w3.org/WAI/standards-guidelines/act/rules/afw4f7/#background).
- **Summary:** F24 fails content where the author specifies only the text color (or only the background color) and the other is specified nowhere, including ancestors, because the author's color combined with a user's preferred color can become unreadable. Definition notes 3 and 4 also say white is assumed when no background is specified and that specifying only one is a failure. ACT says this issue must be tested separately from its rule.
- **Conditions / limits:** Definition notes are informative under section 5.1. F24 is a Failure documented by the AG WG.

### 1.4.3-E06 — States, placeholders, and which presentations to evaluate

- **Type / source:** [Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html#intent), [Term — contrast ratio](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#dfn-contrast-ratio).
- **Summary:** Placeholder text, and text shown when a pointer hovers or when an object has keyboard focus, are in scope. Evaluate the color pairs that the author would expect to appear adjacent in typical presentation (definition note 6). Unusual presentations, such as color changes by the user agent, need not be considered except where caused by the author's code.
- **Conditions / limits:** Note 6 is informative. The sources give no example for author-provided themes (light and dark).

### 1.4.3-E07 — A mechanism to switch to sufficient contrast

- **Type / source:** [Technique — G174 "Description"](https://www.w3.org/WAI/WCAG22/Techniques/general/G174#description) (Sufficient), [Understanding — Rationale for the Ratios Chosen](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html#rationale-for-the-ratios-chosen).
- **Summary:** The criterion can be met if a link or control on the page switches to a presentation with sufficient contrast. The control itself must meet the requirement, the new version must contain the same information and functionality, and it must conform to all criteria. A mechanism that lets users choose low-contrast color combinations is not a violation if it can return to the required values.
- **Conditions / limits:** G174 assumes a control on the page and does not address presentations that only follow an OS setting (such as `prefers-contrast`).

### 1.4.3-E08 — The scope of the ACT rule and axe

- **Type / source:** [ACT afw4f7 "Applicability"](https://www.w3.org/WAI/standards-guidelines/act/rules/afw4f7/#applicability), ["Assumptions"](https://www.w3.org/WAI/standards-guidelines/act/rules/afw4f7/#assumptions), ["Background"](https://www.w3.org/WAI/standards-guidelines/act/rules/afw4f7/#background).
- **Summary:** For each visible character, the rule checks whether the highest possible contrast between foreground and background meets the threshold. Text in disabled components is excluded. It assumes that text to be ignored is disabled or hidden from assistive technologies and does not consider logos or brand names, so exempt text can fail the rule while the criterion is still satisfied. Text with the same foreground and background color (1:1) is not "visual presentation of text." Passing the rule does not mean the criterion is satisfied.
- **Conditions / limits:** axe `color-contrast` is mapped to this ACT rule, but do not assume an identical implementation.

## Judgment lines

- Text that is not exempt fails if it is below 4.5:1 for normal text or 3:1 for large text. Compare without rounding. [Evidence: 1.4.3-E01–E03]
- For Japanese, also treat text of 18pt (about 24px) or more, or 14pt (about 18.66px) or more with `font-weight` 700 or more, as large text. When complex kanji in a thin font are hard to read, add an improvement recommendation without changing the threshold. [Author policy: W3C does not define the CJK equivalent size, and this keeps results aligned with axe. Evidence: 1.4.3-E02]
- The inactive-component exception applies only to components that are visible and actually not operable. Do not exempt a component that only looks gray but can be activated. Decoration is limited to text whose words can be substituted without changing its purpose. [Evidence: 1.4.3-E01]
- The logo exception is limited to logos as designed marks (including logotypes set in text). Company or product names written as ordinary text in body copy, headings, or buttons are not exempt. Treat a logo as exempt even when it is a link, and add a sufficient-contrast variant as a recommendation. A row of logos the author chose to show faint fails. [Author policy: the normative "brand name" can be read broadly, but we read it narrowly to match Understanding's treatment of brand guidelines. Evidence: 1.4.3-E01]
- For text over background images or gradients, pick the letters whose ratio is likely to be lowest (letters over the lightest or darkest part of the background, for example) and measure them. Compare each with the background color touching the letter that is most like the text. Pass if it meets the ratio, fail if it does not. Exclude background specks finer than the letter's strokes (such as photo grain). Measuring every letter is not required. [Author policy: we adopt F83's procedure as measuring the letters likely to be lowest. Excluding fine specks is also our interpretation. Evidence: 1.4.3-E04]
- When the author specifies only the text color (or only the background color) and the other is specified nowhere up to the root, do not fail on that alone. Fail when you reproduce an unreadable combination with user color settings (such as changing the browser's default text and background colors). If you cannot reproduce one, add a recommendation to specify the missing background (or text) color. [Author policy: F24 fails this specification by itself, but that produces many failures where the actual ratio is maintained, so we limit failures to reproduced cases. State the difference from F24 in the report. Evidence: 1.4.3-E05]
- Placeholder text, and text and colors that appear or change on hover or focus, are in scope. [Evidence: 1.4.3-E06]
- Every theme a user can ordinarily select through an OS setting or an on-site switch (light, dark, and so on) must meet the criterion. A presentation that becomes sufficient only under `prefers-contrast: more` does not exempt shortfalls in the default presentation. [Author policy: we read author-provided themes as typical presentations produced by the author's code, and an OS setting as not being an on-page switch under G174. Evidence: 1.4.3-E06, E07]
- Pass if an on-page switch produces a sufficient-contrast version, the switch itself meets the criterion, and the new version has the same information and functionality and conforms to all criteria. [Evidence: 1.4.3-E07]
- Text invisible because its foreground and background are the same color (1:1) is not assessed under 1.4.3. If the invisibility loses information, assess it under other criteria. [Evidence: 1.4.3-E08]

## Judgment examples

- **Pass:** Body text is `#595959` on `#ffffff` (about 7:1). A 24px normal-weight heading is `#949494` on `#ffffff` (about 3.03:1). [Evidence: 1.4.3-E02, E03]
- **Fail:** A 14px note is `#999999` on `#ffffff` (about 2.85:1). Being a brand color is not an exception. [Evidence: 1.4.3-E01]
- **Fail:** Body text at 4.499:1. Do not round it to 4.5:1. [Evidence: 1.4.3-E03]
- **Pass:** A 20px (about 15pt) Japanese heading with `font-weight: 700` at 3.5:1. It is 14pt bold or more, so it is large text and meets 3:1. [Author policy: the Japanese and weight lines. Evidence: 1.4.3-E02]
- **Fail:** The same 20px heading at 3.5:1 with `font-weight: 600` is normal text and needs 4.5:1. [Author policy: the weight line. Evidence: 1.4.3-E02]
- **Exempt, not reported:** Gray text in a `disabled` submit button. Text on a street sign in a photo. Words placed faintly in the background of a dictionary cover. The company name in the header logo image. [Evidence: 1.4.3-E01]
- **Fail:** The author shows a row of partner logos in faint dark gray and makes them white only on hover. [Evidence: 1.4.3-E01]
- **Fail:** A white heading over a photo, where letters over a bright part of the sky are 2.1:1 against the touching sky color. [Author policy: how to pick the letters. Evidence: 1.4.3-E04]
- **Improvement recommendation (not a failure):** Only `body { color: #333 }` is set and no background is specified anywhere. Unless you can reproduce an unreadable combination by darkening the background through user color settings, recommend adding a background color. [Author policy: the difference from F24. Evidence: 1.4.3-E05]
- **Fail:** In the dark theme, body text is `#666666` on `#1a1a1a` (about 3.03:1). A sufficient light theme does not exempt it. [Author policy: themes. Evidence: 1.4.3-E06]
- **Fail:** An input's placeholder is `#aaaaaa` on `#ffffff` (about 2.3:1). [Evidence: 1.4.3-E06]
- **Needs review:** A translucent band under the text overlaps a video behind it, so the background color changes with the scene. Measure the letters likely to be lowest in the brightest scene. [Author policy: inspection example. Evidence: 1.4.3-E04]

## When building

- When you specify a text color, also specify a background color on the same element or an ancestor. [Evidence: 1.4.3-E05]
- For text over images, place a band of sufficient color behind the text or add a thin outline. [Evidence: 1.4.3-E04]
- Choose placeholder, hover, focus, visited-link, and dark-theme colors against the same thresholds as normal text. [Evidence: 1.4.3-E06]
- With thin fonts, avoid color pairs that only just meet the threshold; leave a margin. [Evidence: 1.4.3-E03]

## When checking

- **What automation settles:** Treat axe `color-contrast` violations as evidence of failure when there is no sign of an exception (a component that looks inactive but is not `disabled`, a logo, decoration, text in a picture). If there is a sign, check the exception. A pass is evidence only for that element's text in the initial presentation. [Evidence: 1.4.3-E01, E08]
- **incomplete:** Background images (`bgImage`), gradients (`bgGradient`), overlap with other elements (`bgOverlap`, `elmPartiallyObscured`), foreground transparency (`fgAlpha`), pseudo-elements (`pseudoContent`), outside the viewport (`outsideViewport`), inputs without a value (`emptyValue`), symbol-only content (`nonBmp`), 1:1 (`equalRatio`), and so on. Keep them as needing verification until measured in the actual presentation. Decide images and gradients by the "letters likely to be lowest" line. [Evidence: 1.4.3-E04, E08. The list of reasons was checked against the axe-core 4.14.0 messages]
- **Remaining:** Placeholders (axe does not check them), hover and focus presentations, other themes such as dark, images of text, text over canvas or video, and iframe content. Check every placeholder; for components whose colors change on hover or focus, check one representative of each kind. Report unchecked states and themes under "remains", and do not mark NT for that alone. [Author policy: inspection scope. Evidence: 1.4.3-E06]
- **Do not assert:** Do not treat an axe pass or zero results as conformance with all of 1.4.3. axe does not detect text-color-only specification (it calculates against an assumed white background). Confirm large-text decisions with the font size and weight axe reports. [Evidence: 1.4.3-E05, E08]
- **AAA:** The AAA criterion with 7:1 / 4.5:1 is [1.4.6](./1.4.6.md). It uses these judgment lines with only the thresholds changed. Do not mix text below 7:1 into 1.4.3 reports.
