# 3.3.7 Redundant Entry

- Scope: Places in the same process that make users enter again information they already entered or were given
- Materials: Inputs and information presented across the whole process, earlier values, initial values and selection means on the repeated input, and the reason for requesting re-entry
- Automated check: `redundant-entry-check` only reports overlap candidates within one page. Check multi-page flows manually
- Sources checked: 2026-11-05. WCAG: Recommendation of 2024-12-12. Understanding updated 2025-09-17 and G221 updated 2026-03-09 (living published pages). The following are summaries, not quotations.

## Evidence

### 3.3.7-E01 — Determine the process and information in scope

- **Type / source:** [Normative — Redundant Entry](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#redundant-entry), [Term — process](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#dfn-processes), [Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/redundant-entry.html#intent), [G221 “Examples”](https://www.w3.org/WAI/WCAG22/Techniques/general/G221#examples) (Sufficient).
- **Summary:** Covers information entered in the same process and information provided to the user. As in G221 example 2, this includes an identification number issued in an earlier step. A process can span domains, such as through a third-party payment provider.
- **Conditions / limits:** Storage between sessions is not required. It does not apply when a user returns after closing a session or navigating away. Information provided by a different method, such as uploading a resume, is out of scope.

### 3.3.7-E02 — Check auto-population and selection means

- **Type / source:** [Normative — Redundant Entry](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#redundant-entry), [Understanding — Intent / Examples](https://www.w3.org/WAI/WCAG22/Understanding/redundant-entry.html#intent), [G221 “Tests”](https://www.w3.org/WAI/WCAG22/Techniques/general/G221#tests) (Sufficient).
- **Summary:** Showing the value as an editable default is an example of auto-population. Selection includes choosing and populating from a drop-down or similar, selecting text on the page and copying it into the input, and a “same as billing” checkbox. Selectable information must be on the same page and may be inside a show/hide component.
- **Conditions / limits:** “Available to select” does not prescribe a means. Browser autocomplete alone is insufficient; the content must provide the information. Being visible by default and near the input is ideal, not required. Understanding also lists not requesting the same information as a potential future technique.

### 3.3.7-E03 — Check the three exceptions

- **Type / source:** [Normative — Redundant Entry](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#redundant-entry), [Understanding — Exceptions](https://www.w3.org/WAI/WCAG22/Understanding/redundant-entry.html#exceptions).
- **Summary:** The exceptions are when re-entry is essential (such as memory games), required for content security (such as preventing a password from being shown or copied), or when earlier information is no longer valid. Re-validating a manually created password that is not displayed qualifies.
- **Conditions / limits:** There is no exception specific to privacy or personal information. Still, auto-population implementations should protect the data, including temporary storage ([Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/redundant-entry.html#intent)).

### 3.3.7-E04 — Separate value retention after errors and 3.3.8

- **Type / source:** [Understanding — Examples / Intent](https://www.w3.org/WAI/WCAG22/Understanding/redundant-entry.html#examples).
- **Summary:** One example keeps submitted information after an error from an incorrect card number. Another pre-fills the search term on a search results page.
- **Conditions / limits:** These are examples, not a requirement for the same implementation on every redisplay. Browser auto-filling is a sufficient technique in [3.3.8](./3.3.8.md), but this criterion asks the content to provide the information.

## Judgment lines

- For an input asking again for the same information in the same process, Pass when auto-population, selection on the same page, or an exception holds. Fail when none holds and the user can only enter it again. [Evidence: 3.3.7-E01–E03]
- Fail when an earlier step's information must be entered again in a later step and that page provides neither the value nor a selection means. Working browser autocomplete is not a reason to Pass. [Evidence: 3.3.7-E02]
- For same-page cases such as an email confirmation field or billing/shipping addresses, do not Fail under this criterion when the earlier value is visible and can be selected, copied, and pasted. Fail, absent an exception, when the value is masked or pasting is blocked. [Author policy: Applies Understanding's “select text from the page and copy it” to values in inputs. Evidence: 3.3.7-E02]
- Do not treat selection of only part of a value, such as the last four digits, as a selection means. [Author policy: The whole required information cannot be selected. Evidence: 3.3.7-E02]
- After a submission error, Fail when fields without errors are also cleared and must be re-entered. Treat clearing only the rejected field as “no longer valid” and clearing a password field as the security exception. [Author policy: Handling of rejected fields. Evidence: 3.3.7-E03–E04]
- Treat password re-validation and re-authentication before an action as exceptions. Do not extend this to fields with only non-security reasons. [Evidence: 3.3.7-E03]
- When a “Back” control in the flow returns to an earlier step and values are lost, judge it as the same process. When values are lost only through browser back or reload, this cannot be distinguished from leaving, so do not Fail; report it as an improvement candidate. [Author policy: Separates navigation provided in the flow from leaving. Evidence: 3.3.7-E01]
- Do not Fail only because a search term is not retained. Judge it when re-entering the same term is required to complete the process. [Author policy: Pre-filling the term is an example, not a required condition. Evidence: 3.3.7-E04]

## Judgment examples

- **Pass:** The employee ID entered in step 1 appears in step 3 as an editable default. [Evidence: 3.3.7-E02]
- **Pass:** A later step has a “same as billing” checkbox that populates the shipping values. [Evidence: 3.3.7-E02]
- **Pass:** A number issued in an earlier step is displayed on the page and can be selected, copied, and pasted into the input. [Evidence: 3.3.7-E01–E02]
- **Out of scope:** The user returns the next day and enters an address in a new session. [Evidence: 3.3.7-E01]
- **Out of scope:** The user uploads a resume, then enters work history in inputs, because the information was provided by a different method. [Evidence: 3.3.7-E01]
- **Exception:** A new password is created while hidden and retyped in a confirmation field. [Evidence: 3.3.7-E03]
- **Fail:** The page after shipping address entry requests a billing address with no default, no copy means, and no earlier address on the page. [Evidence: 3.3.7-E01–E02]
- **Fail:** A same-page email confirmation field blocks pasting, with no exception reason. [Author policy: Same-page handling. Evidence: 3.3.7-E02]
- **Fail:** A third-party payment page requires the billing address already entered during checkout, with no selection means. [Evidence: 3.3.7-E01–E02]
- **Needs review:** A card security code is requested again in the same process. The sources give no example, so confirm whether the reason for the new request is a security requirement. Privacy concerns alone are not an exception. [Author policy: Inspection example. Evidence: 3.3.7-E03]

## When building

- First, do not ask for the same information. If needed, provide an editable default or make it selectable on the same page. [Evidence: 3.3.7-E02]
- Keep acceptable input after submission errors. Protect reused values, including temporary storage. [Evidence: 3.3.7-E03–E04]

## When checking

- **Implementation confirmed:** axe-core 4.14.0 has no rule tagged wcag337. `redundant-entry-check` (`a11y-skills/redundant-entry`) reports as `incomplete` each editable input after the first with an overlapping purpose, within the same form or across inputs outside any form.
- **Settled:** The result of comparing records of entry and presentation across the process with actual auto-population, selection, and exception reasons.
- **Reading candidates:** `copyControls` is a text match and does not verify that values are copied. Not counting password and one-time-code fields is a tool scope, not proof of an exception. Inputs hidden at load are also counted.
- **Remaining:** Zero candidates is not Pass. Multi-page flows, re-entry of information provided by the system, other forms, checkboxes and radio buttons, and iframes and shadow DOM are not detected. If the process cannot be walked through, state the unchecked steps and mark needs review.
