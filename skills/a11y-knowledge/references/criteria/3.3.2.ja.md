# 3.3.2 ラベル又は説明

- 対象の部品: form（中の入力欄をまとめて）、input、checkbox、radio、switch、combobox、listbox、slider
- 要る材料: 入力欄の名前と、名前の出どころ（label / aria-label / placeholder）
- 自動チェック: axe の `label`（名前の有無。placeholder だけでも pass になる）

## 根拠

- [Understanding 3.3.2](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html)（[日本語](https://waic.jp/translations/WCAG22/Understanding/labels-or-instructions.html)）
  - 入力を求めるときにラベルか説明があること。何を入れるか、形式、必須かが分かること。
  - ラベルが「プログラムで結び付いている」ことは 1.3.1 / 4.1.2 の範囲。3.3.2 は、見えるラベル・説明があることを求める。
  - placeholder は入力すると消えるので、恒久的なラベルにならない。
- [G131: 説明的なラベル](https://www.w3.org/WAI/WCAG22/Techniques/general/G131)、[G162: ラベルの位置](https://www.w3.org/WAI/WCAG22/Techniques/general/G162)、[H90: 必須を示す](https://www.w3.org/WAI/WCAG22/Techniques/html/H90)、[F82: 必要な形式を示さない](https://www.w3.org/WAI/WCAG22/Techniques/failures/F82)

## 線引き

- 入力欄に名前が無いもの、または名前の出どころが placeholder だけのもの（入力すると消えるので恒久的なラベルにならない）があれば不適合。[解説書]
- placeholder だけのラベルはここで扱う。1.3.1 / 4.1.2 の不適合の理由にしない（placeholder から来た名前でも名前は名前）。[独自]（分担）
- フォームの 3.3.2 は、中の入力欄のラベルをまとめて見る。中の入力欄の情報が見えなければ要確認。[独自]
- 形式の指定（日付の書き方、ハイフンの有無）が要る欄で説明が無ければ不適合。[解説書]（F82）

## 作るとき

- すべての入力欄に見える `<label>` を付ける。placeholder はヒントに使い、ラベルの代わりにしない。
- 形式が決まっている欄（日付、電話番号）は、ラベルか説明に書き方の例を書く。
- 必須の欄は「必須」の文字か記号で示し、記号の意味をフォームの先頭で説明する。
- ラベルを見た目で隠すなら、`aria-label` ではなく視覚的に隠した `<label>` を使う（音声入力で名前を言えるようにする）。

## 確かめるとき

- **確定**: axe の `label` の違反（名前が無い）は不適合。pass は適合に数えない（placeholder だけでも pass になる）。
- **残る**: 名前の出どころが placeholder だけの欄が無いか。形式の説明が要る欄に説明があるか。
- **言い切らない**: 名前があることだけで適合にしない。
