# 3.3.1 Error Identification

- Components in scope: form, input
- Inputs needed: the screen in its error state (not visible on the screen before input), `aria-invalid`, error messages
- Automated checks: none

## Rationale

- [Understanding 3.3.1](https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html) ([Japanese translation](https://waic.jp/translations/WCAG22/Understanding/error-identification.html))
  - When an input error is automatically detected, the item in error must be identified and the error described in text.
  - Indicating an error by color alone or an icon alone is not allowed (text is required).
  - If errors are not detected (submitted as is), not applicable.
- [G83: indicating a missing required field in text](https://www.w3.org/WAI/WCAG22/Techniques/general/G83), [G85: indicating a format error in text](https://www.w3.org/WAI/WCAG22/Techniques/general/G85), [ARIA21: aria-invalid](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA21)

## Judgment lines

- It is normal for the screen before input to show no errors. Do not mark non-conformant solely because the error display mechanism cannot be confirmed or because there are required fields. [Understanding] (cannot be decided without seeing the error state)
- If the error state does not appear in the information, such as `aria-invalid` or error messages, needs review (trigger an error to confirm). [Our interpretation]
- On a screen showing errors, if which field is in error cannot be told from text (a red border only, an icon only), non-conformant. [Understanding]

## When building

- Show errors in text next to the field ("The email address format is incorrect") and associate them with the field via `aria-describedby`.
- Put `aria-invalid="true"` on the field in error.
- When there are several errors, summarize them at the top (an error list) and link each item to its field.
- Do not indicate errors by color or border alone (also falls under 1.4.1).

## When checking

- **Settled**: none.
- **Remains**: actually submit with incorrect input and check whether the location and content of the error can be told from text.
- **Do not assert**: do not mark conformant or non-conformant from the screen before input alone.
