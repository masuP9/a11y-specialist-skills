# 3.2.1 フォーカス時

- 対象: ページ全体と、違反を起こした要素
- 要る材料: 実測（`@a11y-skills/audit` の focus-indicator-check の `onFocus`。フォーカスだけで URL が変わった要素）
- 自動チェック: focus-indicator-check

## 根拠

- [Understanding 3.2.1](https://www.w3.org/WAI/WCAG22/Understanding/on-focus.html)（[日本語](https://waic.jp/translations/WCAG22/Understanding/on-focus.html)）
  - フォーカスを受けただけで「状況の変化」（別のページへ移動、フォーカスの移動、新しいウィンドウ、内容の大きな並べ替え）を起こさないこと。
  - フォーカスで見た目が変わる（強調、ツールチップ）のは状況の変化ではない。
- [G107: フォーカスではなく操作で変える](https://www.w3.org/WAI/WCAG22/Techniques/general/G107)、[F55: フォーカスを受けた瞬間に外す](https://www.w3.org/WAI/WCAG22/Techniques/failures/F55)

## 線引き

- 判定は Tab でフォーカスを送った実測を根拠にする。実測が無いときは判定しない。[独自]
- フォーカスしただけで origin か pathname が変わった要素があれば不適合（遷移を直接見ているので例外が当たらない）。違反の要素が特定できれば要素に、できなければページ全体に付ける。[解説書]
- 同じ文書の中の URL 変更（query / hash だけ）は自動で不適合にしない。`pushState` / `replaceState` でも起きるので、画面の内容が変わる遷移かは URL だけでは分からない。要確認。[独自]
- 違反が無く、実測が最後まで終わり、操作できる要素が 1 つ以上あれば適合。「Tab でフォーカスしたときのページ遷移だけを調べた（新しいウィンドウ・ダイアログ・Tab で届かない要素は対象外）」と書き添える。[独自]
- どの要素が遷移を起こしたか分からないまま実測が終わったとき（`unidentifiedNavigation`）は適合にしない。[独自]
- SPA で pathname だけを `replaceState` で書き換える実装は誤検出として残る。[独自]

## 作るとき

- `focus` イベントで遷移・送信・フォーカスの移動をしない。変えるのは `click` / `change` / Enter で。
- セレクトボックスの `change` で自動遷移しない（3.2.2）。
- フォーカスでツールチップを出すのはよい。

## 確かめるとき

- **確定**: `onFocus` に origin か pathname が変わった要素があれば不適合。
- **残る**: query / hash だけが変わった要素は、画面の内容が変わるかを見る。
- **言い切らない**: 実測が無い状態で適合にしない。途中で止まった実測で適合にしない。
