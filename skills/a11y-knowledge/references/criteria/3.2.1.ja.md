# 3.2.1 フォーカス時

- 対象: フォーカスを受ける部品と、そのときの状況の変化
- 要る材料: フォーカス前後の操作ログ・URL・画面・フォーカス位置、起動操作との区別
- 自動チェック: focus-indicator-checkの `details.onFocusViolations` 等。Tab時のURL変化の検査
- 原文確認日: 2026-11-02。WCAGは2024-12-12勧告、Understanding / Techniquesは随時更新の公開ページ。以下は引用ではなく要約。

## 根拠

### 3.2.1-E01 — フォーカスと起動、内容変化と状況変化を分ける

- **種別・出典:** [規範 — On Focus](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#on-focus)、[Understanding — Intent / Changes of context](https://www.w3.org/WAI/WCAG22/Understanding/on-focus.html#intent)。
- **要約:** フォーカスだけで送信・別ウィンドウ・別部品へのフォーカス移動等を起こす場合を確認する。対象はTabに限らず、ポインタ等でフォーカスを受ける場合も含む。
- **適用条件・限界:** ボタンのクリックには起動も含まれるので、クリック後の遷移をすべてフォーカス由来にしない。強調や補足表示は、それだけでは状況変化ではない。URL変化と状況変化は同義ではない。

### 3.2.1-E02 — 起動操作を使い、受けたフォーカスを勝手に外さない

- **種別・出典:** [Technique — G107「Tests」](https://www.w3.org/WAI/WCAG22/Techniques/general/G107#tests)（Sufficient）、[Failure — F55「Tests」](https://www.w3.org/WAI/WCAG22/Techniques/failures/F55.html#tests)。
- **要約:** 状況を変える操作はフォーカスではなく利用者の起動で行う。受けた直後のフォーカス除去は失敗条件を確認する。
- **適用条件・限界:** 入力にフォーカスするたびにヘルプへフォーカスが移る例は不適合。フォーカスを維持して説明を表示するだけの例へ広げない。

## 線引き

- 実際のフォーカス操作と結果で判断する。URLが同じでも、新しいウィンドウやフォーカスを奪うダイアログがフォーカスだけで生じれば不適合にできる。Tab時のURL検査だけをSCの対象範囲としない。[根拠: 3.2.1-E01–E02]
- ツールでフォーカスに伴うorigin / pathnameの変化を記録した要素は、不適合とする既定方針を維持する。ただし、実際には画面を変えないhistory更新や独立したタイマーだったと確認できた場合は、この証拠でFailにしない。要素を特定できない記録を別要素へ割り当てない。[独自: URLを用いる検査方針。根拠: 3.2.1-E01]
- query / hashだけの変化は自動で不適合にせず、画面・フォーカス・原因を確認する。要確認から、実際の状況変化が確認できればFail、単なるURL更新なら指摘なしへ進める。[独自: URL候補の確認方針。根拠: 3.2.1-E01]
- 違反・未解決のURL候補がなく、操作対象が1つ以上あり、実測が最後まで終わった場合は「Tab時のページ遷移」の範囲で適合とする既存方針を維持する。新しいウィンドウ・ダイアログ・Tabで届かない要素は未検査と書く。既に判明した範囲外の違反をこの限定結果で打ち消さない。[独自: 範囲を明記する報告方針。参考根拠: 3.2.1-E01–E02]
- `interrupted` / `aborted` / `unidentifiedNavigation` 等の未完了・未特定があれば適合にしない。現行ツールはURL差を `onFocusViolations` に入れ、正規化後のviolationでもquery / hash等の意味は別途判断する。未特定遷移はincompleteに残る。[独自: ツールとの対応。実装確認: `packages/a11y-audit/src/playwright/runFocusIndicatorCheck.ts`、`src/utils/axe-format.ts`]

## 判断例

- **適合:** フォーカスで補足が表示されるが位置は維持され、起動操作まで送信・遷移しない。[根拠: 3.2.1-E01–E02]
- **不適合:** 入力欄にフォーカスしただけでヘルプダイアログへフォーカスを奪われる。URLが変わらなくても指摘する。[根拠: 3.2.1-E01–E02]
- **指摘しない:** ボタンをEnterで起動して別ページへ移る。フォーカスのみでは変化しない。[根拠: 3.2.1-E02]
- **要確認:** Tab後にhashが変わったが画面は未取得。本文の大きな変更・フォーカス移動・発生原因を確認する。[独自: 検査例。根拠: 3.2.1-E01]

## 作るとき

- 送信・遷移等は明示的な起動で行い、focusハンドラでは実行しない。changeは3.2.2の条件で別に評価する。[根拠: 3.2.1-E01–E02]
- 補足を表示するときは、元の操作を継続できるようにする。[根拠: 3.2.1-E01]

## 確かめるとき

- **確定:** フォーカスによって生じた状況変化。URLベースの既定判定は上記の著者方針。[3.2.1-E01–E02]
- **残る:** URLだけの更新か、起動やタイマーとの区別、ツールが検査しない状況変化。
- **言い切らない:** URL不変を適合にしない。フォーカスに伴う内容変化すべてをFailにしない。[根拠: 3.2.1-E01]
