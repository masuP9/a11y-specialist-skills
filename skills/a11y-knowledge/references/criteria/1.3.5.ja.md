# 1.3.5 入力目的の特定

- 対象の部品: input（textbox など）、combobox
- 要る材料: 実測（`@a11y-skills/audit` の autocomplete-audit）、欄の名前・ラベル
- 自動チェック: autocomplete-audit、axe の `autocomplete-valid`

## 根拠

- [Understanding 1.3.5](https://www.w3.org/WAI/WCAG22/Understanding/identify-input-purpose.html)（[日本語](https://waic.jp/translations/WCAG22/Understanding/identify-input-purpose.html)）
  - 対象は「利用者本人に関する情報」を集める入力欄のうち、WCAG の [Input Purposes for User Interface Components](https://www.w3.org/TR/WCAG22/#input-purposes) の一覧にある目的のもの。他人の情報（送り先）や検索語は対象外。
  - 目的を「プログラムで判断できる」形は、実質 HTML の `autocomplete` 属性。
- [H98: autocomplete 属性](https://www.w3.org/WAI/WCAG22/Techniques/html/H98)

## 線引き

- 対象は本人の情報（名前・メール・電話・住所など、`autocomplete` の値に対応するもの）を集める入力欄だけ。検索欄、他人の情報の欄は対象外。[解説書]
- 欄の目的を name / id / ラベル / placeholder から推定できて、`autocomplete` の値が仕様に無い書き方なら不適合。有効な値があれば適合。[解説書]
- `autocomplete` が無い（または `off`）欄は、本人の情報の欄だと確かめられれば不適合。本人の情報でない（送り先の名前など）と読み取れれば対象外。[解説書]
- 目的を推定できなかった欄の無効な値は、ラベルなどから本人の情報の欄だと確かめられれば不適合、本人の情報でないと読み取れれば対象外、どちらとも読み取れなければ要確認。[独自]
- 属性の値を確かめられないときは、推測で不適合にしない（要確認）。[独自]

## 作るとき

- 本人の情報を入れる欄には `autocomplete` を一覧の値で付ける（`name`、`email`、`tel`、`postal-code`、`street-address` など）。
- 送り先など他人の情報の欄には `autocomplete="shipping name"` のようにセクションを付けるか、付けない。
- `autocomplete="off"` を本人の情報の欄に付けない（ブラウザの補完を止めたいだけなら、別の手段を検討する）。
- 値の書き方は仕様どおりに（`tel` を `phone` と書かない）。

## 確かめるとき

- **確定**: autocomplete-audit が「目的を推定できた欄の無効な値」を出せば不適合。有効な値があれば適合。
- **残る**: `missing`（autocomplete が無い）と、目的を推定できなかった欄の無効な値は、本人の情報の欄かを見て決める。
- **言い切らない**: 実測が無い欄を推測で不適合にしない。
