# 3.2.6 Consistent Help

- Scope: help mechanisms repeated across multiple pages within the same set
- Inputs needed: aria snapshots, routes to help, order relative to shared content, and presentation conditions. Read [cross-page](../cross-page.md) first
- Automated checks: no dedicated check. `page-snapshot` only supplies material
- Sources checked: 2026-11-02. WCAG is the 2024-12-12 Recommendation; Understanding / Techniques are living WCAG 2.2 public pages. The following are summaries, not quotations.

## Rationale

### 3.2.6-E01 — Compare existing help without requiring its provision

- **Type / source:** [Normative — Consistent Help and Note 1](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#consistent-help), [Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/consistent-help.html#intent).
- **Summary:** Check direct presentation and links for human contact details, human contact mechanisms, self-help, and fully automated contact mechanisms. Missing help on some pages is not itself a failure.
- **Conditions / limits:** Contextual help such as field instructions is separate. Do not require constant human availability or the same help on downloadable static documents. Establish set boundaries first.

### 3.2.6-E02 — Compare serialized order under matching presentation conditions

- **Type / source:** [Normative — Consistent Help and Note 2](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#consistent-help), [Understanding — Intent / Limitations and Exceptions](https://www.w3.org/WAI/WCAG22/Understanding/consistent-help.html#intent).
- **Summary:** Compare before/after relationships with other shared content. Viewport, zoom, and orientation changes can change the presentation variation. Different visual positions alone do not fail when serial order matches.
- **Conditions / limits:** Mere page navigation or ordinary login is not a user request to change layout. Compare within matching presentation conditions.

### 3.2.6-E03 — A disclosure widget alone does not cause failure

- **Type / source:** [Technique — G220, Examples and Tests](https://www.w3.org/WAI/WCAG22/Techniques/general/G220.html#examples) (Sufficient).
- **Summary:** The example with direct links on some pages and links inside disclosure widgets in the same relative order on others conforms. Distinguish this from the recommendation to provide direct links consistently.
- **Conditions / limits:** Inspect the disclosure and its destination. Do not turn G220's checks for presence on all pages or visual placement into requirements beyond the normative criterion.

## Judgment lines

- First determine which candidates are help and which repeated mechanism they belong to. Assign each candidate once to a group or out of scope; leave uncertain correspondence as needs review. [Our interpretation: preventing omissions from reversing the majority. Evidence: 3.2.6-E01]
- Group duplicate help in a page's header and footer as separate recurring occurrences. However, do not split one mechanism that moved between pages into location-based groups and thereby exclude it from comparison. [Our interpretation: grouping policy. Evidence: 3.2.6-E02]
- Help confirmed to exist on only one page is outside the multiple-page comparison. Merely having obtained one page means needs review. Use the majority policy in [cross-page](../cross-page.md) for assigning page results. [Evidence: 3.2.6-E01. Insufficient-material handling and assignment are author policy]
- Do not mistake ordinary navigation or login for help; include direct links to FAQs, contact details, and similar help. [Evidence: 3.2.6-E01]

## Judgment examples

- **Conformant:** Contact follows the main content on every page, with coordinates changing only because content length varies. Different CSS visual positions with the same serial order also do not fail this criterion. [Evidence: 3.2.6-E02]
- **Conformant:** On some pages, opening a help disclosure in the same relative order reveals the contact link. Requiring disclosure alone is not a failure. [Evidence: 3.2.6-E03]
- **Non-conforming inconsistency:** Under matching presentation conditions, contact moves before the shared main content on one page. Merely navigating there does not qualify for the user-change exception. [Evidence: 3.2.6-E02]
- **Do not flag:** Pages without help, different placement between editing and marketing applications that form different sets, or presentation changes following user resizing. Still compare pages within matching presentation conditions. [Evidence: 3.2.6-E01–E02]
- **Needs review:** A possible contact mechanism exists, but its expanded link or surrounding shared content has not been obtained. Obtain that state and compare. [Our interpretation: inspection policy. Evidence: 3.2.6-E02–E03]

## When building

- Make help reachable from a shared location. Align both serial and visual order, preferring direct links where possible. Do not confuse the latter two recommendations with this criterion's minimum requirements. [Our interpretation: author implementation recommendations. Supporting evidence: 3.2.6-E02–E03]
- Also check [3.2.3](./3.2.3.md) when help is part of navigation. [Evidence: 3.2.6-E02]

## When checking

- **Settled:** Results of comparing help's serial order relative to other shared content under matching presentation conditions. [3.2.6-E01–E03]
- **Remains:** Expanded routes, correspondence between recurring occurrences, user presentation changes, and uncollected pages.
- **Do not assert:** Failure solely because help is absent, coordinates differ, or a disclosure contains it. [Evidence: 3.2.6-E01–E03]
