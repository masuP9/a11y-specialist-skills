# 3.2.6 Consistent Help

- Scope: multiple pages (elements of help mechanisms. The whole page for candidates that are text or elements that cannot be looked up)
- Inputs needed: the aria snapshot of each page (`page-snapshot`). Read [cross-page](../cross-page.md) first
- Automated checks: none

## Rationale

- [Understanding 3.2.6](https://www.w3.org/WAI/WCAG22/Understanding/consistent-help.html) ([Japanese translation](https://waic.jp/translations/WCAG22/Understanding/consistent-help.html))
  - If a help mechanism appears repeatedly on multiple pages, its relative order to the other content on the page must be the same. There is no obligation to provide help.
  - There are 4 kinds of help mechanism: human contact details (phone, email, hours), human contact mechanisms (form, chat, social media), self-help options (FAQ, how-to, support pages), and fully automated contact mechanisms (chatbot).
  - Contextual help only for that place, such as an explanation next to an input field, is out of scope.
- [G220: help in the same location](https://www.w3.org/WAI/WCAG22/Techniques/general/G220)

## Judgment lines

- Help mechanisms are the 4 kinds above. A link to a help page is also help. [Understanding]
- Not help: explanations next to input fields and contextual help only for that place, ordinary navigation items, and non-help actions such as login. [Understanding]
- What is judged is only "which candidates are help" and the grouping "is it the same help across pages". The comparison of whether the position or order matches is done after grouping. [Our interpretation]
- Each candidate passed in goes into exactly one group or "not help", exactly once. Silently dropping one can flip the majority and produce a false non-conformance (when the same help is in the footer on 3 pages and in the header on 2, dropping 2 on the footer side makes the header side the majority). [Our interpretation]
- Help in 2 places on the same page (header and footer) is grouped separately per place. [Our interpretation]
- Help that exists on only one page is not evaluated. Candidates with no content to compare across 2 or more pages are needs review. Conformant if compared and there is no disagreement. [Our interpretation]
- Picking up phone numbers and email addresses may be coarse. Anything picked up by mistake can be excluded as not help. [Our interpretation]
- Handling of majority and even splits is in [cross-page](../cross-page.md).

## When building

- Place contact details, FAQ, and chat in the shared header or footer, in the same position on every page.
- Page-specific help (form explanations) is out of scope for 3.2.6, so it may be placed per page.
- If placing help as a navigation item, keep its order within the navigation on every page (overlaps with 3.2.3).

## When checking

- **Settled**: none.
- **Remains**: pick up help candidates from each page's snapshot, group them, and compare the relative order to the other content.
- **Do not assert**: do not mark the absence of help non-conformant. Do not evaluate help that is on only one page.
