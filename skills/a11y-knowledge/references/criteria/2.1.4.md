# 2.1.4 Character Key Shortcuts

- Scope: author-provided shortcuts operated using only characters
- Inputs needed: shortcut specifications, settings, and behavior inside/outside component focus
- Automated checks: character-key-shortcut-check (actual character input with focus on body)

- Sources checked: 2026-11-01. WCAG refers to the 2024-12-12 Recommendation; Understanding / Techniques are the continuously updated WCAG 2.2 published pages. The following are summaries, not quotations.

## Evidence

### 2.1.4-E01 — Judge characters rather than physical key counts

- **Type / source:** [Understanding — notes under “Intent”](https://www.w3.org/WAI/WCAG22/Understanding/character-key-shortcuts.html#intent).
- **Summary:** Character-only sequences are included. Do not exclude pressing G followed by A or entering ? with Shift + / merely because multiple keys are involved.
- **Conditions / limits:** Distinguish Shift or AltGr used to produce characters from shortcuts requiring keys such as Ctrl. Keyboard layouts vary; physical key counts are insufficient.

### 2.1.4-E02 — Check disablement, remapping, or focus restriction

- **Type / source:** [Normative — WCAG 2.2 “Character Key Shortcuts”](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#character-key-shortcuts), [Technique — G217 “Description” / “Tests”](https://www.w3.org/WAI/WCAG22/Techniques/general/G217.html#tests) (Sufficient).
- **Summary:** Check for at least one of disablement, remapping to include a non-printable key, or activation only when the relevant component has focus. Changing only the character does not satisfy remapping.
- **Conditions / limits:** Do not universally require disablement for character selection within a focused select. Suppressing shortcuts in text inputs does not by itself make page-wide shortcuts focus-restricted.

### 2.1.4-E03 — Exhaustive key pressing is not the only inspection method

- **Type / source:** [Failure — F99 “Description” / “Tests”](https://www.w3.org/WAI/WCAG22/Techniques/failures/F99#tests), [Technique — G217 “Locating and testing for character key shortcuts”](https://www.w3.org/WAI/WCAG22/Techniques/general/G217.html#description) (Sufficient).
- **Summary:** Trusted author information or instructions can identify shortcuts for checking actual behavior and mitigation. Script searches and listeners alone cannot provide exhaustive coverage.
- **Conditions / limits:** No response to automated individual keys does not rule out sequences, other states, or other layouts. Actually causing an accidental activation is not a prerequisite for establishing failure.

## Judgment boundaries

- Fail an applicable shortcut with none of disablement, appropriate remapping, or component-focus restriction. [Evidence: 2.1.4-E01, 2.1.4-E02]
- The tool tries 94 printable ASCII characters excluding space on body. Reactions and untested keys require review; probes without reactions or untested keys return pass; no listeners on the specified top-level nodes returns not applicable. Keep these results within the inspected scope, excluding character sequences and app wrapper elements from any generalization. [Our interpretation: tool mapping. Implementation: [runCharacterKeyShortcutCheck.ts](../../../../packages/a11y-audit/src/playwright/runCharacterKeyShortcutCheck.ts), [normalizeCharacterKeyShortcutCheck](../../../../packages/a11y-audit/src/utils/axe-format.ts)]

## When building

- Provide disablement or remapping to include a non-printable key for global character shortcuts. Restrict component-specific character interactions to when that component has focus. [Evidence: 2.1.4-E02]

## When checking

- **Established:** Applicable key interactions and behavior after settings changes and outside component focus. [2.1.4-E01–E03]
- **Remaining:** Character sequences, other states, non-ASCII characters, and wrapper listeners. The tool can execute deletion/submission shortcuts. Use the function API's `keys` to try a suspect character individually (the CLI has no key filter). [Our interpretation: inspection limits]
- **Do not conclude:** preventDefault() or a DOM change alone does not establish a shortcut. Shift used to generate a character does not make it out of scope.
