# 1.3.2 Meaningful Sequence

- Scope: Content whose presented order affects its meaning (text, procedures, tables, ordered lists, paired figures and descriptions, and similar content)
- Materials: On-screen order, DOM and accessibility tree order, CSS used for positioning, and white space or line breaks inside words
- Automated check: None. axe-core 4.14.0 has no rule tagged `wcag132`. `page-snapshot` provides reading-order material but no verdict
- Sources checked: 2026-11-05. WCAG: Recommendation of 2024-12-12. Understanding updated 2025-09-16; G57, F1, F32, and F49 updated 2026-01-12; C27 updated 2025-10-31; F33 updated 2026-01-26; F34 updated 2026-06-15 (living published pages). The following are summaries, not quotations.

## Evidence

### 1.3.2-E01 — Determine where order affects meaning

- **Type / source:** [Normative — Meaningful Sequence](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#meaningful-sequence), [Term — correct reading sequence](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#dfn-correct-reading-sequence), [Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/meaningful-sequence.html#intent).
- **Summary:** Only sequences whose meaning changes when reordered are in scope. HTML text is always a meaningful sequence, as are tables and ordered lists; unordered lists are not. Several orders can be correct, and it is enough that one of them can be programmatically determined.
- **Conditions / limits:** The relative order of main and navigation, or of an article and its callout sidebars, does not affect meaning. The same holds for two independent articles, unless their contents are interleaved.

### 1.3.2-E02 — Separate a visual/DOM order difference from a change in meaning

- **Type / source:** [Understanding — Examples](https://www.w3.org/WAI/WCAG22/Understanding/meaningful-sequence.html#examples), [G57 "Tests"](https://www.w3.org/WAI/WCAG22/Techniques/general/G57#tests) (Sufficient), [C27 "Description"](https://www.w3.org/WAI/WCAG22/Techniques/css/C27#description) (Sufficient), [F1 "Tests"](https://www.w3.org/WAI/WCAG22/Techniques/failures/F1#tests) (Failure).
- **Summary:** Understanding Example 1 shows a multi-column document read from top to bottom of each column. Example 2 positions a navigation bar, main story, and side story with CSS; the visual and programmatic orders differ, but this is not a problem because the meaning does not depend on the order. G57 linearizes the content and checks that the meaning stays the same. F1 is the failure where CSS positioning changes meaning, checked by code, the accessibility tree, a screen reader, or the display without positioning.
- **Conditions / limits:** C27 is one sufficient way to match DOM and visual order, not a required condition. Mismatched orders can still confuse people combining speech and the screen, and keyboard users.

### 1.3.2-E03 — Check how layout tables linearize

- **Type / source:** [F49 "Description"](https://www.w3.org/WAI/WCAG22/Techniques/failures/F49#description), [F49 "Tests"](https://www.w3.org/WAI/WCAG22/Techniques/failures/F49#tests) (Failure).
- **Summary:** Layout tables themselves are not prohibited. It is a failure when reading in source order, or removing the table markup, does not match the meaningful sequence conveyed by the presentation.
- **Conditions / limits:** Check the linearized result, not the use of a table. A figure and its description split across rows are also covered.

### 1.3.2-E04 — Check white space inside words, and columns or tables built from white space

- **Type / source:** [F32 "Description"](https://www.w3.org/WAI/WCAG22/Techniques/failures/F32#description), [F32 "Examples"](https://www.w3.org/WAI/WCAG22/Techniques/failures/F32#examples), [F33 "Tests"](https://www.w3.org/WAI/WCAG22/Techniques/failures/F33#tests), [F34 "Tests"](https://www.w3.org/WAI/WCAG22/Techniques/failures/F34#tests) (Failure), [C8](https://www.w3.org/WAI/WCAG22/Techniques/css/C8) (Sufficient with G57, updated 2025-09-25).
- **Summary:** F32 is the failure of adjusting letter spacing with white space, non-breaking spaces, or line breaks inside a word. Its examples include "W e l c o m e", "東　京", and "東京都" stacked vertically with `<br>`. F33 and F34 are failures of columns and tables built from white space characters, and also fail 1.3.1. CSS letter-spacing can adjust spacing.
- **Conditions / limits:** White space inside an initialism and white space between words are not F32. F33 and F34 cover plain text content.

### 1.3.2-E05 — Check mixed text direction

- **Type / source:** [Understanding — Sufficient Techniques](https://www.w3.org/WAI/WCAG22/Understanding/meaningful-sequence.html#sufficient), [G57 "Description"](https://www.w3.org/WAI/WCAG22/Techniques/general/G57#description), [H34](https://www.w3.org/WAI/WCAG22/Techniques/html/H34) (updated 2025-09-24), [H56](https://www.w3.org/WAI/WCAG22/Techniques/html/H56) (updated 2025-09-25) (Sufficient with G57).
- **Summary:** In text with mixed direction, moving punctuation in the source to fix its display exposes the wrong order to assistive technology. RLM, LRM, or `dir` keep both the display and the source order correct.
- **Conditions / limits:** This is normally not an issue on pages using only left-to-right languages. Check only text with mixed direction.

## Judgment lines

- Fail where order affects meaning and reading in DOM or tree order changes that meaning. Pass if at least one correct order can be programmatically determined. [Evidence: 1.3.2-E01–E02]
- Do not fail on a visual/DOM order difference alone. Do not flag reordering that keeps the meaning, such as cards or the order of main and navigation. [Evidence: 1.3.2-E01–E02]
- Fail where order or pairing carries meaning and has been swapped: procedure numbers, date order, table rows and columns, paired figures and descriptions. [Evidence: 1.3.2-E01–E03]
- Do not fail layout tables for their use alone; judge the linearized result. [Evidence: 1.3.2-E03]
- Fail letter spacing adjusted with white space or line breaks inside a word. Treat the space between family and given names as between words and do not flag it. [Evidence: 1.3.2-E04. Names are [Author policy]: an application of F32's "white space between words"]
- When the same ordering issue also harms operation order, evaluate [2.4.3](./2.4.3.md) separately. Do not copy a 1.3.2 Fail to 2.4.3. [Evidence: 1.3.2-E02]

## Judgment examples

- **Pass:** CSS places navigation to the left of the main content, and the DOM has it after the main content. Either order keeps the meaning. [Evidence: 1.3.2-E01–E02]
- **Pass:** Equivalent product cards are reordered with CSS `order`. Their relative order carries no meaning. [Evidence: 1.3.2-E01–E02]
- **Pass:** A two-column document reads the left column from top to bottom, then moves to the right column. [Evidence: 1.3.2-E02]
- **Fail:** Steps 1–3 display correctly using `flex-direction: row-reverse`, but the DOM has them as 3, 2, 1. [Evidence: 1.3.2-E02]
- **Fail:** The heading "会 社 概 要" uses spaces to adjust letter spacing. [Evidence: 1.3.2-E04]
- **Fail:** A layout table has a figure in the first row and its description in another column of the next row, and linearizing places other content between them. [Evidence: 1.3.2-E03]
- **Needs review:** A list's visual and DOM orders differ, but the screen does not show whether it is newest-first or arbitrary. Confirm the ordering basis and judge if the order carries meaning. [Author policy: inspection example. Evidence: 1.3.2-E01]

## When building

- Write the DOM in reading order and adjust visual placement with CSS. [Evidence: 1.3.2-E02]
- Use CSS letter-spacing for spacing and `writing-mode` for vertical text. [Evidence: 1.3.2-E04. `writing-mode` is [Author policy]: a recommended alternative to F32 Example 3]

## When checking

- **Implementation confirmed:** `page-snapshot` aria snapshots carry no on-screen position, so compare them with a screenshot. `focus-order-check` provides Tab order material and does not examine reading order.
- **Settled:** The result of comparing the screen with DOM and tree order where order carries meaning, and of checking white space inside words.
- **Remaining:** The effect on meaning is not decided automatically. Treat a tree/screenshot difference as a candidate and read the content to see whether the meaning changes.
- **Do not assert:** Do not turn the absence of automated results into a Pass. Do not fail on a DOM/visual order difference alone.
