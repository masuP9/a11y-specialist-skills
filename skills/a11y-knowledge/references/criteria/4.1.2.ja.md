# 4.1.2 名前（name）、役割（role）及び値（value）

- 対象の部品: 標準・自作の操作部品。この知識ベースでは dialog / alertdialog 自体を4.1.2の対象から外す。中のボタン・入力欄などは対象
- 要る材料: DOM、計算された名前・役割・状態・値、操作前後のアクセシビリティツリー、必要に応じた支援技術での確認
- 自動チェック: axe の `button-name`、`link-name`、`input-button-name`、`aria-*` 系
- 原文確認日: 2026-11-01。WCAG は 2024-12-12 勧告、Understanding / Techniques は WCAG 2.2 公開ページ（随時更新）。以下は引用ではなく要約。

## 根拠

### 4.1.2-E01 — 標準要素なら常に適合、ではない

- **種別・出典:** [Understanding —「Intent」](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html#intent)。
- **要約:** 標準部品が要件を満たすのは仕様どおりに使った場合。役割や機能をスクリプト等で変えた場合は追加対応が必要になる。
- **適用条件・限界:** `button` 等のタグと名前だけで適合にしない。実際の役割、状態・値とその変更の通知まで確認する。

### 4.1.2-E02 — 名前は属性の存在ではなく計算結果を確認する

- **種別・出典:** [Technique — ARIA14「Description」「Tests」](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA14#tests)（Sufficient）。
- **要約:** `aria-label` を使う場合、名前を持てる役割であることと、値が操作の目的を表すことを確認する。
- **適用条件・限界:** この手法は見えるラベルが使えない場合などの一例。属性を置くこと自体や非空文字列だけを十分条件にしない。見えるラベルの要件は別途確認する。

### 4.1.2-E03 — 状態属性は必要性と更新を確認する

- **種別・出典:** [Technique — ARIA5「About this Technique」「Tests」](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA5#tests)（G10と併用してSufficient）。
- **要約:** 役割に必要な状態・プロパティがあり、不許可のものを使わず、操作後も現在の状態を反映するか確認する。
- **適用条件・限界:** すべての部品に `aria-expanded` 等を要求しない。静止したDOMだけでは更新を確認できない。ARIA5単独を達成基準全体の十分条件にしない。

### 4.1.2-E04 — 名前チェックの pass は部分的な証拠

- **種別・出典:** ACT（Approved）[97a4e1「Applicability」「Expectation」「Accessibility Requirements Mapping」](https://www.w3.org/WAI/standards-guidelines/act/rules/97a4e1/#applicability)（版: 2023-08-31）。
- **要約:** アクセシビリティツリーにあるボタンの非空の名前を確認する。すべて pass でも4.1.2には追加確認が必要。
- **適用条件・限界:** `input type="image"` はこのルールの対象外。名前の存在から状態更新や別の部品の適合を推定しない。axe の同種のチェックと実装が同一とは限らない。

### 4.1.2-E05 — ダイアログの名前要件とWCAGの判定を分ける

- **種別・出典:** [技術仕様 — WAI-ARIA 1.2「dialog」](https://www.w3.org/TR/2023/REC-wai-aria-1.2-20230606/#dialog)（2023-06-06 勧告）、[ツールの分類 — axe-core 4.14「aria-dialog-name」](https://dequeuniversity.com/rules/axe/4.14/aria-dialog-name)（2026-11-01確認）。
- **要約:** WAI-ARIAではdialogの名前が必須。axeはdialog / alertdialogの名前の欠落をWCAGルールではなくbest practiceに分類している。
- **適用条件・限界:** ARIAの名前要件はWCAGへの対応付けを単独で確定せず、axeの分類もWCAGの規範ではない。以下の対象除外は、この知識ベースの著者が採用する運用上の判断であり、W3Cが対象外と明示したものではない。

## 線引き

- 対象の操作部品に名前がなければ不適合。名前があっても、それだけでは役割・状態・値・変更通知まで適合としない。[根拠: 4.1.2-E01, 4.1.2-E04]
- title や placeholder 由来でも、対象環境で実際に名前として公開されているなら、その出どころだけを不適合の理由にしない。見えるラベル等は別に確認する。[独自: 名前とラベルの確認の分担。根拠: 4.1.2-E01, 4.1.2-E02]
- 標準要素も実際の機能を確認する。たとえばトグル動作を追加したボタンの状態は、タグだけで伝わると推定しない。[根拠: 4.1.2-E01, 4.1.2-E03]
- 必要な状態がネイティブに公開される場合、同じARIA属性の追加を要求しない。`summary` は展開状態の公開と更新を確認し、属性の欠落だけでは不適合にしない。[独自: ネイティブ実装の確認方針。根拠: 4.1.2-E01, 4.1.2-E03]
- dialog / alertdialog 自体は操作部品の入れ物として扱い、4.1.2の対象から外す。名前の欠落は、達成基準を付けない「ベストプラクティス」の改善候補として報告する。この欠落だけで4.1.2をFailやNTにしない。中の操作部品は通常どおり評価する。[独自: 著者の監査方針。参考根拠: 4.1.2-E05]
- `href="#"` 等の構文だけで役割の不一致を決めない。実際の動作と公開された役割を比較する。[根拠: 4.1.2-E01]

## 作るとき

- 標準の操作部品を仕様どおり使い、独自の動作を追加したら公開される状態も確認する。[4.1.2-E01, 4.1.2-E03]
- アイコンボタンには目的を表す名前を付ける。ダイアログには見出しを参照する名前などを付ける。[4.1.2-E02, 4.1.2-E05]
- 自作部品では役割に必要な状態・値を実装し、操作後も更新する。[4.1.2-E03]

## 確かめるとき

- **改善候補:** 名前のないdialog / alertdialogは「ベストプラクティス」と明記し、見出しを `aria-labelledby` で関連付ける等の修正を提案する。監査では適合判定と別枠に記す。例:「ベストプラクティス（独自方針）: ダイアログに名前がない。見出しを名前として関連付ける。WCAG達成基準: 付与しない」。[独自: 著者の監査方針。参考根拠: 4.1.2-E05]

- **確定:** 対象の部品の名前・役割・必要な状態等の欠落や不一致を確認できれば不適合にする。[4.1.2-E01–E03]
- **残る:** 名前チェックの pass の後も役割、状態・値、変更通知を確認する。ブラウザのツリーだけで支援技術のサポートまで検証済みにしない。[4.1.2-E01, 4.1.2-E04]
- **言い切らない:** 静止した状態の属性だけで動的な部品を適合にしない。必要でないARIA属性を一律に要求しない。ダイアログ自身の名前の欠落を、別の根拠なく1.3.1や2.4.6の不適合へ振り替えない。[4.1.2-E03–E05]
