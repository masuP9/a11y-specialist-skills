# 1.4.4 Resize Text

- Scope: Author-provided text and text-based controls
- Needed: Actual enlargement using 200% as the standard test point, access to content/functionality after resizing
- Automated checks: zoom-200-check (candidates from CSS zoom)

- Sources checked: 2026-11-01. WCAG: 2024-12-12 Recommendation; Understanding / Techniques: live WCAG 2.2 pages. Summaries, not quotations.

## Rationale

### 1.4.4-E01 — Verify the resizing method and actual text size

- **Type / source:** [Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html#intent), [Technique — G142, Tests](https://www.w3.org/WAI/WCAG22/Techniques/general/G142.html#tests) (Sufficient).
- **Summary:** At least one UA-supported resizing method can satisfy the criterion. Preserve content/functionality at intermediate steps up to 200%. G142 uses browser zoom.
- **Conditions / limits:** Do not universally require both text-only and page zoom. With responsive font changes, zoom settings alone do not prove doubled text. Horizontal scrolling alone does not fail this criterion.

### 1.4.4-E02 — Distinguish detected clipping from lost content

- **Type / source:** [Failure — F69, Description / Tests notes](https://www.w3.org/WAI/WCAG22/Techniques/failures/F69#tests), [Understanding — Truncation in Intent](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html#intent).
- **Summary:** Check clipping/obscuration that makes content unavailable on resizing. F69 cautions against applying its failure when a sufficient technique satisfies the criterion.
- **Conditions / limits:** Distinguish truncated subjects or similar labels with full content available on focus/activation and an indication of that access beyond truncation itself. CSS overflow alone does not establish failure.

### 1.4.4-E03 — Check entered text as well as body text

- **Type / source:** [Normative — WCAG 2.2, Resize Text](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#resize-text), [Failure — F80, Tests](https://www.w3.org/WAI/WCAG22/Techniques/failures/F80#tests).
- **Summary:** Check text in fields/buttons too. Captions and images of text are excluded by the normative criterion.
- **Conditions / limits:** Enlarged labels do not prove enlarged input text. Assess exclusions separately under 1.2.2, 1.4.5, etc.; do not replace text with images as a workaround.

## Judgment lines

- Verify inability to enlarge applicable text or loss of content/functionality against available resizing and full-text access methods before failing. [Evidence: 1.4.4-E01–E03]
- Retain the existing policy of reviewing all zoom-200-check candidates. CSS `zoom: 200%` is not identical to browser zoom and does not verify breakpoints or actual interaction. [Our interpretation: tool mapping; implementation: [runZoomCheck.ts](../../../../packages/a11y-audit/src/playwright/runZoomCheck.ts)]
- Do not fail solely for px units; judge actual resizing. [Evidence: 1.4.4-E01]

- Use 200% as the standard test point; do not require exhaustive testing of intermediate scales or assign needs review/NT solely because they were not tested. Include any actually observed intermediate loss in the judgment. This policy reflects available tooling and testing effort; it does not claim that a 200% result proves every scale. [Our interpretation: author’s testing policy; supporting evidence: 1.4.4-E01]

## When building

- Recommend relative font units such as rem and avoid losses from fixed heights/overflow. This is implementation policy, not a prohibition on px units. [Our interpretation: author recommendation; supporting evidence: 1.4.4-E01, 1.4.4-E02]
- Do not block pinch zoom through `maximum-scale=1` or `user-scalable=no`. [Our interpretation: author’s implementation policy; supporting evidence: 1.4.4-E01]

## When checking

- **Conclusive:** Lost content/functionality verified through actual resizing, not automated candidates alone. [1.4.4-E01–E03]
- **Remaining:** Entered text, responsive changes at 200%, full-text access, and control usability. [1.4.4-E01–E03]
- **Do not overclaim:** CSS zoom or zero candidates does not establish a page-wide pass. Also check scrolling separately under [1.4.10](./1.4.10.md). [Our interpretation: scope management; supporting evidence: 1.4.4-E01]
