# 2.4.4 Link Purpose (In Context)

- Components in scope: link
- Inputs needed: link names/text, DOM context and associations, actual destination or action
- Automated checks: axe `link-name` supplies naming implementation evidence; adequate purpose is separate
- Sources checked: 2026-11-02. WCAG is the 2024-12-12 Recommendation; Understanding / Techniques are living WCAG 2.2 public pages. The following are summaries, not quotations.

## Rationale

### 2.4.4-E01 — Judge the link alone or with associated context

- **Type / source:** [Normative — Link Purpose (In Context)](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#link-purpose-in-context), [Understanding — Intent](https://www.w3.org/WAI/WCAG22/Understanding/link-purpose-in-context.html#intent).
- **Summary:** Use programmatically determined context as well as the name. Document/application names can communicate purpose; visible URLs and purpose understandable from the link alone are not universally required.
- **Conditions / limits:** Do not import AAA 2.4.9's link-only requirement. Game doors whose purposes are ambiguous to everyone can qualify for the exception, but clues available on the page only to some users do not.

### 2.4.4-E02 — Separate visual proximity from context associations

- **Type / source:** [Technique — H78, Tests](https://www.w3.org/WAI/WCAG22/Techniques/html/H78#tests), [H79, Tests](https://www.w3.org/WAI/WCAG22/Techniques/html/H79#tests) (Sufficient for combining link text and programmatically determined context), [Failure — F63, Tests](https://www.w3.org/WAI/WCAG22/Techniques/failures/F63#tests).
- **Summary:** Check the same sentence, paragraph, list item, cell, associated table headers, ARIA associations, and similar context. An explanation merely in an adjacent paragraph is insufficient.
- **Conditions / limits:** Tree proximity may not establish paragraphs, cells, or associations. Read DOM and referenced elements as needed. Preceding explanations are recommended; following explanations do not fail solely for their position.

### 2.4.4-E03 — State the source classification for preceding headings

- **Type / source:** [Technique — H80, Description and Tests](https://www.w3.org/WAI/WCAG22/Techniques/html/H80#tests) (Advisory).
- **Summary:** This method combines a preceding heading with link text to explain purpose. H80 is currently Advisory rather than a sufficient technique.
- **Conditions / limits:** Do not classify it as Sufficient alongside H78. Distinguish this knowledge base's acceptance of heading context as the author policy below.

### 2.4.4-E04 — Missing image alt alone does not establish a nameless link

- **Type / source:** [Failure — F89, Description and Tests](https://www.w3.org/WAI/WCAG22/Techniques/failures/F89.html#tests).
- **Summary:** For non-text-only links, check the absence of alternatives or other accessible naming that identifies the link. A separate adjacent text link does not rescue a nameless image link.
- **Conditions / limits:** Also check `aria-label`, `aria-labelledby`, and other naming methods. Missing/empty alt alone does not fail the link. Evaluate the image's 1.1.1 separately.

## Judgment lines

- “Here” and “Read more” conform when associated context communicates purpose. Fail when no context establishes purpose; if contextual evidence is missing, specify the material needed and leave needs review. [Evidence: 2.4.4-E01–E02]
- Retain acceptance when the immediately preceding semantic heading identifies the content to which the link belongs and, with its text, establishes purpose. State that H80 is Advisory; do not extend acceptance to headings of other sections or visual proximity alone. [Our interpretation: author policy accepting heading context. Supporting evidence: 2.4.4-E03]
- For on-page actions such as “Close” or “Pause,” judge purpose from the action expressed by the name. Do not fail for lacking a destination URL; inspect role and keyboard issues under applicable separate criteria. [Our interpretation: action-link assessment policy. Supporting evidence: 2.4.4-E01]
- Identical names with different destinations conform here when their respective contexts distinguish them. Separately evaluate repeated-component identification under [3.2.4](./3.2.4.md). [Evidence: 2.4.4-E01–E02]
- axe-core 4.14.0 `link-name` checks text, ARIA, title, and similar naming for `a[href]`. Treat missing-name violations as failure evidence, but do not extend passes to descriptive purpose. Keep incomplete as needs review. [Our interpretation: tool mapping. Implementation checked: `node_modules/axe-core/axe.js`. Evidence: 2.4.4-E04]

## Judgment examples

- **Conformant:** An article description and “Read more” share a paragraph that identifies the article. Price links in a table also work when associated vehicle-type and company headers establish purpose. [Evidence: 2.4.4-E02]
- **Non-conformant:** “Read more” appears below a separate description paragraph, without usable heading, ARIA, or other associations. Also flag an independent image link lacking a meaningful name. [Evidence: 2.4.4-E02, E04]
- **Conformant under author policy:** “Read more” within the article heading's content block clearly links to that article. Do not return to needs review merely for crossing paragraphs when the heading conditions above are met. [Our interpretation: heading-context example. Supporting evidence: 2.4.4-E03]
- **Do not flag under the exception:** “Door 1” and “Door 2” in a game deliberately hide destinations from all users. If visual clues actually exist, check that the information is also provided. [Evidence: 2.4.4-E01]
- **Needs review:** Only a link name was collected and “Details” has no identifiable referent. Obtain the paragraph, list item, table headers, ARIA references, or other context. [Our interpretation: inspection policy. Evidence: 2.4.4-E02]

## When building

- Prefer wording understandable alone. When relying on context, provide the same paragraph/list item or explicit associations. [Our interpretation: author implementation recommendation. Supporting evidence: 2.4.4-E01–E02]
- Give image-only links names indicating purpose. Images and adjacent text with the same destination can also be combined into one link. [Evidence: 2.4.4-E04]

## When checking

- **Settled:** Missing names, or links whose purposes remain unclear after checking context and exceptions. [2.4.4-E01–E04]
- **Remains:** DOM context, heading scope, ARIA references, actual functions. A list of link names alone is insufficient.
- **Do not assert:** Failure solely from “Here,” repeated names, long names, or missing image alt. [Evidence: 2.4.4-E01–E04]
