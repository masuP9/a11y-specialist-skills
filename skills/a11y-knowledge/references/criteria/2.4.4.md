# 2.4.4 Link Purpose (In Context)

- Components in scope: link
- Inputs needed: the link's name and the surrounding tree (the same sentence, paragraph, list item, or table cell; the preceding heading)
- Automated checks: axe `link-name` (presence of a name only)

## Rationale

- [Understanding 2.4.4](https://www.w3.org/WAI/WCAG22/Understanding/link-purpose-in-context.html) ([Japanese translation](https://waic.jp/translations/WCAG22/Understanding/link-purpose-in-context.html))
  - Even if the link text alone is not understandable, it is enough if it can be understood together with the "programmatically determined context" (the same sentence, paragraph, list item, or table cell; table headers; the preceding heading).
  - Links whose purpose is ambiguous to users in general (those that deliberately hide the destination) are an exception.
  - It does not require the destination URL to be visible.
- [G91: link text that describes the purpose](https://www.w3.org/WAI/WCAG22/Techniques/general/G91), [H78 / H79 / H80 / H81: combining with context](https://www.w3.org/WAI/WCAG22/Techniques/html/H80), [F63: no context](https://www.w3.org/WAI/WCAG22/Techniques/failures/F63), [F89: links with no name](https://www.w3.org/WAI/WCAG22/Techniques/failures/F89)

## Judgment lines

- Conformant if the purpose can be understood from the link's name alone, or together with the link's context (the same sentence, paragraph, list item, or table cell; the preceding heading). The destination URL need not be visible. [Understanding]
- A link that operates something on the page ("Pause", "Close", "Show more") is conformant if its name expresses that operation, because the purpose is understood. Do not mark non-conformant because it does not indicate a destination (the problem of using a link in place of a button is 4.1.2). [Our interpretation]
- For links not understandable from the name alone, like "here", "click here for details", "read more", or "more", check the same list item, paragraph, or preceding heading. Conformant if the purpose is understood from there; non-conformant if not. Needs review if there is no way to check the surroundings. [Understanding]
- A link with no name (an image-only link with no alt) is non-conformant. [Understanding] (F89)
- Do not mark non-conformant solely because several links have the same name or because a name is long. [Understanding] (for 2.4.4, the same name with different destinations is fine if distinguishable by context)

## When building

- Write the content of the destination in the link text ("See pricing plans"). Do not use only "here" or "details".
- For cards that line up "Read more", make the heading the link, or use `aria-labelledby` to combine the heading and "Read more" into the name.
- For image-only links, write the destination in alt.
- If links with the same name and different destinations are lined up, place distinguishing context in the same list item or paragraph.

## When checking

- **Settled**: violations of axe `link-name` (no name) are non-conformant.
- **Remains**: check links not understandable from the name alone, one at a time, together with their context.
- **Do not assert**: do not mark "here" non-conformant without checking its context. Do not mark an operation link non-conformant for "having no destination".
