# 2.4.11 Focus Not Obscured (Minimum)

- Scope: Components receiving keyboard focus and author-created content obscuring them
- Needed: Visible portions of the component itself, origin/initial position of the covering content, and whether it can be revealed without advancing focus
- Automated checks: focus-indicator-check (`focus-not-obscured`). Check detection scope, including fixed/sticky coverage

- Sources checked: 2026-11-01. WCAG: 2024-12-12 Recommendation; Understanding / Techniques: live WCAG 2.2 pages. The following are summaries, not quotations.

## Rationale

### 2.4.11-E01 — The component itself must not be entirely hidden

- **Type / source:** [Normative — WCAG 2.2, Focus Not Obscured (Minimum)](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#focus-not-obscured-minimum), [Understanding — Notes in Intent](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html#intent).
- **Summary:** Evaluate whether author-created content entirely hides the component receiving focus. An indicator outside the component does not count as a visible portion of the component itself.
- **Conditions / limits:** Partial visibility is not a failure of this criterion. Distinguish a visible outer ring around an entirely hidden component. Also check indicator visibility under 2.4.7.

### 2.4.11-E02 — Evaluate movable content at its initial position

- **Type / source:** [Normative — Note 1](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#focus-not-obscured-minimum), [Understanding — User-movable content](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html#intent).
- **Summary:** Content users can reposition is evaluated at its initial position.
- **Conditions / limits:** Being movable does not exempt initial-position obscuration. Being dismissible is not the same as being repositionable.

### 2.4.11-E03 — User-opened content requires a way to reveal the target

- **Type / source:** [Normative — Note 2](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#focus-not-obscured-minimum), [Understanding — User-opened content](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html#intent).
- **Summary:** The note can apply to user-opened content when the target can be revealed without advancing keyboard focus.
- **Conditions / limits:** Do not exempt content merely because it is a menu or dialog. Verify user initiation and the reveal mechanism. Do not use the note to exempt normally non-persistent menus left open after interaction or focus departure. Do not apply it to automatically displayed notifications. Having to Tab to a close button does not meet the condition.

### 2.4.11-E04 — Check fixed content in both directions and actual presentation

- **Type / source:** [Failure — F110, Tests](https://www.w3.org/WAI/WCAG22/Techniques/failures/F110#tests), [Technique — C43, Description / Tests](https://www.w3.org/WAI/WCAG22/Techniques/css/C43#tests) (Sufficient).
- **Summary:** F110 checks complete obscuration with forward and backward Tab navigation. C43 uses padding and scroll-padding to reserve space beneath fixed content and scroll focused targets into view.
- **Conditions / limits:** CSS properties alone are insufficient; check actual scrolling. Testing fixed/sticky content does not cover all other author-created obstructions.

## Judgment lines

- Fail after verifying complete obscuration by author-created content and that the notes do not apply. Lack of evidence of user initiation alone does not establish that a note is inapplicable. [Evidence: 2.4.11-E01–E03]
- A partly visible component satisfies 2.4.11 for that obstruction. Distinguish recommendations for greater visibility and 2.4.12. [Evidence: 2.4.11-E01]
- The current tool’s `fullyObscured` threshold is an area ratio of at least 99%. This is not a WCAG numeric requirement; treat it as a candidate for checking complete obscuration. Check transparency, shape, and actual presentation. [Our interpretation: tool mapping; supporting evidence: 2.4.11-E01; implementation: [constants.ts](../../../../packages/a11y-audit/src/constants.ts), [runFocusIndicatorCheck.ts](../../../../packages/a11y-audit/src/playwright/runFocusIndicatorCheck.ts)]
- With no entirely hidden target, completed measurement, at least one target, and none skipped, retain the existing operational pass within the detection scope. State that this covers overlap with fixed content; separately check untested display states and coverings. [Our interpretation: author’s measurement policy; supporting evidence: 2.4.11-E04]

## When building

- Set scroll-padding or similar spacing for fixed headers/footers and verify visibility in both navigation directions. [2.4.11-E04]
- Making a banner dismissible alone is insufficient. Automatically displayed content should avoid covering targets; to use the user-opened note, provide a way to reveal the target without advancing focus. [2.4.11-E02, 2.4.11-E03]

## When checking

- **Conclusive:** Fail after actual complete obscuration and inapplicability of the notes are established. Keep verified failures even if traversal stops early. [2.4.11-E01–E03]
- **Remaining:** Check origin, reveal mechanism, and actual presentation for `focus-not-obscured` candidates. Normalized results also mark them for review. [Our interpretation: tool mapping; implementation: [axe-format.ts](../../../../packages/a11y-audit/src/utils/axe-format.ts)]
- **Do not overclaim:** Do not fail on 99% alone, exempt content solely for dismissibility, or give a page-wide pass after interrupted measurement. [2.4.11-E01–E04]
