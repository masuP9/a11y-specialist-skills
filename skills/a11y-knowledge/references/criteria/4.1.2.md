# 4.1.2 Name, Role, Value

- Components in scope: all interactive components (button, link, input fields, tab, menuitem, option, treeitem, gridcell, tablist, menu, tree, grid, progress). dialog / alertdialog are not in scope
- Inputs needed: accessibility tree (name, role, state), the combination of tagName and role
- Automated checks: axe `button-name`, `link-name`, `input-button-name`, the `aria-*` rules

## Rationale

- [Understanding 4.1.2](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) ([Japanese translation](https://waic.jp/translations/WCAG22/Understanding/name-role-value.html))
  - The scope is "user interface components" (components the user operates). The name and role must be programmatically determinable, states and values determinable, and changes conveyed to assistive technology.
  - Using standard HTML components as standard, the browser conveys the name, role, and state. The problem is mainly custom components (div + JavaScript).
  - The source of the name is not asked (a name from aria-label, label, title, or placeholder is still a name).
- [ARIA14: aria-label](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA14), [ARIA5: conveying state](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA5), [F59: click only on a div](https://www.w3.org/WAI/WCAG22/Techniques/failures/F59), [F15: non-standard component not conveying its role](https://www.w3.org/WAI/WCAG22/Techniques/failures/F15)

## Judgment lines

- The name is judged by whether a name exists. The source is not asked (a name from a placeholder or title is still a name). Having only a placeholder is handled under 3.3.2 and is not a reason for non-conformance under 4.1.2. [Understanding]
- If there is no name, non-conformant (a screen reader cannot tell what the component is). [Understanding]
- For standard HTML elements (button / a[href] / input / select / textarea) whose role has not been changed, the browser conveys the role and state, so conformant if a name exists. [Understanding]
- The summary of a details is treated as a button that opens and closes. The browser conveys whether it is open, so do not mark non-conformant because `aria-expanded` is absent. [Understanding] (the browser's default behavior)
- Modals (dialog / alertdialog) are not in scope for 4.1.2. They are containers for interactive components, not user interface components in the sense of 4.1.2. A dialog having no name is not marked non-conformant under 4.1.2 (checked as a matter of 1.3.1 / 2.4.6). [Our interpretation]
- For custom components (a div with a role), check whether the state appropriate to the role (`aria-expanded`, `aria-selected`, `aria-checked`, `aria-pressed`) is present and changes on operation. On a static screen, "whether it changes" cannot be known, so non-conformant if the state attribute is absent, needs review if present (operate to confirm). [Understanding]
- Links used in place of buttons (an a without href, `href="#"` with JavaScript only) have a mismatched role, so check them under 4.1.2 (not asked under 2.4.4). [Our interpretation] (division)

## When building

- Build interactive components with standard elements (button, a[href], input, select). Do not attach click to a div / span.
- Give custom components a role and the state appropriate to the role (`aria-expanded` and so on), and update it on operation. Follow the APG patterns.
- Give icon-only buttons an `aria-label`.
- For things that open and close (accordions, menus), use `<details>` / `<summary>` or button + `aria-expanded`.
- Give dialogs their heading as the name via `aria-labelledby` (for 1.3.1 / 2.4.6, not 4.1.2).

## When checking

- **Settled**: violations of axe `button-name` / `link-name` / `input-button-name` are non-conformant. Passes may be counted as conformant (for standard elements, the browser conveys the role and state).
- **Remains**: whether a custom component's state changes on operation. Whether the role matches the actual behavior.
- **Do not assert**: do not mark a placeholder-only name non-conformant under 4.1.2. Do not mark the absence of `aria-expanded` on a summary non-conformant. Do not ask the dialog's name under 4.1.2.
