# 2.5.2 Pointer Cancellation

- Scope: author-provided single-pointer functionality
- Inputs needed: press, move outside, and release interactions; completion and reversal results
- Automated checks: pointer-cancellation-check (down-event changes and listener candidates)

- Sources checked: 2026-11-01. WCAG refers to the 2024-12-12 Recommendation; Understanding / Techniques are the continuously updated WCAG 2.2 published pages. The following are summaries, not quotations.

## Evidence

### 2.5.2-E01 — A down-event response alone does not establish failure

- **Type / source:** [Normative — WCAG 2.2 “Pointer Cancellation”](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#pointer-cancellation), [Understanding — “Intent”](https://www.w3.org/WAI/WCAG22/Understanding/pointer-cancellation.html#intent).
- **Summary:** Identify which condition is satisfied: no function execution on down-event; completion on up-event with abort before completion or undo afterwards; up-event reversal of the down-event outcome; or essential down-event completion.
- **Conditions / limits:** Content appearing only while pressed and disappearing on release can be evaluated as up reversal. The normative note considers key-press emulation essential. A preference for faster response alone does not establish essentiality.

### 2.5.2-E02 — Check completion, abort, and undo rather than listener names

- **Type / source:** [Failure — F101 “Description” / “Tests”](https://www.w3.org/WAI/WCAG22/Techniques/failures/F101#tests), [Technique — G212 “Description” / “Tests”](https://www.w3.org/WAI/WCAG22/Techniques/general/G212#tests) (Sufficient).
- **Summary:** Press, move outside the target, and release; check that the function does not execute or can be undone. Automated listener detection cannot establish conformance or failure. A response such as focus entering a native input alone is not a failure.
- **Conditions / limits:** Do not generalize F101's description/tests into permission to complete any function on down-event merely because Undo exists. Record completion timing and check the normative alternatives. [See: 2.5.2-E01]

### 2.5.2-E03 — Separate drag cancellation from alternative operation

- **Type / source:** [Technique — G210 “Examples” / “Tests”](https://www.w3.org/WAI/WCAG22/Techniques/general/G210#tests) (Sufficient).
- **Summary:** Check options such as aborting by releasing outside a drop target, undoing by returning to the original position, or confirmation/undo after dropping. Not all options must be provided.
- **Conditions / limits:** Dragging an item back can provide undo for this criterion; it does not establish a nondragging alternative under [2.5.7](./2.5.7.md).

## Judgment boundaries

- Check completion, reversal, and essentiality through actual interaction; fail when none of the conditions is satisfied. A pointerdown listener or DOM change alone is insufficient. [Evidence: 2.5.2-E01–E03]
- The tool sends synthetic down-events and does not test release or Undo. Review `activated-on-press` / `press-only-listener` findings, untested targets, and page-level review notes. It returns pass when targets were tested without candidates, untested targets, or page-level review notes, but do not extend this to actual touch behavior or undetected states. ## When building

- Use standard click activation for ordinary buttons and links. When adding custom down-event handling, verify actual abort, undo, or reversal behavior. [Evidence: 2.5.2-E01, 2.5.2-E02]

## When checking

- **Established:** Completion timing and the applicable abort, undo, reversal, or essentiality condition. [2.5.2-E01–E03]
- **Remaining:** Touch, delegated listeners, delayed effects, iframes, and truncated inspection. Synthetic tool events can still submit or save. [Our interpretation: inspection limits]
- **Do not conclude:** A down-event response alone is not Fail; zero candidates alone is not a page-wide Pass.
