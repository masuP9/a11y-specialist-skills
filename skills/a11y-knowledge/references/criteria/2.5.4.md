# 2.5.4 Motion Actuation

- Scope: functions using device shaking/tilting or user motion detected by cameras or other sensors as input
- Inputs needed: alternative controls, settings to disable motion responses, and actual behavior
- Automated checks: motion-actuation-check (motion listeners and synthetic-event candidates)

- Sources checked: 2026-11-01. WCAG refers to the 2024-12-12 Recommendation; Understanding / Techniques are the continuously updated WCAG 2.2 published pages. The following are summaries, not quotations.

## Evidence

### 2.5.4-E01 — Check both alternative operation and disablement

- **Type / source:** [Normative — WCAG 2.2 “Motion Actuation”](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#motion-actuation), [Technique — G213 “Tests”](https://www.w3.org/WAI/WCAG22/Techniques/general/G213.html#tests) (Sufficient), [Failure — F106 “Tests”](https://www.w3.org/WAI/WCAG22/Techniques/failures/F106#tests).
- **Summary:** Unless excepted, the same function must be operable through UI components and motion activation must be disableable. An alternative button alone is insufficient when motion responses cannot be stopped.
- **Conditions / limits:** Check that the same function remains available through the alternative after disabling motion. Testing only one requirement does not establish conformance.

### 2.5.4-E02 — Do not require a site-specific setting in every case

- **Type / source:** [Understanding — “Intent”](https://www.w3.org/WAI/WCAG22/Understanding/motion-actuation.html#intent).
- **Summary:** Supporting an operating-system setting that disables motion detection can satisfy the disablement requirement.
- **Conditions / limits:** An OS setting's existence alone is insufficient; verify that it stops the relevant response. Do not infer that reduced animation settings also disable motion input.

### 2.5.4-E03 — Distinguish intentional motion input, exclusions, and exceptions

- **Type / source:** [Understanding — “Intent”, notes and essential exception](https://www.w3.org/WAI/WCAG22/Understanding/motion-actuation.html#intent), [Normative — WCAG 2.2 “Motion Actuation”](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#motion-actuation).
- **Summary:** Hand or face gestures toward a camera are included. Geolocation-based movement detection and pointing a camera at a QR code or similar object are not these input gestures.
- **Conditions / limits:** Distinguish motion involved in operating keyboards, mice, or assistive technology under Supported Interface. Measuring motion itself, as in a pedometer, can be essential; choosing a shake-based interface alone does not establish essentiality.

## Judgment boundaries

- Establish applicability and exceptions, then fail if either alternative operation or disablement is missing. [Evidence: 2.5.4-E01–E03]
- Listeners require review even when synthetic events cause no DOM change. After CDP inspection, no listeners returns not applicable; unsupported CDP returns needs review. Separately check cameras, Generic Sensor API, iframes, and states after permission grants. [Our interpretation: tool mapping. Implementation: [runMotionActuationCheck.ts](../../../../packages/a11y-audit/src/playwright/runMotionActuationCheck.ts), [normalizeMotionActuationCheck](../../../../packages/a11y-audit/src/utils/axe-format.ts)]

## When building

- Provide buttons or equivalent controls for shake/tilt functionality, and provide or support a means of disabling motion activation. [Evidence: 2.5.4-E01, 2.5.4-E02]

## When checking

- **Established:** Alternative operation and disablement of the relevant function, or an applicable exception. [2.5.4-E01–E03]
- **Remaining:** Real-device behavior, states after permission grants, undetected APIs, and camera input. Synthetic events can also change page state. [Our interpretation: inspection limits]
- **Do not conclude:** Sensor use alone is not Fail; no response to synthetic events alone is not Pass.
