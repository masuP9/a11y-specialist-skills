# 3.3.4 Error Prevention (Legal, Financial, Data)

- Components in scope: form
- Inputs needed: the form's purpose (name, heading, submit button name), whether there is confirmation before submission
- Automated checks: none

## Rationale

- [Understanding 3.3.4](https://www.w3.org/WAI/WCAG22/Understanding/error-prevention-legal-financial-data.html) ([Japanese translation](https://waic.jp/translations/WCAG22/Understanding/error-prevention-legal-financial-data.html))
  - The scope is legal commitments, financial transactions, modification or deletion of user-controllable data, and submission of test responses.
  - It is enough if one of these exists: reversible, checked (input is validated with an opportunity to correct), or confirmed (reviewable and correctable before submission).
  - It does not apply to forms outside the scope (contact, search).
- [G98: reviewing and correcting before submission](https://www.w3.org/WAI/WCAG22/Techniques/general/G98), [G99: reversible](https://www.w3.org/WAI/WCAG22/Techniques/general/G99), [G164: reversible for a set period](https://www.w3.org/WAI/WCAG22/Techniques/general/G164), [G168: a confirmation checkbox](https://www.w3.org/WAI/WCAG22/Techniques/general/G168)

## Judgment lines

- The scope is only forms for legal commitments (contracts, applications), exchanges of money (purchases, transfers, payments), modification or deletion of user-controllable data (account settings, updating registered information, closing an account), and submission of test responses. [Understanding]
- Forms not matching the above, such as contact, search, login, newsletter signup, comments, and surveys, are out of scope. Judge from the form's name, the names of its input fields and submit button, and headings. [Understanding]
- For a form in scope, conformant if confirmation before submission (a "Go to confirmation" button, a checkbox indicating the content was checked) is evident from the information. If not, needs review, because a confirmation screen after submission or a means to undo is not visible on the screen before input. Do not mark non-conformant solely because the confirmation mechanism is not visible. [Our interpretation]

## When building

- For purchases, applications, account closure, and data deletion, insert a confirmation screen or add an "I have checked the content" checkbox.
- Make deletion reversible (a trash bin, restoration within a set period).
- Validate input before submission and give an opportunity to fix errors (overlaps with 3.3.1 / 3.3.3).

## When checking

- **Settled**: none.
- **Remains**: for a form in scope, actually proceed to just before submission and check whether there is a means of confirmation or undo.
- **Do not assert**: do not ask 3.3.4 of forms out of scope. Do not mark non-conformant because there is no confirmation screen on the screen before input.
