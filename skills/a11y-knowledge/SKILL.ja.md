# アクセシビリティ知識ベース

達成基準ごとに「判断の根拠になること」をまとめた参照用の知識ベース。WCAG の達成基準の定義や ARIA の仕様は書かない（エージェントは知っている前提）。書くのは、解説書のどこを押さえるべきか、解釈の線引き、線引きを満たす作り方、自動チェックが決められる範囲と決められない範囲。

このスキルは単体で作業をするものではない。実装・レビュー・監査のスキルが、必要な達成基準のファイルだけを読むために使う。

## 引き方

1. **達成基準の番号が分かっているとき**: `references/criteria/<番号>.ja.md` を読む（例: `references/criteria/1.1.1.ja.md`）。一覧は [references/index-by-criterion.ja.md](./references/index-by-criterion.ja.md)。
2. **部品の種類から探すとき**（コードを書く・レビューするとき）: [references/index-by-component.ja.md](./references/index-by-component.ja.md) で部品（button、link、image、dialog など）からその部品に問われる達成基準を引き、各ファイルを読む。
3. **自動チェック（axe、`@a11y-skills/audit`）の結果を読むとき**: [references/checks-axe.ja.md](./references/checks-axe.ja.md) と [references/checks-audit.ja.md](./references/checks-audit.ja.md) で、どの結果が確定で、どれが要確認かを確かめてから、各達成基準の「確かめるとき」を読む。
4. **複数ページを見比べる達成基準**（3.2.3 / 3.2.4 / 3.2.6 / 2.4.2 の見比べ）: 先に [references/cross-page.ja.md](./references/cross-page.ja.md) の共通の判定のきまりを読む。

全部を一度に読まない。問われている達成基準の分だけ読む。

参照ファイルを編集するときは [判断根拠の編集・確認](./references/evidence-format.ja.md) を読む。2.5.8 / 1.1.1 / 4.1.2 は根拠ID付きの試作形式。これらは各項目の出典種別・条件・限界を読み、線引きから根拠IDを辿る。他の基準は既存形式。

## 各ファイルの 4 段

| 段             | 誰が読むか               | 中身                                                                                                   |
| -------------- | ------------------------ | ------------------------------------------------------------------------------------------------------ |
| 根拠           | 全場面                   | 判断を支える出典と要点。試作形式では根拠ID、出典種別、適用条件・限界を持つ     |
| 線引き         | 全場面                   | この基準をどう読むか。適用しないもの、例外、よくある誤判定。既存形式は **[解説書]** / **[独自]**、試作形式は根拠IDと独自判断の印 |
| 作るとき       | 実装・レビュー           | 線引きを満たす作り方と、避ける作り方                                                                     |
| 確かめるとき   | 監査・自動チェックの精査 | 自動チェックが決めること、残ること、言い切ってはいけないこと（要確認にとどめる条件）                     |

## 使うときの決まり

- **[独自] の線引きは、WCAG の唯一の読み方ではない。** プロジェクトの判断で上書きしてよい。上書きしたら、その理由をプロジェクト側に書き残す。
- **自動チェックの確定範囲を保つ。** 達成基準のファイルにある適用条件・例外を照合する。部分的な pass を達成基準全体の適合に広げず、未検証の条件は要確認として残す。
- **判断できないときは「要確認」にとどめる。** 推測で不適合にも適合にもしない。何を確かめれば決まるかを書く。
- **理由を先に書き、理由に合う判定を付ける。** 判定だけ書いて理由を後付けしない。

## 載せる範囲の決まり

- 出すのは「判断の根拠になること」だけ。達成基準の文言や解説書の全文は書き写さない。
- 解説書の要点は、判断の根拠になる箇所に限る（用語の定義、意図、例外の出どころ）。
- 線引きは、出典に基づくもの（既存形式の [解説書]、試作形式の根拠ID）と、運用上の解釈（[独自]）を分けて書く。
- 測って分かった誤判定の型は書く。測定の数字は書かない。
